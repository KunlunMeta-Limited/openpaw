## 3. 已复现问题：人物与成员详情

当前 Host 的 `office/projection.rs::prepare` 总是发布 assistant→office-lead、files→file-agent、search→data-agent 三个功能成员；只有启用 bash 才添加 command→code-agent。画面始终有六个固定人物。`office/actions.rs::dispatch` 对 `actor.inspect` 要求当前会话 employees 存在 sceneActorId 绑定，所以：

- office-lead、file-agent、data-agent 返回通用 `OpenPaw 会话详情`；无成员身份字段。
- app-agent、review-agent、code-agent（本现场 bash 未开放）返回 `scope_denied：该人物未绑定此会话成员`。真实请求为 HTTP200，但 presentation.success=false；不能把 HTTP200当功能成功。
- 左侧 assistant、files、search 各自发出正确的 `employee.inspect(employeeId)`，Host 校验后全部降为 `kind=menu`，丢失 employeeId/actorId，fields 都为空。六类会话查询可用不等于成员详情已完成。

登记 OpenPaw **D50**（常驻人物与成员呈现不一致，产品缺陷）与 **D51**（详情丢失目标上下文）。**不能删除 scope 校验来修复**。方案是共同成员目录、同会话解析、未启用/空闲角色的准确说明，以及携带目标身份的 detail-v1；陌生 team/跨会话成员/伪造 actor 仍拒绝。新草稿不应因一次点击创建真实 Run；若 Office 前置契约不接受草稿查询，显示其真实边界，不伪造会话。

当前源码 master 15.1 F30 将“单 poller 和范围校验完成”概括成“成员上下文完成”，范围过大，须修正。历史 T5 测试只覆盖已绑定主助手进入六类查询，**没有覆盖六人物逐个点击、三成员目标差异**；这解释了之前绿灯未捕获用户问题。

## 5. 多 Agent 最小可交付方案与框架审查

实际角色名是 **王明**（用户本轮称王民），不自行改 Office 人名；业务员工可用同名加职责。配置固定六角色：王明统筹；李研资料/技术检索；周理本地资料整理；陈书撰稿；刘市验收核对；赵审来源与结论复核。具体任务分工由主Agent根据目标决定，不把角色名写死成天气专用逻辑。

当前可复用：AgentLoop、Provider/SystemPromptBlocks、ToolRegistry/ToolCallContext、Host::open_session/submit_run、JSONL、Store host_events、Approval精确输入CAS、Root锁、Run取消与总预算、Office tasks/employees/events/detail-v1。`is_sub_agent`索引列和skill字符串只证明遗留字段/文本存在，**不证明有可调用的委派执行器**。

需要增加的Host职责只分两部分：`agents.rs`定义可信角色、权限子集和身份解析；`orchestration.rs`协调父子Run关系、幂等委派、预算/取消/生命周期。不复制推理循环，不新建Node Bridge、工具主体或任务数据库；Office DTO只留office模块。新角色映射不是在工具名映射表里再堆五个if。

主要技术风险与约束：

1. **容量与死锁**：默认全局4Run包含主Agent；不是每个角色都可同时运行。初期单个协作最多1个主+2个子，其余有界待派发；全局不足只等待可取消的可用名额，不能反复创建失败Run。委派不取得工作区读/写锁，主Agent等结果期间不能挡住子Agent写入。
2. **事实与幂等**：每个子Agent真实独立Session/Run；父Run+委派callId稳定识别。Store原host_events记录版本化所属关系/任务/结果引用，JSONL仍是推理与工具事实。两个存储阶段不冒称单事务；先存意图再接受，崩溃留下明确interrupted，不重放工具。具体字段及回退见0007。
3. **权限与审批**：子角色工具是Host白名单的子集，网页/子输出均是非可信内容，不变成system。子写入沿原Approval，Office只把展示定位到父会话；不能把父审批复制为五份通用授权。默认无bash，无新根/密钥/任意网络权限。
4. **取消与删除**：主Run取消/关闭/会话删除必须覆盖待派发和全部后代，实际工具清理后才结束；单个子失败产生真实阻塞或失败，不把总目标涂成100%。父子不形成循环，首期只有一层、子Agent不能再次委派。
5. **交接与显示**：持久派发事实产生稳定task.assigned；子任务必须仍在快照且负责人匹配，Office才触发自动visit。不能同时发第二条visit。主Agent先把全部已接受子任务归属呈现，再等待/汇总；每人的任务卡与气泡跟随真实子任务，旧工具重试不新建交接。
6. **不能承诺的边界**：现协议无动画播放回执，首次加载不重播；若任务在投影前完成，前端会跳过拜访，浏览器离线也无法“必走到”。可复现演示用确定性Provider在真实子任务中保持足够可观察阶段，而不能在生产虚构慢进度；真实DeepSeek另验。若要求“走到且收到确认后才允许实际执行”的强事务语义，另列R16候选，未批准时不宣称达到。
7. **工程与性能**：现projection/action/scene多处独立解释成员与工具映射，应共用目录/所属关系；大量全Run/账本遍历是需测量的风险，先记录真实负载再决定复用查询索引，不能借审查全仓重构。旧错误记录、用户数据与最小墓碑仍保留。
