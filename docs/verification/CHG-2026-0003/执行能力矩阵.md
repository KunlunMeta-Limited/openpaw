# T2执行能力与T3交接（CHG-2026-0003）

关联：REQ-OP-005/006/007，DES-OP-004/005；范围以主CHG、master第10节T2及14.7 M2为准。这里区分实现策略和实际平台验证，当前完整验收结果见[验证记录](验证记录.md)，未执行不算通过。不适配macOS，不以WSL或交叉编译替代原生Windows。

## 普通执行与限制执行

| 能力 | Linux实现 | Windows 10/11 x64实现 | 验证入口/边界 |
| --- | --- | --- | --- |
| 普通本地命令 | sh -c，独立进程组 | 系统cmd.exe /D /V:OFF /S /C；普通用户CreateProcessW | exec_e2e批准后echo/exit；不是文件/网络隔离 |
| 分析与审批 | 显式Bash分析链复用原解析器；未知/复杂审批，危险拒绝 | 显式Cmd；没有grammar则保守审批；危险规则仍执行 | d07_*；windows_raw_cmd_requires_approval_even_for_echo；不要求Git Bash |
| 取消与超时 | SIGKILL本组、wait leader、管道EOF，正常退出终止遗留后台成员 | 挂起创建→分配原Job→恢复；终止Job并等待ActiveProcesses清零及leader/管道结束 | d08_cancel_reaps_a_child_tree_before_returning、原lifecycle；普通进程组不承诺阻止恶意setsid/daemon脱组 |
| 输出 | 两条异步管道同时排空 | PeekNamedPipe/ReadFile交替排空，两管道公平轮询 | d08_both_output_pipes_are_drained_past_retention_limit；每流保留1MiB，其后读弃，bash显示30000字符，退出原因独立保留 |
| 创建/Job失败 | spawn错误透传、guard兜底 | 句柄立刻RAII；加入Job失败也终止挂起进程并等待 | Windows私有failed_job_assignment_reaps_the_suspended_process；不可仅close句柄 |
| 取消时记录开始 | 等待可靠观察完成后再检查token，不丢弃写入 | 同Linux | d05_execution_record_failure_fails_run_and_keeps_result_pairing；失败整Run为Failed，保留工具配对 |
| 受限只读/工作区写 | 原bwrap后端；缺失/不可用即拒绝；域名AllowDomains建目录前拒绝 | 现token/ACL不能证实网络限制，所有当前受限组合在ACL/进程副作用前拒绝 | d09_requested_domain_isolation_is_never_an_environment_hint；本期不宣称Windows受限沙箱可用 |
| environment工厂 | 直接构造指定后端，不嵌套runtime健康探测 | 同Linux | d09_environment_factory_does_not_panic_in_current_thread_runtime；不能降为Local |
| 子进程环境 | 仅必要系统键允许列表 | 同规则，UTF16环境块 | 不继承任意业务/model/Office变量；调用方不可把密钥放入PATH等系统键 |
| literal builder参数 | 单引号字面化，内嵌引号安全拼接 | 拒绝无法安全表示的cmd元字符；支持普通字面参数 | d34_*；command本身仍是有意脚本，env覆盖未实现明确拒绝 |

Linux受限策略可用性取决于bwrap安装及宿主user namespace权限；本轮普通执行与受限拒绝是必验，不能把本机缺后端写成隔离成功。旧Sandbox审批callback/whitelist配置入口保留，exec不利用它们解除请求的隔离。普通进程管理与权限隔离是不同能力。

## 路径、Todo与授权边界

| 场景 | 要求/实现 | 回归 |
| --- | --- | --- |
| 中文/空格目录 | 原生cwd保留路径，不靠拼接cd；Windows规范化本地盘符/去除verbatim disk前缀供cmd | d08_local_cwd_supports_spaces_and_unicode |
| Windows盘符、大小写、verbatim别名 | 同一实际根读取/更新同一Todo，原解析器和路径校验复用 | d11_windows_drive_case_alias_and_verbatim_paths_share_todos |
| UNC/device命令cwd | 明确拒绝，在创建前返回错误；不允许cmd默认落入Windows目录 | d10_unc_cwd_is_rejected_instead_of_cmd_directory_fallback；没有建立测试共享/修改系统配置 |
| 文件查询UNC | 仍使用原filesystem路径校验；不宣称网络共享运行已验收；本期Host允许根以本地盘符为基线 | T3配置阶段约束，不能据ID切工作区 |
| Linux链接/Windows junction逃逸 | 复用safety::resolve校验实际根，拒绝.openpaw重定向到根外 | d11_link_to_another_workspace_is_rejected、d11_windows_junction_to_other_workspace_is_rejected |
| Todo不存在/读取 | 真正只读，不创建.openpaw/锁文件；仅NotFound为空；原id/title/status JSONL | d11_structured_read_of_missing_todos_has_no_writes |
| 损坏、无权限、过大 | JSONL坏行/重复零ID/非法状态/非普通文件/2MiB限制报错；写入同样限制，失败旧数据保留 | d11_corrupt_*、d11_invalid_jsonl_*、d11_permission_error_*、d11_oversized_update_* |
| 并发更新 | 原OS独占锁覆盖整个读改写，同目录tempfile sync+atomic persist；按原200项保留策略 | 48个独立注册表d11_concurrent_registries_*，不新增第二种存储 |
| 等待锁取消 | 5ms轮询原非阻塞OS锁、WouldBlock重试；取消返回前不进入工具主体 | d11_lock_wait_cancels_without_entering_tool_body；审批等待无锁 |
| Windows文件占用 | 禁DELETE share时替换失败，不删旧文件/吞错误；临时文件清理 | d11_windows_file_without_delete_share_keeps_old_data_on_replace_failure |
| 授权范围 | 原guardrail+ToolSpec.requires_approval；Run/call/工具/完整JSON精确绑定；拒绝不执行 | engine d05_*、tools d07_* |
| 执行状态 | ToolUseStart仍为提议；真正进入主体前等待观察；Todo锁后观察 | d05_running_observation_failure_prevents_file_write、engine可靠开始失败回归 |

读写工具不是全部可以默认开放。注册表保留21项原工具主体；read_file/grep/glob/todo_list/think等只读或无外部副作用按现有声明/guardrail判定；write_file/edit_file/notebook_edit/todo_add/todo_update/bash等须原requires_approval或guardrail确认（bash危险仍拒绝）。clipboard/web_fetch/web_search/web_extract含系统/网络交互，T3/T4必须显式配置可用清单；clarify/plan_mode是已有占位能力，不将其标为真实暂停/禁写。T4只开放验证过的读取工具，T5接入人工菜单后才开放写工具；T2不新增Office路由。

## T3直接使用的接口与责任

- `ToolRegistry::with_environment(Arc<dyn Environment>)`指定后端；`with_execution_observer`注入可靠开始记录。既有ToolRegistry::call是可信进程内兼容入口，Host网络请求不能直接绕过审批调用它。
- `ToolExecutor::call_with_context`接收不可变最终输入、Run/call关联和调用token；旧执行器默认委托原call_cancellable。旧Environment默认可取消方法等待原exec，不保证即时中断；Local/Sandboxed已贯通托管清理。
- `ToolCallContext::approve`只能在可信审批器已确认后调用。上下文可克隆用于同一次调用传递，没有消费缓存或远程凭据；Host必须用共享Approval状态机/Run注册控制重复请求和执行唯一性。
- T3按规范根目录管理资源锁，获批后取锁、再校验文件前置条件、记录开始；清理/原子提交完成后释放。T2仅落实Run内metadata屏障与Todo事务锁，未落实跨Session/跨客户端资源调度。
- `todo::read`提供结构化只读查询；Host不得复制JSONL解析。Session/Skill/Goal查询继续使用各自所属Store接口。
- 原CLI/默认feature/sidecar不强制启用Host。新增core类型无Office/OpenCode字段。Office菜单confirm/reject/408、真实running/blocked映射分别在T3/T5消费，不把T2核心测试当浏览器验收。

## 兼容、数据与回退

ToolExecutor/Environment新增方法提供默认实现，既有实现可继续编译；`ApprovalRequest::new`及serde旧JSON不变，可选binding需外部struct literal调用方补字段。Todo不改格式；Session账本本阶段无新增事件格式；API快照同步。锁依赖复用原sandbox，tempfile/tokio-util已在锁文件，没有新增版本。

备份工作区.openpaw及会话数据后可回退代码；不删除用户账本、Todo或产物。原子替换错误不会先删旧文件；目录sync失败可能表示数据已替换但耐久性未知，报告错误且不可自动重试副作用。受限能力拒绝是必要安全变化，不能为了“回退可用”重新启用静默本地兜底。本轮Windows验证按用户决定暂缓；Linux交付已验收，T2 PR #6待平台审核/合入，不开放Office写工具，不进入T3。当前事实见0003首页及验证记录。
