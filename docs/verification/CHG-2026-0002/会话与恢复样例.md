# T1会话与恢复样例

本文件展示新事件的阅读方式；可执行夹具复用专用回归源码，避免另存一套逐渐漂移的测试账本。以下为说明性片段，不作为真实Provider验收证据；真实数据和HTTP断言由测试生成。

## 完整工具链

执行入口：`cargo test --locked -p openpaw-cli --test chat_persistence_regressions successful_tool_turn_persists_user_result_and_matching_ids`。用loopback HTTP服务让现有OpenAiProvider请求read_file，再给出正常文本响应；检查原SessionReader实际读取的JSONL：

~~~jsonl
{"type":"run_started","run_id":"示例-run"}
{"type":"usage","input_tokens":7,"output_tokens":4}
{"type":"message","role":"assistant","content":[{"type":"tool_use","id":"call-real-1","name":"read_file","input":{"path":"fact.txt"}}]}
{"type":"tool_call_start","call_id":"call-real-1","tool_name":"read_file"}
{"type":"tool_call_complete","call_id":"call-real-1","tool_name":"read_file","success":true,"duration_ms":1}
{"type":"message","role":"user","content":[{"type":"tool_result","tool_use_id":"call-real-1","content":"persist this result","is_error":false,"name":"read_file"}]}
{"type":"run_finished","run_id":"示例-run","status":"completed","error":null}
~~~

真实账本还含Meta、用户输入、每次usage和最后assistant。User角色的tool_result必须保留；tool_call_start表示模型提议已记账，不能由它把Office人物标成实际运行。耗时示例不是测试固定值，回归要求真实Some时长及ID配对。

后续Provider失败用`tool_results_and_call_ids_survive_later_provider_failure`：第二次HTTP响应没有结束标记；结果仍保存，部分assistant文本只保存一次，最终failed，不重试已发生的工具。

## 压缩后恢复

执行入口：`cargo test --locked -p openpaw-store --test session_recovery_regressions compacted_context_restores_without_duplicating_original_facts`。夹具按顺序保存旧Message、Usage、context_snapshot和新回复。SessionReader.events保留旧事实；ReadOutcome.restore返回`[summary, new reply]`，输入用量仍为3，不把summary再次作为用户事实索引。

真实引擎压缩入口：`cargo test --locked -p openpaw-engine --test lifecycle_regressions compaction_persists_snapshot_and_summary_usage_with_effective_model`，同时验证摘要用量和请求模型覆盖，避免只测手工拼JSON。

## 损坏与写入失败

`damaged_tail_is_backed_up_before_append`在有效Meta后追加不完整JSON字节，open_append后检查备份与修复前原文件逐字节相同；追加新Message后再次读取无尾损、两条完整事件。备份文件命名`<原路径>.torn-<pid>-<序号>.bak`，create_new不覆盖旧证据。

`torn_utf8_tail_and_repeated_repair_preserve_unique_backups`使用被截断的中文UTF-8字节，连续两次恢复必须生成两份独立备份；`valid_last_record_without_newline_remains_separate`验证合法无换行记录；`middle_corruption_is_not_modified`验证中间损坏时拒绝打开且原字节不变。

`persistence_failure_blocks_execution_and_never_replays_side_effect`在assistant/result/terminal边界注入存储错误；首次工具前失败时调用次数0，实际工具后失败时次数1，不能重试隐式重复执行。T2前旧工具只能等待实际结束；T3前不声称已提供Host崩溃后的interrupted协调或SQLite自动重建命令。
