# ADR-005：Chat Completions 的工具媒体适配

- **Status**: accepted（Q11 适配选择已确认；用户最终回复“开始实施”）
- **Date**: 2026-10-13
- **Deciders**: 用户；Codex 整理

OpenPaw 首版需要支持 Agent 工具读取图片和音频，同时继续使用 Chat Completions。
[官方 Chat 参考](https://developers.openai.com/api/reference/resources/chat)规定 tool 消息只允许文本，
user 消息可接受受模型能力约束的图片或音频。Q11 已确认：历史保留完整工具结果及其媒体来源；
Provider 发出全部对应 tool_call_id 的文本结果之后，将工具媒体转换成后续媒体输入交给模型。

这条附加输入属于协议适配，不生成新的用户回合或用户消息事实，不替代原工具结果。并行工具
调用先返回完整的配对结果，再附加媒体，保留工具名、调用 ID 和来源说明，防止图片与结果错配。
媒体能力和错误策略使用与用户附件相同的规则；Anthropic 使用其协议允许的 tool_result 媒体结构。

替代方案是首版只处理用户附件，或增加 Responses 图片工具结果支持。Q8 已要求媒体工具，Q4
已选择复用现有适配器，因此采用本方案，接受适配层与目标服务验证成本。官方 schema 允许这些
单独消息，但未找到对上述组合的通用保证；必须验证具体服务/模型的接受行为和正确理解，不能
称为 Chat 原生多模态工具结果。音频阶段也需独立验证。

完整范围、问题与最终授权见 [CHG-2026-0026](../changes/CHG-2026-0026-图片与音频附件理解.md)。
