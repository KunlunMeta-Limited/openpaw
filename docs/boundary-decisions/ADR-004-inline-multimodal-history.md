# ADR-004：内联附件的会话记录

- **Status**: accepted（Q6 / Q9 / Q17 已确认；用户最终回复“开始实施”）
- **Date**: 2026-10-13
- **Deciders**: 用户；Codex 整理

OpenPaw 的用户附件需要在重启和会话分支后仍可使用。2026-10-13，用户在 Q6 中选择
“直接把附件内容内联到会话记录”，因此图片和音频原件随会话内容保存，记录保持自包含。
当前 JSONL 已原样保存消息；该选择可以沿用消息回放和分支复制，而不新增独立附件资源仓及其生命周期。

替代方案是受管理的附件文件、会话只保存稳定引用。它能减少重复记录的体积，但需要资源仓、
引用完整性及分支/回退后的保留规则。本轮按用户决定采用内联方案，接受记录和分支文件体积增加，
Q13 已确认单图 5 MiB、单音频 20 MiB、每回合最多 4 个且原件总计 20 MiB，超限明确报错，
不自动压缩或转码；实际模型请求另须符合所选上游的更严格限制。已有纯文本和 Image 字段的读取兼容必须保留。

内联持久化只保证原件在会话记录中，不等于每次模型请求都应发送全部附件。Q9 已确认压缩后的
摘要保留附件编号和简要说明，Agent 可按需通过 read_attachment({attachmentID}) 重新读取
当前会话有效历史中的原件。媒体 token 估算与原件/请求体字节预算分别处理，
不按 Base64 字符数估算真实媒体 token，不用 Base64 文本摘要替代模型对附件的理解。
Q17 已选择 CLI / Host 接入共享自动压缩；公共记录继续保存真实消息，压缩上下文是可重建视图。
重启可重新摘要，不把摘要写成新的用户回合；有效历史的回退/分支边界同时约束原件读取。
完整范围、问题与最终授权见 [CHG-2026-0026](../changes/CHG-2026-0026-图片与音频附件理解.md)。
