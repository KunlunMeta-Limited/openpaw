# ADR-003：共享运行能力的所有权

- **Status**: accepted
- **Date**: 2026-10-13
- **Deciders**: 用户授权；Codex 按 Q1–Q5 实施

Host 已共享 AgentLoop、Provider、工具注册和审批，但仍保有中立调度、文件事务与第二份
持久化类型。决定由 Engine 拥有 FIFO 调度及受保护的回合执行，Store 拥有会话写入、
回放和修复机制；Host 与 CLI 组装适用能力并负责各自的交互适配。

## 决定的边界与理由

- Engine 的 scheduler 与 turn_execution 为独立模块，不把跨会话队列、Host 任务注册
  或 JSONL 事务加进 AgentLoop。它们使用中立参数和事件回调，能够被多个入口调用。
- Store 重用已有 Transcript/变更类型，提供独占 writer 的事务与修复能力。
  读取目录和查询历史继续只读，修复及写入使用明确接口。
- Host 保留会话表与协调锁、HTTP 幂等接收、协议身份校验、SSE/Office 发布、进程关闭
  及孤儿回合的恢复策略。CLI 保留输入、审批交互、输出与搜索索引刷新。
- 共享接口不依赖 Host、HTTP、Office 或终端；通过调用方组合执行与持久化，保持
  先持久提交再发布终态的次序。Engine 不因本次迁移新增 Store 依赖。

该方案把可复用能力的所有权交给相应模块。单纯拆 Host 文件不能实现跨入口复用，
而将整个 runtime 放进 Engine 会把模型执行与服务/协议生命周期绑定。
