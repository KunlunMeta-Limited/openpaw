# ADR-006：Office 委派的桌面与审批授权隔离

- **Status**: accepted（仅设计决定；实现与合并尚未批准）
- **Date**: 2026-10-19
- **Deciders**: 用户通过 CHG-2026-0032 访谈 Q3、Q4、Q6、Q7 确认

## Context

Office 分支的子 Agent 共享父审批管理器，多模态分支的 always 会在当前会话记住同工具授权。直接组合会使父 Agent 既有授权自动覆盖子任务；如果继续复用桌面包装，还会让并行子任务冒用父会话的桌面身份。

## Decision

桌面工具只供主 Agent 使用，子 Agent 继续处理后台工作区文件/命令任务。主会话保留 always 记忆，但其授权不自动扩展给子 Agent，子任务在既有 manual/guardrail 策略下需要明确审批。每次子任务执行有独立授权寿命，子任务内 always 不延续到下次执行，即使复用同名空间。父子授权均不相互传播。

## Consequences

保留主会话的审批体验，同时要求委派执行区分父子授权，桌面登记与凭据也保持隔离。本轮不自动把主会话上传附件传给子任务；工作区文件读取仍受原有路径和工具策略约束。Host 需聚合父子待审批项并正确清理；具体路由实现与回退缓存失效细节见 CHG-2026-0032。

## Rejection notes

未采用父子共享 always 的直接合并方式：用户选择了明确区分子任务授权，接受额外审批交互的成本。子任务不获得桌面权限，避免多个执行者竞争同一桌面及跨作用域复用登记。

相关方案和候选文件范围见 [CHG-2026-0032](../changes/CHG-2026-0032-Office多模态合并设计.md)。本决定保持 ADR-003 的 Engine/Store/Host 职责所有权。
