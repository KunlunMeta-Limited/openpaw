# 测试与验证规范

每个可交付变更（包含文档）完整运行当前已实现套件：fmt、默认/全feature测试与clippy、Host/sidecar共存、MSRV默认/全feature、默认依赖隔离、既有xtask门禁、cargo-deny、固定Office/SDK契约和治理测试。定向调试不替代最终完整验证；失败修复后重跑最终版本。Linux/Windows原生覆盖，macOS不在范围。未实现的Host/浏览器/真实Provider旅程不以mock或fixture冒充通过。

生产Rust功能/缺陷测试优先扩展所属crate既有测试；新增多个集成场景时用tests/features.rs与tests/regressions.rs显式挂载子目录。Cargo不会递归发现任意子目录，virtual workspace根tests/*.rs也不会自动执行。私有逻辑inline #[cfg(test)]并在CHG映射，不能为目录形式扩大public或复制实现。治理测试在governance/tests，契约复用tests/engine-host-contracts。

用例应包含正常/错误/边界；bug记录修复前失败、根因和修复后通过；并发/取消/副作用/平台差异必须测相应行为。不得删除/放宽断言、任意skip、无限重跑掩盖问题。既有ignored单列来源。

governance/commands.json登记实际argv、工作目录、平台和证据ID；governance/verify.py真正执行并保存每步退出码/时长/日志、工作树摘要、工具链及最终JSON。登记命令不代表执行。报告不可覆盖既有结果；日志不记录凭据和完整环境。Windows只能由原生执行产生，Linux报告不声明Windows通过。

本地先准备锁定依赖：Node24.19.0，契约npm ci --ignore-scripts --no-audit --no-fund；Rust stable/1.88，cargo-deny。脚本不修改系统HOME，不自动安装全局工具。不在Office工作区安装/生成，21来源从固定git对象只读核验；契约可在仓库外隔离副本执行，须记录来源哈希。

代码可提交后由CI验证精确head，报告写artifact；本地未提交则保留dirty摘要，不能称精确HEAD验证。Windows、真实Provider或浏览器尚未执行时明确未运行，历史结果不能代替当前提交。需求/设计/代码/测试/证据关联由追踪矩阵定位，实测结论仍需查看实际报告。

治理检查器自身必须有临时Git仓、中文/空格路径、重命名两端、越界、CHG缺失/重复/删除、风险降级、异常表格、测试入口、假批准等反例。门禁不能只检查自己永远通过的happy path。
