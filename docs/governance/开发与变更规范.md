# 开发与变更规范

适用OpenPaw；Office另受Rx预审批。用户当前明确指令优先于参考资料，参考framework和旧master-plan不是独立授权。

一Tx一主CHG，采用参考框架十二节中文表格作为单一事实源。所有功能、bug、文档、工程变更都登记；阶段完成后普通CHG不再受Tx串行限制。实施授权可引用明确用户指令，PR批准必须由非作者针对当前提交作出。工具不提供approve命令，不把姓名/时间非空当身份认证。

CHG字段包括状态、Tx、目标分支、实施授权来源、REQ/DES/D/R、准确文件/操作/原因/影响、禁止范围、保护级别、数据与实现、文档影响、测试、回退、验证和审批。状态draft/review可用于方案/在已授权范围内实施；review不表示已批准。verified只表达证据通过，closed还要求真实批准和合入记录。旧修复追溯登记，不编造当时事前批准。

允许文件必须具体到仓库内路径，不用全仓通配。每项“必改/条件”分开；实际diff不得超出允许集合，必改必须出现，条件未使用说明原因。重命名登记旧/新两端，删除登记原因并处理引用。保护等级不得低于profile，L4要求critical风险声明；门禁自身和依赖/权限/协议变更不能自行降级。

代码改动优先复用；新增必须解释不可复用的职责。bug先复现，独立D记录/逻辑提交/回归；不改断言掩盖失败。私有实现可在授权边界内迭代，扩大API、权限、依赖、持久化或Office范围须补方案和授权。

文档影响表列具体文件、章节和理由。行为→需求/使用说明；职责/状态→设计；路由/事件→契约/fixtures；存储→迁移恢复；权限→风险回归；依赖/平台→兼容/构建/CI。不涉及也写理由。自动检查只核对关联和结构，语义由人工评审，不以更新时间或任意改一行证明同步。

Office任何修改先Rx：现状/复现或必要性、无修改替代、方案/准确范围、功能/协议/数据/权限/部署/双平台影响、测试/回退、批准版本与证据。用户批准总计划、允许提案、发现bug、CI绿灯都不能替代Rx批准。只读核查和仓库外测试副本不改Office源工作区。

历史ADR已按用户指令还原。历史报告保留事实，不批量重写；无关m2/m5格式改动保留工作区，提交只选择本CHG文件。DCO使用git commit -s，不自动合入、不强推。平台required checks/CODEOWNERS需真实账号和人工配置；本地文件无法保证这些设置已生效。
