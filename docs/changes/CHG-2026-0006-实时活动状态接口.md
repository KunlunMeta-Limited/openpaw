# CHG-2026-0006：实时活动状态接口

## 先说结论

本变更为活动回合增加脱敏的内存活动快照，使 AI Office 能区分思考、工具执行和回复阶段。它只扩展 `GET /session/status` 的可选 `activity` 字段，不把思考正文、工具参数、路径或凭据写入 JSONL。实现和历史测试已有记录，但当前工作树尚无独立 PR、CODEOWNER 审核和正式批准证据。

## 2. 变更原因

AgentLoop 仍在生成消息时，完整消息 REST 不一定包含当前工具或文本阶段。AI Office 若只依赖历史消息，只能显示笼统的忙碌状态，人物动画和状态条会滞后。活动快照必须是只读、脱敏且短生命周期的观察数据，否则会把内部思考、工具输入输出或凭据泄露给前端。

## 9. 影响、数据流和实现

### 影响分析

调用方只多读取可选字段；被调用方仍由 `runtime.rs` 维护每 session 独立内存。活动锁仅覆盖一次快照读写，不跨越模型或工具 `await`。权限不变，仍受 Host Basic Authentication 保护。性能影响是常量级锁和小对象序列化，日志和持久化格式不变。

### 数据流和失败路径

```text
AgentEvent -> SessionHandle.activity 内存快照 -> GET /session/status
         \-> 回合完成、失败或取消 -> clear_activity -> 不写 JSONL
```

活动生成失败或序列化失败不得改变回合结果。不同 session 的快照不能串用；客户端必须按 session ID 消费。

### 实现方案和选择理由

选择 Host 内存快照而不是轮询完整消息或持久化中间状态，因为它能降低读取和解析开销，同时避免把瞬时、敏感的执行细节写入历史。替代方案是扩展 SSE 专用事件，但会扩大 OpenCode 兼容协议和重连恢复范围，本变更没有采用。
