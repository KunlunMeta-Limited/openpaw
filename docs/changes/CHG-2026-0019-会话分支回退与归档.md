# CHG-2026-0019：会话分支、回退与归档

## 先说结论

本变更把 OpenPaw Engine Host 的 `fork`、`revert` 从返回原会话的显式降级改为真实会话操作，新增 `unrevert` 与 `PATCH /session/:id`，使 OpenWork 已有的 Branch、Revert、Archive/Unarchive 和 Rename 交互在 attached OpenPaw 模式下可用。Revert 只撤销会话历史和模型上下文，不恢复工具已经修改的工作区文件；新 prompt 会提交暂存回退，之后不可 unrevert。持久化继续采用 append-only JSONL 和 Host 私有未知事件，不修改 `openpaw-core`、`openpaw-store` 或依赖树。

**当前裁决：草案（draft），禁止修改业务代码。** 2026-09-24 的需求访谈已确认产品语义、错误边界、持久化方案、跨仓测试范围和行数预算，但尚缺人工 CHG 批准、L3 CODEOWNER 审查和正式测试证据。本文件获批前只能修改本 CHG 和索引。

## 2. 变更原因

当前 Host 将 `POST /session/:id/fork` 和 `POST /session/:id/revert` 都路由到 `get_session`，返回原会话且不产生任何状态变化；`POST /session/:id/unrevert` 和 `PATCH /session/:id` 不存在。OpenWork 已有产品代码会校验 fork 必须返回新会话、revert 必须返回匹配的游标，并通过 `session.update` 写入 `time.archived`，因此 attached OpenPaw 模式只能提示不支持或请求失败。

Host 的 `SessionWire` 只有 `id/title/slug/directory/time.created/time.updated`，恢复投影也只重建消息、回合结果和 request admission。若只补路由而不补持久化，archive/revert 会在重启后丢失；若只在 UI 隐藏消息，被撤销尾部仍会进入下一轮模型上下文；若直接重写 JSONL，崩溃或写盘失败可能损坏完整会话。因此需要把公共契约、内存状态、append-only 恢复投影和 prompt 接收事务作为一个受控变更实现。

## 9. 影响、数据流和实现

### 9.1 状态与持久化

`session_mutation.rs` 只定义 Host 私有事件、`SessionMutationProjection` 和无 I/O 的折叠/裁剪函数。`runtime.rs` 仍是 session、writer、gate 和内存缓存的唯一 owner，不允许新模块绕过 runtime 写文件。旧 JSONL 没有私有事件时，投影为未归档、无 fork 来源、无 revert。

Archive 保存正数 Unix 毫秒；unarchive 追加值 0，wire 响应省略 `time.archived`。Revert 状态为 `none -> staged -> cleared` 或 `none -> staged -> committed`。staged 期间消息仍在 JSONL、message cache 和内存 Session 中，UI 按游标隐藏；下一条新 prompt 在 requestID replay/conflict 判断之后、Provider 执行之前提交裁剪。

### 9.2 Prompt 提交事务

```text
POST prompt/message
  -> 校验 body、session、requestID
  -> replay/conflict：直接返回，不提交 revert
  -> turn_gate：确认未删除、未活动并取得调度容量
  -> 若 staged：准备包含新 turn accept 的 session_revert_committed_v1
  -> writer snapshot 后只追加这一条复合接收记录
  -> 全部 fsync 成功后发布裁剪后的 Session/cache/outcomes/admissions
  -> 启动 AgentLoop；模型只看到保留前缀和新 user
  \-> 任一写入失败：截断到 snapshot，恢复内存，返回 persistence_failed
```

`session_revert_committed_v1` 内嵌本次新 user、初始 turn outcome 和可选 request admission，由恢复投影先裁剪再接收，避免两次 fsync 之间崩溃造成“已提交回退但新 prompt 未接收”的半事务。commit 必须删除边界及之后的 message、关联 turn outcome 和 request admission，但保留历史 turn sequence 高水位，防止重启后复用 ID。commit 后不可 unrevert；原始 JSONL 中的旧事件仅作为 append-only 历史存在，REST、SSE、模型上下文和恢复投影均不得重新暴露。

### 9.3 Fork

Fork 与 prompt/delete 使用源 session 的生命周期和 `turn_gate` 线性化。源会话活动时返回 409。未提供边界时复制全部当前可见消息；提供边界时复制严格早于该消息的前缀；源会话有 staged revert 时，上限始终为游标之前。未知或隐藏边界返回 400。

新会话继承 directory、provider 和 model，标题按同一源会话的直接分支生成 `源标题 (1)`、`源标题 (2)`。从分支再次分支时以当前标题为基准，例如 `方案 (1) (1)`。消息、part 和工具调用关联 ID 全部重新生成；不复制 turn outcomes、request admissions、active、approval 或 archive 状态。子会话先写同目录、非 `.jsonl` 后缀的临时文件；meta、workspace metadata、fork origin 和消息全部 fsync 后关闭 writer，再原子重命名为最终 JSONL、重新打开 append，最后加入 session map 并发布 `session.created`。失败时清理临时或最终文件，源会话不变，列表扫描不会看到半成品。

用户 Branch 是独立根会话：Session 不返回 `parentID`。来源只保存在私有 fork event，避免 OpenWork 将其当作 sub-agent 从 sidebar 隐藏。

### 9.4 PATCH、错误和事件

PATCH 可独立或同时提交 title/archive；空 patch、空标题、负归档时间或非法类型返回 400。涉及 archive 且会话活动时整次请求返回 409，不得只更新 title；单纯 title 更新允许在活动回合执行。PATCH 的全部字段写入同一条 `session_metadata_v1`，恢复投影采用最后提供的字段，避免 title 与 archive 半更新；既有自动标题仍可继续使用 core Metadata。未知 session 返回 404。unrevert 在无 staged 状态时幂等 200。

所有 Session 事件统一为 `properties={sessionID,info}`。这修复当前 Host 把字段直接放在 properties 顶层、OpenWork 因找不到 `info` 而忽略事件的问题。消息、permission、status 和 Office 事件不改变。

### 9.5 行数、替代方案和范围

当前已记录的成功门禁为 Host 4999/5000、Host tests 1479/1500。本变更把上限分别调整为 5700 和 1900；实际实现仍必须删除 fork/revert no-op 分支、复用 writer snapshot/error 映射并记录最终增量。没有采用大规模压缩现有 Host，因为会把功能修复变成无关重构；没有新建 crate，因为状态只被 Host 使用；没有独立 metadata 文件，因为会产生双文件一致性问题；没有物理重写 JSONL，因为断电和 fsync 失败会扩大损坏面。

本期明确不恢复文件系统。工具已写入的文件在会话 revert 后保持现状；完整文件快照需要另建 CHG，覆盖 write/edit/bash 工具前置打点、快照存储、冲突和恢复权限。

回滚限制：一旦写入 `session_revert_committed_v1`，不得直接降级到不识别该事件的旧 Host，否则旧 reader 会重新显示 JSONL 中被逻辑删除的尾部。运行时回滚必须部署仍能解释全部 `session_*_v1` 事件的兼容版本；不得删除 `OPENPAW_HOME` 或重写用户会话。新功能尚未被使用时，代码回滚只需恢复路由、协议、预算和测试。该版本门槛必须进入发布说明。
