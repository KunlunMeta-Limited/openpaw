# CHG-2026-0010：回合终态与办公室空闲闭环

## 先说结论

本变更调整成功回合的终态发布顺序，确保客户端收到 `session.idle` 时最终 assistant 已进入缓存且 `active=false`；同时释放该回合实际占用的全部 Office 角色，不再保留虚构的长期整理状态。它不修改 HTTP/SSE/Office 字段，也不解决动作重放和持久 outbox。历史测试已有记录，但正式 PR、人工审批和当前候选版本复测仍缺失。

## 2. 变更原因

旧成功路径先发布 `session.idle`，随后才刷新 `message_cache`、更新时间并释放活动标记。客户端收到 idle 后立即读取消息可能缺少最终 assistant，立即发下一轮也可能得到 409。Office 投影还把 5 号角色长期留在 working，导致没有真实任务时仍显示工作动画。终态必须在单一闸门内按可观察顺序收敛。

## 9. 影响、数据流和实现

### 影响分析

客户端读取最终消息和提交下一轮的时机变得确定；事件字段、鉴权、依赖和存储格式不变。`turn_gate` 只保护终态收敛与新回合进入的顺序，不跨越 provider 执行。Office owner 集合继续支持多 session 共享角色：一个 owner 完成不能错误释放仍被其他 owner 使用的角色。

### 数据流和失败路径

```text
AgentLoop success
  -> append session messages
  -> refresh message_cache and updated time
  -> clear activity and release Office owner
  -> under turn_gate set active=false
  -> publish session.status(idle)
  -> publish session.idle
  -> next prompt may reserve session
```

持久化失败和取消不应伪装成成功；它们由各自失败终态路径收敛。Office 投递失败只记录日志，不阻止回合终态。

### 实现方案和选择理由

采用同一 `turn_gate` 串行化旧回合 idle 与新回合 busy，避免通过固定延时掩盖竞态。Office 结束只释放实际 owner，而不是设置新的 working 状态，因为动画必须反映真实任务。没有引入全局 UI 状态或额外数据库。
