## 禁止路径与兼容性

不改 `openpaw-core`、Engine/Store、openpaw-tools 默认注册表、公共 trait、Cargo.toml/lock、CLI、CI、Office 或 provider 配置：工具只是 Host 专用包装，不要求改变其合同或默认依赖。不得改现有 session JSONL 协议或回合/SSE语义，不修改其他会话及部署。禁止全局进程环境传桥接凭据，因为内置 bash 等工具可能读取；禁止把 token 放入 prompt、journal、事件、日志、Debug 或工具 schema。未经本次部署授权不重建或重启现有容器。

## 接口与可信身份

注册 JSON：`{"bridge_url":"http://host.docker.internal:<port>/ai-pc","token":"<随机会话令牌>"}`；拒绝额外字段，不接受 mode、service_id、自报 session。只接受 localhost/127.0.0.1/host.docker.internal 的 HTTP(S) 地址、固定 /ai-pc 路径，无用户信息、query、fragment；不跟重定向，限制请求与响应容量及超时。凭据只在会话登记表的内存中。

工具参数：current 为严格空对象；history 为 keyword/application/from_ms/to_ms（关键词与应用最多 256 字，时间 Unix 毫秒，结果有界）。工具包装器注入真实 Host session id，向登记地址的 /current 或 /history 发一次请求，用会话 token 鉴权。参数不能选择 token、身份或权限模式。内置工具仍由原 ToolHost 执行，但已登记 AI PC 会话的全局 `session_search` 拒绝调用，必须使用授权历史工具，避免从官方全局会话索引绕过桌面授权；普通会话不受影响。调度回合时动态补充工具声明，不能仅依赖创建时缓存的 21 项。此为已批准包装器与权限数据流范围内的实现细化，不改全局注册表或 Core trait。

AI PC（独立仓库实现）持久绑定 token→本应用创建的 Host session→接收服务与权限模式，逐次执行最新授权。受限历史必须在已授权文字上匹配，不能因未授权标题、应用、摘要匹配而泄漏其存在。每次交付先记录内容来源/有效授权/受管会话关联，支持后续撤销和删除。令牌轮换或注销立即拒绝旧令牌；暂停采集不因查询而恢复。桥接不提供通用 MCP/agent 或模型推理 API。

默认会话仍只有原 21 工具。Host 重启后登记失效；AI PC 只为自己的会话重新登记；fork 的新 id 默认无桌面工具。注册和删除在 runtime 生命周期与回合闸门内协调，禁止运行中替换授权。

## 替代方案

不采用在 prompt 中加入凭据/开放标记，模型不能作为授权主体；不采用全局启用工具或通用 MCP，避免其他客户端获取桌面记录；不改 provider 协议，因为 agent 问答继续使用既有接口。
