## 2. 变更原因

AI Office 扩展对话、任务、技能和动画展示后，需要确认 Host 仍满足工具到人物映射、每回合最多一次拜访、动作超时失败隔离、取消传播和审批清理等既有约束。本变更只登记兼容复核和验证证据，不用前端需求反向修改 OpenPaw Core 或跨项目协议。

若不复核，前端可能把动作投影误认为业务终态，或在 Host 实际取消、审批、超时语义变化时产生错误展示。

## 9. 影响、数据流和实现

### 影响分析

复核确认六个办公室角色仍是单一 AgentLoop 的阶段投影；Office 请求失败只影响动画，不反向改变回合。任务和技能是 AI Office/Gateway 的产品对象，不进入 OpenPaw Core。Host 的 session JSONL、活动回合和 pending permission 继续由 runtime/approval 唯一维护。

### 数据流和失败路径

```text
AgentLoop / AgentEvent
  -> Host office.rs 脱敏映射
  -> POST /actions（500 ms 超时、失败不重试）
  -> AI Office Gateway 队列
  -> 浏览器动作轮询和场景投影

Host session/message/status/permission
  -> AI Office Gateway 受控代理
  -> React 对话、任务和权限面板
```

Host 失败、取消和审批语义只能由 Host 状态与持久事实判断，不能由 `/actions` 是否到达推断。

### 实现方案和选择理由

本变更采用只读源码复核和现有自动化测试，不复制一套运行时状态，也不为前端展示修改 Host 协议。后续发现 Host 缺陷时必须建立单独 CHG，列出实际 Rust 文件、接口、状态机和回滚。
