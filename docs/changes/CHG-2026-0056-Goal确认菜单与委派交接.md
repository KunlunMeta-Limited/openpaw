## 2. 最终行为

### 2.1 派工与返回

成功开始一次真实子执行时，按实际员工 `sceneActorId` 发送主→子 `activity.start / office.visit`，随后沿既有流程执行、返回及收尾。命令用本次真实执行的唯一身份去重；相同 Goal Task 的后续合法执行不得复用旧命令 ID。拒绝、取消前未启动以及无有效员工绑定时，不伪造交接。Office 发送失败依旧与执行结果隔离。

### 2.2 自做与委派

规划提示及工具说明明确区分：主 Agent 自己做才调用 `start_task`；委派从 pending 直接 `start_agent(goal_task_id=...)`，由 Host 原子预留并绑定真实子执行。`task_id` 仍指真实子会话。

对实际复现的“刚 start_task，尚未执行任何工作就委派”，允许**同一真实回合内的原子转交**，而非放开所有 running 任务：当前主任务与当前回合必须吻合；没有子执行绑定、结果或验收；从本次主执行起点到该委派调用之间，可靠执行记录必须证明没有业务工具已开始、已完成或结果未知。只读业务工具也按已开展工作处理；缺少证明即拒绝。转交成功清除主执行占用，再由原委派路径取得独占绑定。并发只能一项成功。

一旦执行过工作、已派发、已有产出、失去原回合、受人工阻塞或依赖未验收，继续拒绝重复启动，并给出可纠正说明。不得通过删除重复保护、忽略 Goal 参数或自动重跑历史任务修复。

### 2.3 固定确认菜单

1. 每次成功提交新计划版本后，暂不继续交付；后台根据真实 Goal 状态安排固定菜单，不依赖模型再调用提问工具。同一工具批次不能连续提交多个未确认计划而跳过前一个菜单。
2. Engine 先将该版本的**完整规范计划**作为可见聊天内容可靠记录并发布，再开始等待答案。卡片只放版本及简短提示，不能因 `description` 的 2000 字符限制截断或替换完整计划。
3. 在原版“待你决定”卡片提供固定选项“执行／修改／取消”，保留原版“其他需求”自定义输入。
4. “执行”：仅在当前会话、当前回合、当前 Goal、当前已展示版本及该逻辑问题全部吻合，且真实回答可靠保存后，授予该版本的当前回合许可。刷新模型工具声明及 Goal 提示，沿**同一 AgentLoop、剩余预算和取消令牌**继续，不能另起隐蔽回合或假装用户发送“确认执行”。
5. “修改”：不执行，保存为待修改并结束本轮等待，提示在原聊天补充修改要求。自定义输入按真实回答保存为本次修改要求，可继续规划；不把自定义“执行”等文字当作选中执行。新版本必须再次完整展示并弹菜单。
6. “取消”：保留计划与执行事实，将当前 Goal 结束，不再自动接续；不把取消当作完成。已有子执行沿既有取消和收尾路径处理，记录真实终态。
7. 用户说“每次”，因此初始 `set_plan`、用户修改后的 `set_plan`、执行中 `replan` 的每个成功新版本均适用；失败的提交、只读及重复展示不产生新题。执行中重规划也需要重新确认，这是相对原来目标内自动重规划规则的明确调整。
8. 超时、保存失败、停止、断连取消、服务重启或旧版本迟到回答均不授权。使用现有每主会话 FIFO，轮到该题时开始 5 分钟；刷新重显保留逻辑问题和原剩余时间。服务重启后只恢复事实，等待用户明确继续并重新确认，不自动执行。
9. 普通 `request_user_input` 仍只提供信息，不批准 Goal 或授予工具权限。原有用户文字“确认执行”仅在当前计划已完整展示、旧菜单已失效且无活动回合竞争时，沿现有真实用户入口兼容；不能使未确认的新版本因旧 `confirmed_version` 或 `/goal continue` 而绕过确认。

## 3. 实现边界与数据流

固定菜单安排在工具批次可靠结算之后、下一次模型请求之前。Goal 工具保存待审核版本和真实 `ToolInvocationContext`，并立即关闭该版本未获批的交付准入。Engine 只新增可选、中立的交互协调扩展：无扩展时保持当前行为；扩展只发布入口给出的规范说明，等待真实交互，按结果继续或暂停，不理解 Goal、HTTP 或 Office。

拟登记 Engine 接口：`TurnOptions::tool_batch_coordination`、`ToolBatchCoordination`、`TurnInteraction`、`TurnInteractionResolution`。协调器准备规范展示与延迟启动的等待 future；Engine 可靠记录／发布展示后才轮询该 future，取消时丢弃它；继续结果携带当前工具声明及系统提示，暂停结果携带原因。保留现有迭代、token、压缩与取消检查；耗尽额度的最终答复路径不得弹出会诱导继续执行的新菜单。具体签名在上述职责内确定，新增其他公共符号须先补登记。

Goal 拟登记接口：`PlanReview`（会话内 Goal／版本／真实调用／规范计划的只读绑定）、`GoalContext::pending_review`、`GoalContext::review_displayed`、`GoalContext::settle_review`；`reserve_delegation` 追加真实调用上下文，用于核验无工作转交。其余新增实现保持私有，`GoalRuntime` 继续使用原有五项同步效果，不新增 writer。

Host 使用现有 `QuestionContext`、FIFO、`decision.request`、回答归属校验及唯一 writer。固定菜单的提问内容由后端构造，绑定真实的计划更新调用；不用模型参数、工具结果正文或模型自称的用户选择授予许可。Goal 快照新增带默认值的私有可选审核记录，记录逻辑问题、实际更新调用、Goal／计划版本、展示与处理状态；`user_question_v1` 的公开形状不改。

原件／恢复校验仅对**可信 Goal 审核记录已绑定的真实 goal_update**承认这类后端问题，原有普通问题仍要求真实 `request_user_input` 调用和完全匹配的输入。旧回合、回退后隐藏记录、其他会话、普通问题或伪造相同选项均不能成为审核许可。已保存回答与审核提交之间故障时暂停，不重放权限；重启不恢复内存执行许可。
