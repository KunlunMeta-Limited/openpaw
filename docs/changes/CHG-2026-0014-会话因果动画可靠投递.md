## 2. 变更原因

当前 `OfficeAction` 只有动作 payload。`OfficeDispatcher::send` 使用有界 MPSC 的 `try_send`，队列满或 receiver 不可用时只记录失败；HTTP worker 使用 500ms 尽力 POST，不重试、不持久化，也没有稳定事件编号。Gateway 和浏览器因此无法判断动作属于哪个 session/turn/task，无法区分重复与重放，也无法在 Host/Gateway/浏览器重启后恢复多会话人物状态。

本变更把 Office 输出定义为“可恢复但不影响业务结果的视觉投影”。每个 turn 产生稳定的 `eventId`、回合内严格递增 `sequence`、session 内严格递增 `turnOrdinal` 和稳定 `sessionEpoch`，批次在 Host outbox 中等待 Gateway 持久接受；网络失败使用同一 eventId 重试。outbox 达到有界容量时不得阻塞 Provider 或伪造 turn 失败，而是压缩为每 session 最新 snapshot 并记录脱敏诊断。

当前 `MessageRequest` 和 `ScheduledTurn` 没有任务编号，禁止从标题、时间、UI 选择或文本猜测 `taskId`。本合同采用向 `prompt_async` JSON 增加可选 `taskID` 的方案：任务中心发起时由 Gateway 传入真实 goal id，普通对话传 null/省略；Host 校验后原样放入私有 `ScheduledTurn` 和动画 envelope，不写入模型 Prompt。该新增字段和多消费者租约模型必须由真实协议/Gateway/Host 负责人批准后方可实施。

## 9. 影响、数据流和实现

### 9.1 因果生成

```text
reserve turn -> 确定 sessionId + turnId + optional taskId
             -> 恢复/分配 sessionEpoch + turnOrdinal
AgentEvent -> Office mapping
  -> sequence += 1
  -> eventId = stable unique id
  -> append to outbox before enqueue delivery
  -> delivery worker POST /actions/v2
```

同一个语义事件只生成一次 envelope。HTTP retry、Host worker restart 和 Gateway 408/425/429/5xx 都复用相同 eventId/sequence。不同 session 各自保序，不要求全局总序；同 session 先比较 sessionEpoch，再比较 turnOrdinal，最后比较 sequence。旧 sessionEpoch 或更小 turnOrdinal 的迟到事件进入诊断但不得覆盖当前投影。Gateway 用 journal cursor 提供消费顺序。

### 9.2 HTTP 批次、ACK 和错误分类

`POST /actions/v2` 请求固定为：

```json
{
  "schemaVersion": 2,
  "producerId": "host-instance-id",
  "batchId": "stable-batch-id",
  "events": [{ "schemaVersion": 2, "eventId": "evt", "sessionId": "ses", "sessionEpoch": "epoch", "turnId": "turn", "turnOrdinal": 1, "taskId": null, "sequence": 1, "emittedAt": "2026-09-17T00:00:00Z", "action": { "type": "set_state", "rosterNo": 1, "state": "thinking", "task": "处理当前回合" } }]
}
```

Gateway 成功持久接受后返回：

```json
{ "schemaVersion": 2, "batchId": "stable-batch-id", "acceptedEventIds": ["evt"], "duplicateEventIds": [], "journalCursor": "42", "highWatermark": "42" }
```

整批先校验再写入；相同 eventId 和相同 canonical digest 为幂等 duplicate，相同 eventId 不同 digest 返回 409 并进入 producer dead-letter。408、425、429 和 5xx 可重试；429 尊重 `Retry-After`；413 对多事件批次二分重试，单事件仍 413 时进入 dead-letter；400/409/422 为 payload 永久错误；401/403 为配置阻断并打开 circuit，人工修复前低频探测；网络超时和连接重置可重试。任何分类都不得改变 turn outcome。

Poll 响应固定包含 `consumerId/events/nextCursor/highWatermark/gap/leaseExpiresAt`；ACK 请求固定包含 `consumerId/cursor/appliedEventIds/projectionDigest`。ACK 只能确认已按序应用的连续前缀。`gap=true` 时客户端停止应用增量，获取目标 session snapshot，使用 snapshot 的 cursor/epoch/ordinal 重置后再续传。

### 9.3 outbox、journal、租约和失败隔离

Host outbox 固定在 `<OPENPAW_HOME>/office-animation-v2/host-outbox/<producerId>/`，Gateway journal 固定在 `<OPENPAW_HOME>/office-animation-v2/gateway-journal/`。两者使用版本化 `manifest.json`、分段 JSONL、snapshot、dead-letter 和同目录临时文件；写入流程为 write -> flush -> sync -> close -> Windows 同卷原子 replace。不得写入 session JSONL。目录使用独占 lock + PID/启动标识/heartbeat；无法证明旧锁已失效时启动失败，禁止两个 writer 同时写同一 journal。

Gateway 每个浏览器 tab 使用 sessionStorage consumerId。poll/ACK 自动续租，推荐租约 TTL 5 分钟；compaction 只等待未过期 consumer 的最小 ACK，关闭浏览器后租约过期不会永久阻止压缩。过期 consumer 再连接必须 snapshot resync。多消费者租约模型及 TTL 属于人工批准项，批准前不能实现为隐式“第一个浏览器拥有全部事件”。

journal 配额建议 256 MiB、Host outbox 建议 128 MiB、dead-letter 建议每端 32 MiB；具体值由负责人结合 10,000 事件压力结果批准。超过配额先生成每 session 最新完整 snapshot并合并可推导中间状态，绝不删除最后 snapshot、未接受关键终态或未过期 consumer 唯一所需的 gap 信息。损坏 segment 隔离到 `corrupt/`，从最后已校验 manifest/snapshot 恢复，并对客户端返回 gap，不静默跳过。

投递成功仅在 Gateway 返回 202 且响应 batchId、accepted/duplicate eventId 集合和 cursor 通过最小校验后删除/标记 accepted。网络错误使用有抖动指数退避；永久 payload 错误写 dead-letter 并从活动队列隔离，保留 eventId、digest、稳定错误分类和脱敏原因。

达到容量阈值时按 session 保留最新 snapshot 和尚未投递的关键转折事件，丢弃可由 snapshot 推导的中间冗余状态；记录 dropped/coalesced 计数。任何 outbox 错误不得让 turn 从 completed 变 failed，也不得延迟 session idle。Host 正常关闭时有界等待 worker，超时后保留磁盘 outbox 供重启恢复。

### 9.4 多会话投影、人工菜单和迁移

Gateway ingest 时按 `sessionId/sessionEpoch/turnOrdinal/sequence` 更新每 session 逻辑 snapshot。React 只把 `selectedSessionId` 对应 snapshot 映射到六个物理人物；切换时递增本地 scene epoch，旧 mission 回调不得覆盖新会话。后台会话继续更新逻辑投影并在最近对话/任务中心显示活动状态，但不抢占 Canvas。

`OfficeCanvas` 人工状态、表情和拜访菜单只在当前 session 没有 queued/running 真实 mission 时启用；真实 mission 活动期间菜单禁用并解释为“当前由任务驱动”。人工动作只能进入本地开发轨道，不写 v2 journal、不改变 Gateway agent projection。

迁移期支持配置 `legacy`、`dual`、`v2`。默认在 Gateway/UI v2 就绪前保持 legacy；人工批准联调后进入 dual，比较 v1/v2 数量和状态但 UI 只选一条生产轨道；稳定窗口通过后切 v2。不得在未验证回滚前删除 v1 序列化和配置。

v1 阶段的 paused 只能停止 destructive GET；v2 阶段 paused 继续 poll 并更新逻辑投影，但冻结物理 ticker/mission，恢复时 hydrate 最新 snapshot。hidden 在两个阶段都只改变布局；v2 hidden 继续消费逻辑投影。两种阶段不得混用语义。
