# CHG-2026-0047：适配原版 main 创建工作区

status=approved（2026-10-23，用户明确要求“帮我把 engine host 适配一下现在的创建工作，保证现在的功能不变”，并确认测试写在现有 http.rs 的 tests 模块）。授权仅覆盖此兼容适配，不启动历史工单或动作队列修复；不创建提交、不推送、不部署。L3 CODEOWNER 合并审查独立保留。

## 原因与边界

原版 main 已更新到 d150b96，通过 `/api/pawoffice/ui` 发起未绑定办公室/会话的 `office.create`，等待业务后端通过 `ui.next` 领取并以 `ui.respond` 返回 `target: office` 的真实快照。当前 Host 只处理查看详情等 UI 操作，创建会落入未开放说明；原有 `POST /api/pawoffice/workspaces` 已能安全创建真实目录。

## 实现与接口

将原 HTTP 创建流程下沉到 MainOffice::create_workspace，以可信服务端工作根目录和名称为输入。保留单层目录、UTF-16 40 单元、设备名与非法字符校验、大小写不敏感重名拒绝、100 办公室限制、admission 串行化、原子目录登记和仅回收本次新建空目录的失败清理。

旧 POST /api/pawoffice/workspaces 的 JSON、201 快照及 400/409/422/500 错误保持。新版 UI 创建要求 teamId/conversationId 为空、name 为字符串；沿用相同创建逻辑。成功只返回 target=office 与 wire_snapshot，失败返回 target=result/success=false/message；不使用假办公室、不隐式创建会话、不调用模型、不自动重试副作用。UI 操作的请求 ID 只用于回复关联，不引入跨 HTTP 请求去重承诺。

既有 actor.inspect/employee.inspect/dialog.action/conversation.delete 与其他未开放任务操作保留原分支。复用 runtime 弱引用取得可信工作根目录，不接受浏览器传入路径或上游地址；不持有同步锁跨 await。新增私有异步 directory_sync 互斥，协调周期完整目录发布和 UI 创建/回包，防止先初始化新 ID 导致 Gateway 把创建回复判为 OFFICE_ALREADY_EXISTS；不占用聊天 admission 或 records 锁等待网络。关闭和投递失败不重跑创建，已保存的目录仍通过原周期同步/重启恢复。

替代方案：修改 main 恢复旧专用 HTTP 路由会违背远端原版要求；复制一套目录创建逻辑会导致两个入口校验与错误漂移；用假的本地快照代替真实创建会丢失重启恢复，均不采用。
