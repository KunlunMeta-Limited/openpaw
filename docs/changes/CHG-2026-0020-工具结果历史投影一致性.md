# CHG-2026-0020：工具结果历史投影一致性

## 先说结论

本变更只修改 OpenPaw Engine Host。`GET /session/:id/message` 将 Core 中用于模型上下文的
`user + ToolResult` 消息折叠回发起调用的 assistant tool part，使 REST 历史与实时 SSE、
OpenCode v1 fixture 保持一致。这样在 Revert 隐藏最终 assistant 回复后，OpenWork 看到的可见历史
以已完成的 assistant tool part 结束，不会把内部工具结果误判为一条尚未回答的用户任务。

登记的 OpenPaw 文件，不代表合并或发布批准。

## 2. 缺陷与根因

AgentLoop 按模型协议把工具结果保存为 `Role::User + ContentBlock::ToolResult`，这是内部模型上下文，
不等于终端用户的新任务。实时 SSE 已将 `AgentEvent::ToolResult` 更新到原 assistant tool part；固定的
OpenCode v1 消息 fixture 也把 completed tool 保存在 assistant 消息中。但 REST 历史当前把 Core 消息
逐条映射，导致工具结果暴露为单独的 user 消息。

当用户对最后一条 assistant 文本执行 Revert 时，该文本及尾部被正确隐藏，前一条内部工具结果仍可见。
OpenWork 的 admission outcome 因最后可见角色是 user 而显示 `The task was accepted, but no result arrived`。
Revert 状态、游标和持久化本身均已成功，异常来自 REST wire 投影不一致。

## 4. 禁止范围

不修改 OpenWork 的 `apps/**`、`packages/**`、`ee/**` 或测试；不修改 `openpaw-core`、AgentLoop、
JSONL、`runtime.rs`、`session_mutation.rs`、`events.rs`、依赖和 Compose。Core 中的 ToolResult 继续作为
user 消息保存并进入模型上下文；只改变 Host 的 OpenCode REST 投影。

## 5. API 与兼容规则

`GET /session/:id/message` 与 `GET /session/:id/message/:messageID` 的路由、状态码和顶层字段不变。
消息投影增加以下规则：

1. assistant `ToolUse(callID)` 后紧随的纯 ToolResult user 消息，如果每个结果都能匹配一个此前可见的
   assistant tool part，则把该 part 的 `state` 更新为 `completed` 或 `error`，并省略内部 user 消息。
2. 一个消息中的多个工具结果必须全部匹配后才折叠，避免部分匹配造成数据丢失。
3. 普通用户文本、混合内容、空内容或无法匹配的 ToolResult 保持现有逐条投影，作为兼容性降级。
4. 折叠后保留 assistant message ID、part ID、callID 和 tool 名称；不伪造 assistant 文本，不修改
   Revert 游标或 JSONL。
5. 单消息 GET 查询被折叠的内部 ToolResult message ID 时返回 404；该 ID 从未属于 OpenCode v1
   用户可见消息，调用方应查询 assistant message ID。

这是 wire 兼容修复。普通文本会话的响应完全不变；工具会话从
`assistant(running tool), user(completed tool result)` 收敛为 `assistant(completed tool)`，与实时 SSE 一致。

## 6. 实现与数据流

`messages` 读取现有不可变快照后按顺序投影。私有 helper 记录已经输出的 assistant tool part，遇到
纯 ToolResult 消息时先验证全部 callID 均能命中，再原位更新对应 part 的 state 并跳过该 Core 消息。
helper 无 I/O、无锁、无持久化写入；`runtime` 仍是 session 唯一 owner。

Revert 仍按 Core message ID 计算可见前缀。例如历史为：

```text
user prompt -> assistant tool use -> user tool result -> assistant final text
```

对 final text 执行 Revert 后，Core 可见前缀仍包含前三项；REST 投影返回：

```text
user prompt -> assistant completed tool
```

因此页面能看到已完成的 assistant 结果，不会产生新的 admission recovery card。

## 8. 风险与回滚

主要兼容风险是依赖内部 ToolResult message ID 的非标准客户端。该 ID 不在实时 SSE 的可见消息序列中，
OpenWork 也不依赖它；对无法完整匹配的旧数据保留原投影可降低风险。折叠只作用于读取结果，不修改文件，
所以回滚只需恢复 Host 代码和文档，不涉及 session 数据迁移，也不会撤销已存在的 Revert 状态。
