## 2. 变更原因

用户在已启动Office中输入问题后，只得到“收到你的消息……尚未连接AI服务”。源码 `apps/web/src/chat/sources.ts` 明确在缺少 `VITE_PAWOFFICE_CHAT_URL` 时选择PreviewChatSource；当前隔离生产构建没有该地址。Host实际只提供GET /health，POST /office/chat已核实404；host.toml当前provider=echo。因此不是Office聊天组件缺陷，也不能仅设置URL就声称接通模型。

目标是master第1.4节步骤1—2：用户打开办公室，要求读取README.md和notes.txt得到实际内容，再追问；同一Run的文本、工具子任务、人物工作状态和白板一致。T4不做写工具、Office审批/六类详情、主动场景反馈和可靠长任务续接，分别交给T5和获批Rx/T6。也不修改Office预览文案来伪装AI，不用独立快照脚本冒充Run。

依据固定Office b221a44：S4 chat-integration.md的HTTP/历史/停止；S1 office-integration.md的通用约束、1/2/4节及恢复/错误；S2 dashboard-integration.md完整快照/人物规则；S3 message-relay.md生产Node与密钥；S5 chat.ts/office-integration.ts/dashboard.ts/office-ui.ts真实Schema。详见master第4、5、10节T4和14节M4。21份来源继续按sources.json核对，不自动升级Office。

复用T3已合入的Host/Session/Run/Approval/资源锁、AgentLoop、Provider装配和原JSONL，不增第二套后端。选择Host内适配；直接改Office或新增Node聊天Bridge会扩大授权和重复业务职责，均不采用。

## 9. 影响、数据流和实现

### 9.1 一次真实提问如何贯穿产品

~~~mermaid
sequenceDiagram
    participant B as Office浏览器
    participant H as Host聊天适配器
    participant S as 已有共享Run与JSONL
    participant E as 原AgentLoop与Provider/工具
    participant P as Host投影协调器
    participant F as Office Fastify
    B->>H: POST /office/chat，teamId+conversationId+messages
    H->>S: 核对来源/工作根/历史并可靠接受
    S->>E: 每Run独立执行
    E-->>H: 真实文本增量
    H-->>B: 合法status/delta
    E->>S: 工具提议、真实开始、结果、终态
    S-->>P: 通知提示；投影重取持久事实
    P->>S: 原子保存seq与完整内容
    P->>F: messages.office.snapshot
    F-->>B: Office自有SSE→任务/人物/白板
    F-->>P: applied/cached/ignored
    S-->>H: 终态已保存
    H-->>B: 非空成功done，否则error
~~~

Office业务“已连接”仅代表Fastify/SSE；不证明聊天配置或模型已接通。两个通道各自保存同步结果；Office失联不能重跑模型/工具，网络失败不回滚Run。T4只读，模型不能直接调用场景API改变完成状态。

### 9.2 聊天、历史与停止的实施细则

1. 新增可选office配置，不启用时仍只有原health。启用时检查明确的Office origin、地址/密钥引用、slots/names及只读白名单。默认四个办公室沿用slots；请求不能新增工作根。HTTP只绑定loopback，检查Host/Origin与JSON Content-Type；允许配置源的OPTIONS/POST，不开放`*`、不依赖Cookie或浏览器密钥。不把teamId视为认证。
2. 严格请求DTO/无null/未知字段拒绝；最近≤10轮完整历史、总历史≤100000 UTF-16单元；本次非空输入≤4000，最后必须user；ID≤100。HTTP body上限1MiB，覆盖合法最坏JSON转义，不能用messages的64KiB限制聊天。角色/交替顺序/长度异常400，大小413，越权403，忙或历史冲突409，满载503；开始输出后只发合法error，不再改HTTP状态。
3. `(namespace=office, teamId, conversationId)`映射原Session；首次合法历史只导入文本，并记录不可信来源。新增的共享接受缝隙复用原Store/JSONL，持久导入引用防止部分写入后再次导入；工具在导入和本次输入可靠接受后才启动。无turnId，不承诺用户重复请求幂等。失败/取消的助手内容不属于完整对话后缀；已有会话的浏览器历史必须匹配已完成展示历史的合法后缀，不能覆盖账本。压缩后用原SessionReader事实重建展示投影，不能按压缩消息长度推算。
4. 通过已有snapshot_and_subscribe得到一致视图；通知可合并/可能Lagged，重取真实Run并按已发文本偏移输出，验证前缀单调，不能重复追加。Run在释放实时缓冲后从已存消息读取的文本应与流一致；若审核发现通用缺陷，先在本单登记D及具体文件再实施。内部Thinking不展示，工具结果不直接串进聊天正文。
5. delta≤16000、序列化单行≤32000、回复≤50000 UTF-16单元；分片按Unicode边界并检查JSON转义后长度。错误≤1000且非空。空文本、提前断流、输出超限、账本/终态保存失败不发done。已输出文本后不自动重试整Run；同一用户追问可以再次问相同文字，不能用文本相等去重。
6. 浏览器停止、刷新、180秒超时断开触发Run取消，取消任务由Host持有并等待工具清理；不能让响应body被drop同时丢弃清理future。慢客户端有界队列和写入预算，溢出/断开取消该Run；不影响另一个Session。v1无续接游标，页面停止不代表已获得后端清理确认，保留此边界。
7. 原Provider装配保留。自动化确定性模型走真实AgentLoop/工具；用户配置真实模型另记验证。echo/mock仅作为明确测试模式，不把固定回复验收为AI理解或工具执行。

### 9.3 任务投影、版本与恢复

复用Store的bindings/runs、原JSONL和host_events中`tool_started`等真实生命周期；从现有事实读取工具状态/时间/结果，Office适配器不自己创建另一套运行状态。一个Run一个主任务，call派生工具子任务；主子关系留Host，不往strict Office任务塞parentId/runId。功能员工与场景人物分开；负责人office-lead，文件file-agent，检索data-agent，均先查询能力确认。未使用的功能不伪造工作，工具提议不是running，等待资源为blocked，真实开始才running，取消清理为blocked，失败/取消/中断为failed并说明区别，成功终态以可靠事实为准。

白板固定task-board-v1，最多3阶段；无可信百分比为-1，不按计时器制造进度，不展示内部推理。纯聊天无工具子任务。数组/字符串/带时区时间按S5严格验证；≤200员工/1000任务/500事件，精确计算完整请求UTF-8≤64KiB。裁剪按活动优先及有界近期任务，引用闭包和白板同步保留；原记录不删除。保留真实稳定task.assigned可由Office sceneBridge展示派发，但T5才验收完整主动发言/交接；T4不额外发送visit。

每办公室一个协调器，覆盖该办公室所有conversation；空闲历史仍可展示。当前列表上限24个近期Run及每Run12个工具，按活动优先/近期保留并继续按完整64KiB封套裁剪；详情完整记录仍留原账本。按持久事实revision稳定投影，首次观察状态时保存稳定展示时间/ID（不宣称模型给出实际耗时），不因每次poll生成新时间而不断增seq。新内容先事务保存seq+规范化完整JSON再外发；相同seq重试发送原内容，旧回执不能覆盖新版本。达到JS安全整数上限拒绝并诊断。

启动：恢复Host→capabilities核对→以本地保存版本initialize完整办公室→read核对；只查health不表示Office页面ready。单请求超时超过Office默认10秒并留传输余量；网络/503有界指数退避和关闭可取消，401/协议异常明确诊断。202仅cached，200按操作验证applied/ignored；SEQ_CONFLICT停止该办公室投递并诊断，不盲目seq+1遮蔽冲突。404未初始化时重新initialize；Office重启目录清空后，以本地版本恢复，不重放Run或动画。Office不可用时依旧提供真实聊天，但明确业务展示待同步，最终验收必须恢复后核对一致。

Host元数据以事务v1→v2迁移，JSONL格式沿用原实现；未知未来版本拒绝写入。禁止启动时drop重建数据库。关闭顺序延展现有shutdown：拒新→取消并等实际清理→保存最终完整投影及有限投递→停止worker→关Store/监听器；网络不可用不能无限阻止关闭，已保存待同步内容供下次恢复。旧Host::shutdown入口保留，不要求非Office调用方管理投影。

### 9.4 不改Office源码的部署和用户配置

Office原源码只读；从冻结git对象复制到隔离运行目录，安装其锁文件、用原`npm run build:full`构建，**在构建前**注入公开`VITE_PAWOFFICE_CHAT_URL=http://127.0.0.1:<Host端口>/office/chat`。Host允许实际Office origin；生产优先同源代理，外部代理示例写说明，不改Fastify/前端。随机端口发现后再构建或由同源代理固定公开路径；不能构建完成后只修改环境变量就期待静态JS变化。模型密钥和Office服务密钥不进VITE_*。

优先复用r2原生.env模型配置，Host省略provider/model/base_url/api_key_env即可；模型和Office服务凭据分离。下面仍是可选的显式TOML覆盖方式（顶层字段必须在`[roots]`/`[slots]`之前）：

~~~toml
home = "/绝对路径/openpaw-data"
provider = "openai"
model = "服务商实际支持的模型名"
base_url = "https://api.openai.com/v1"
api_key_env = "OPENPAW_MODEL_API_KEY"
tools = ["read_file", "glob", "grep", "todo_list", "think"]
[roots]
project = "/绝对路径/授权项目目录"
[slots]
office-1 = "project"
~~~

OpenAI兼容服务的base_url填其API根，不能填完整`/chat/completions`；原Provider会追加该路径。Anthropic用provider="anthropic"及相应模型/API根，原Provider追加/v1/messages路径（API根不要包含重复的/v1）。密钥通过启动Host的同一个shell注入：Bash可`read -rsp '模型API Key: ' OPENPAW_MODEL_API_KEY`后换行并`export OPENPAW_MODEL_API_KEY`，不回显、不把密钥写命令历史。Windows PowerShell可由安全交互输入设置进程环境变量，不要求WSL。不要把密钥直接发会话。

**office段随本修订实现后才可加入配置**，否则旧版deny_unknown_fields会拒绝；获批实现后才可用。字段为base_url（Office服务根）、api_key_env（Office密钥变量名）、allowed_origins（精确页面源列表）、names（已配置office槽到≤80字符名称）。现有默认echo配置仅能测试底座，改模型不能让尚不存在的/office/chat变出来。

自动化runner使用Office隔离副本锁定的Playwright包和独立浏览器profile，不读取用户浏览器cookies。启动/终止通过Node跨平台子进程API，所有路径用参数数组，中文/空格可用，不依赖bash/PowerShell执行产品流程。Linux/Windows原生Node路径一致，Windows支持仍为目标；当前无环境如实待验，T3暂缓不自动成为T4批准。

首次历史导入标记仅存事件偏移/数量/FNV诊断校验和/完成位；校验和不是认证或防碰撞凭证，已提交前缀必须逐条比较原文本。工具展示ID使用host_office_calls持久唯一配对，不按callId截断或排序位置分配。SEQ_CONFLICT/STALE_SEQ、认证或协议错误持久halted，关闭与重启不得自动解除。

### 9.5 已完成的统一模型配置（合并r2）

r2原方案： 影响、数据流和实现

#### 文件选择和覆盖

默认读取openpaw_core::openpaw_home()/.env，即OPENPAW_HOME/.env或用户目录/.openpaw/.env，不向上查找项目.env。全局--env-file显式指定优先，路径支持中文/空格与Windows原生路径；显式缺失/不可读/格式错误返回非零。默认文件缺失兼容旧行为，默认文件存在但错误必须报错。chat --home只选择会话存储，不改变默认配置路径。

参数优先级：显式CLI模型参数或Host TOML明确字段 > 系统环境 > .env > 原入口默认值（CLI mock，Host echo）。model/base_url缺省仍沿用原Provider规则。系统环境的空值保留并在使用时拒绝，不悄悄退回文件秘密；显式选mock/echo无需网络密钥。Host旧TOML里provider='echo'是明确值，不能被.env覆盖；沿用.env需省略该字段。api_key_env显式指定时仍使用该名称，未指定则按有效Provider选择标准密钥名。

新增openpaw-llm::model_config作协议无关的共用装配配置模块；使用dotenvy的只读迭代解析，不调用dotenv()/set_var、不向进程环境注入文件字段。环境值优先于文件值，来源可诊断；秘密容器不派生Debug。文件解析错误只报告位置/类别，不格式化库原始错误，防止原始行泄露。缺失/错误不创建配置或数据文件。

chat复用原assemble_provider及原运行流程；Host CLI复用HostConfig校验、assemble_provider和Host::with_provider，不复制运行/权限/存储。HostConfig原load与Host::start保留原有语义，嵌入式Rust使用者通过新增回退方法显式选择。配置诊断不建连，URL先校验再显示。dotenv读取的密钥只传Provider，不进入工具子进程；已有系统环境的处理不借本轮扩大权限。
