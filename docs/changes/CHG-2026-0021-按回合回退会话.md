# CHG-2026-0021：按回合回退会话

## 先说结论

本变更把 OpenPaw 的 assistant 消息回退边界规范化为同一回合的 user 消息边界，使 OpenWork
在 assistant 回复下点击 Revert 时，同时隐藏该轮用户输入、助手输出以及后续历史。用户消息边界、
Unrevert、下一条 prompt 提交回退、工作区文件和工具副作用语义保持不变。

后续 Restore 实机复验发现 OpenPaw 在 staged revert 时裁剪了对外 `message_cache`，而 OpenCode
保留完整消息并只用 `session.revert.messageID` 控制可见性。OpenWork 按 OpenCode 语义保留 snapshot，
清除游标后直接从该 snapshot 恢复 transcript。修复因此继续限定在 OpenPaw：staged revert 的
`GET /message` 保留完整历史，默认 Branch 和 replacement prompt 仍只使用游标之前的可见前缀。

OpenWork 主线已经接受 OpenCode 返回的权威 `revert.messageID`，无需修改业务代码。当前本地
`merge/openpaw-deployment` 分支额外增加的“返回游标必须等于请求游标”检查与 OpenCode
`v1.18.18` 的原生规范化行为冲突；运行环境恢复到干净的 OpenWork `main` 后，本变更只修改
OpenPaw，并使用未修改的 OpenWork 主线完成页面验收。

**当前裁决：用户已批准实施（approved），实现与本地验收已通过，CODEOWNER 发布审核尚未执行。**
批准范围仅限第 3 节登记的 OpenPaw 文件，不代表合并或发布批准。

## 2. 缺陷与根因

OpenWork 的 assistant 回复操作栏把被点击的 assistant `messageID` 直接发送给
`POST /session/:id/revert`。OpenPaw 当前把请求游标原样保存，并按“边界消息及其尾部隐藏”裁剪，
因此 assistant 边界只隐藏助手输出，触发该回合的用户输入仍然可见。

OpenPaw 已为每个回合保存 `TurnOutcome.turn_id` 与 `TurnOutcome.user_message_id`，assistant 消息也使用
`msg_<session>_<turn>_assistant[_n]` 的稳定编号。Host 可以用这两项现有事实把本 Host 生成的 assistant
边界可靠地关联到用户输入，无需修改 Core Message、JSONL 事件格式或 OpenWork 的消息组件。

OpenWork 主线的 `revertSession` 直接接受服务端响应，与 OpenCode `v1.18.18` 一致。当前本地
`merge/openpaw-deployment` 分支的提交 `343671a` 为识别早期 OpenPaw no-op 降级，增加了返回游标
必须等于请求值的检查；该检查会拒绝 OpenCode 正常返回的 user 游标，属于部署兼容分支的回归，
不是 OpenWork 主线行为。验收环境切回主线即可，不在本 CHG 中继续维护这项分支补丁。

## 4. 明确禁止范围

- 不修改 `crates/openpaw-core/**`、`protocol.rs`、`http.rs`、`events.rs`、AgentLoop、Store、依赖、
  Compose、Schema 或 JSONL 事件格式。
- 不修改 OpenWork 的 `apps/**`、`packages/**`、`ee/**`、测试、消息列表、React session route、
  transcript reconcile、SDK、状态管理或 UI 文案；OpenWork 以 `origin/main` 原样参与验收。
- 不把 Revert 扩展为工作区文件、工具副作用或外部系统操作的回滚。
- 不改变 Fork、Archive、Rename、partID 拒绝、活动会话 409 或 Unrevert 的对外行为；Fork 内部必须
  显式应用 staged revert 游标，不能把完整 snapshot 中的隐藏尾部复制到新分支。
- 不依赖词典序比较 messageID，不把无法可靠关联的旧 assistant ID 猜测为某个 user 回合。

## 5. API 与兼容规则

`POST /session/:id/revert` 的路由、请求体、状态码和响应结构不变。`revert.messageID` 仍表示
“第一条被隐藏的消息”，增加以下边界规范化规则：

1. 请求命中可见 user 消息时，游标和现有行为完全不变。
2. 请求命中可见 assistant 消息，且其稳定 ID 能关联到当前 session 的一个 `TurnOutcome.turn_id`，
   同时该 outcome 的 `user_message_id` 仍可见时，Host 以该 user ID 作为权威游标。
3. 同一工具循环产生的 `assistant`、`assistant_1` 等消息都规范化到同一个 user 游标。
4. 请求命中 assistant 消息但缺少可靠 outcome 关联时，保留原 assistant 游标，兼容旧数据和外部写入。
5. 请求 ID 不存在、已经隐藏或为空时，仍返回现有 400；`partID` 仍返回
   `unsupported_part_revert`；活动会话仍返回 409。
6. Host 持久化并在 REST/SSE 中返回规范化后的游标。重启、Unrevert 和下一条 prompt 提交都使用
   同一权威游标，不保存请求 assistant ID 的第二份状态。
7. staged revert 期间 `GET /session/:id/message` 继续返回完整消息历史，与 OpenCode 一致；客户端使用
   `revert.messageID` 计算可见前缀。Unrevert 只清除游标即可恢复显示，无需服务端重放消息事件。

OpenWork 主线的 `revertSession` 已直接返回服务端 Session；返回游标可以与请求值不同，并继续传给
现有 `applySessionRevert`。本变更不复制或改写这段客户端行为。

## 6. 实现与数据流

`AppState::revert_session` 已在 `turn_gate` 内读取不可变的可见消息快照。新增私有纯 helper 同时读取
回合结果快照：先确认请求消息可见；user 边界直接返回；assistant 边界只接受当前 session、完整
turn ID 和 `assistant`/`assistant_<数字>` 后缀的精确匹配，再验证 outcome 的 user 消息仍位于可见历史。
任何一步不能证明关联时使用原 assistant 边界。

Host 只把最终权威游标写入现有 `session_revert_staged_v1.messageID`，`Session` 和 `message_cache`
继续保留完整历史。冷启动恢复同样先验证游标存在，再发布完整 snapshot。默认 Branch 在复制前显式
应用游标；下一条 prompt 仍由现有 `session_revert_committed_v1` 事务原子裁剪尾部。因此无需新增事件、
协议字段或迁移旧 session。

未修改的 OpenWork 主线收到响应后沿用现有调用链：`upsertLocalSession` / `applySessionRevert` 读取
响应游标并从该消息开始裁剪本地 transcript。页面不必等待下一次 snapshot，就能同时隐藏 user
和 assistant。

## 8. 风险、替代方案与回滚

主要风险是完整 staged snapshot 被错误用于 Branch 或 replacement prompt。本方案让消息查询保留完整
历史，但默认 Branch 单独应用游标，replacement prompt 继续在持久化提交事务内裁剪。测试覆盖页面
可见性、默认 Branch、重启、Unrevert、replacement prompt、多 assistant 工具循环和无 outcome 旧数据。

在 OpenWork 消息组件中向前寻找 user ID 会复制服务端回合知识，并不能处理刷新、其他客户端或直接
API 调用。OpenCode 已证明正确边界属于服务端职责，因此选择只在 OpenPaw Host 规范化；本地
OpenWork 工作区恢复主线，避免把部署分支的严格同值检查继续当作产品合同。

回滚时恢复两仓登记代码与文档即可。新增事件、Schema 和数据迁移均不存在；已经持久化的规范化 user
游标本来就是现有协议接受的合法边界，旧版本仍可读取、Unrevert 或提交。
