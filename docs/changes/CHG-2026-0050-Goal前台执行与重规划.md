## 2. 行为、分层和数据流

主聊天文本进入既有 Host 入口，解析 /goal 创建与 continue；普通聊天保持原语义。由主 Agent 生成可验收的 Task 及依赖，初始计划确认后在原会话执行。Host 维护 Goal 身份、当前计划、历史、执行授权与验收事实；任务工具所有更新先校验、通过既有 journal 提交，再更新可见状态和 Office 投影。

Agent 可在既定目标内重规划，普通失败不直接终结 Goal。任务执行阻塞采用模型判断、原因非空和状态／归属校验；人工阻塞只能由明确用户控制解除，不由执行轮次或普通 continue 清除。自然语言控制由实际用户回合及模型结构化工具更新表达，绑定该回合身份，不能由 Agent 自己构造“用户消息”解除限制。

所有工作复用同一前台执行和原有预算、审批、取消、并发额度与 180 秒期限。Engine 只增加可选的中立 EndTurn 续行闭包：Host 判断仍有可执行工作时提供继续提示，Engine 在同一 run_turn 内继续消耗原预算；默认无闭包时行为不变。不能外层循环反复 begin_turn 重置预算，不增加后台 driver。

现有普通主聊天观察流断开不取消执行；本次只对正在观察活动 Goal 原回合的流增加按 turn 身份限定的取消清理，避免迟到断开取消新回合。停止、异常、重启后保留状态但不继承执行授权。恢复前核对实际结果；持久状态不承诺自动撤销在途工具副作用。

Office 投影只展示事实，失败不能改变 AgentLoop 结果。Goal 的任务验收与真实子 Agent 的执行结果分开：子 Agent 返回并不自动验收任务。主 Agent 统一维护计划和整体验收。

## 5. 公共接口与兼容策略

- 不新增聊天端点；沿用已有 send／history／resume／cancel 主聊天接口。斜杠命令在 Host 解释。
- Office conversation／dashboard 的可选 goal 摘要包含稳定 id、phase、planVersion、acceptedTaskCount、taskCount、progress 及简短 reason；阶段为 draft／active／paused／blocked／completed／ended，未知进度沿用 -1。
- 任务可选 goalId 明确归属；复杂预期结果、验收、依赖、原因及依据通过现有任务 summary 与完整聊天计划表达，不能截断原始持久事实。白板只投影一行整体验收任务计数，任务列表展示所有当前任务，不套用演示专用三阶段分组。
- 白板可选 progressMode 选 reported 时展示精确比例；未提供字段仍走旧 activity。任务比例 100% 与 Goal completed 是独立事实。
- 委派可选 goal_task_id 与既有表示子会话的 task_id 分开，不改变原 task_id 的含义；运行时校验该 Goal Task 在当前计划内可执行。
- Goal 持久事实通过现有 SessionEvent 可扩展事件承载；由 runtime 协调既有 journal 写入，重载后执行授权关闭。旧会话没有 Goal 事件时保持现有行为，不迁移或共享工作目录 Todo。
- 新旧 producer／receiver 版本需配套测试；严格旧版 receiver 不保证识别新增字段，本次不部署或切换运行服务。

## 6. 禁止修改范围及原因

| 禁止范围 | 原因 |
| --- | --- |
| Core 公共 trait、Store 及 session journal 事务实现 | 既有通用能力足够承载事件和会话，Goal 规则留在 Host；避免扩张中立内核及数据格式。 |
| Goal ledger、CLI Goal 产品功能 | 本次为主聊天前台功能，既有 ledger 不承担后台续跑或重规划驱动。 |
| Cargo.toml、Cargo.lock、前端依赖清单及 lock、CI | 不需引入依赖、修改默认 feature 或构建发布环境。 |
| Host 通用 approval、OpenCode protocol／events、旧聊天断开行为 | 复用既有权限与消息协议，不扩大权限或改变其他消费者。 |
| 其他前端源文件、图片／美术／布局、Gateway 新服务 | 复用现有交互与可选 schema，不新增面板或部署服务。 |
| 已运行容器、预览部署、凭据和真实用户数据 | 本轮为隔离工作树内实施和测试，不切换用户运行环境。 |
| 行数门禁与其他工程门禁规则 | 按现有规则测量，不通过压低验证或暗中提高阈值宣称通过；若确需增加范围，先提交实测与独立范围说明。 |

## 7. 替代方案

不采用全局 Todo 文件作为聊天 Goal 状态，因为共用目录会串用计划；不采用外层反复启动 AgentLoop，因为会重置预算；不采用后台 driver，因为用户选择前台和显式继续；不新增阻塞分类器或强制尝试轮数，因为用户明确选择简化模型判断；不全局关闭普通白板动画，因为只需 Goal 展示真实验收进度。
