## 接口与实现

新增 POST /api/pawoffice/chat，直接由 Host 处理原版页面的 send/history/resume/cancel，沿用 Basic 鉴权；旧 /api/chat 保持不变。原版 gateway 静态页面、SSE、reply、ui 仍经既有代理；15180 为完整入口，25180 仍只是 gateway 调试入口。请求和返回遵循最新 packages/protocol/src/chat.ts。

turnId 复用既有 messageID/requestID 和接收记录；同 ID 只观察旧执行，变更正文拒绝。历史从原会话消息和执行结果读取，游标使用真实消息 ID；resume 首条为 snapshot，不重新运行；断开观察不取消，cancel 取消对应执行并确认终态。订阅输出当前已提交消息/执行事实，不伪造尚未保存的文本。Host 重启沿用既有故障恢复，不承诺丢失前仍在网络中的文字。保持每办公室一个已绑定主对话，其他本地主对话仍明确拒绝发送。

通过 office.capabilities 的 requests 识别 conversations；仅转换出站快照，不改 registry 格式。绑定后的 conversation 包含原员工、任务、事件、白板；未绑定时目录为空。动作和审批附加真实 conversationId，UI 操作核对会话归属；旧 gateway 保持旧协议。无 main 创建入口时，不注入页面或脚本，不冒充按钮已交付。
