# CHG-2026-0012：回合失败终态与会话并发队列

## 先说结论

本变更为不同 session 提供默认 4 个活动回合和最多 32 个 FIFO 等待回合，并把 queued、running、completed、failed、cancelled 终态持久化到 JSONL。它新增只读 turns 接口和 429 队满语义，使失败、取消和 Host 重启后均可恢复，不再由客户端根据“没有 assistant 文本”猜测结果。实现和测试代码已存在，但当前候选工作树的完整复测、独立 PR、CODEOWNER 审核和正式基线批准仍未完成。

## 2. 变更原因

不同 session 原可直接 spawn，但没有进程级容量、排队和背压。Provider 失败、取消或 Host 异常只留下 user 消息，空状态无法区分成功、失败和从未运行。客户端只能等待固定时间后猜测失败，切换或重启后提示丢失，并可能把上游拥塞误判为新会话永久损坏。需要由 Host 提供唯一的调度和持久终态事实源。

## 9. 影响、数据流和实现

### 影响分析

不同 session 可并行但受全局上限约束，同 session 仍只有一个活动回合。默认并发 4、等待 32，可由环境变量在规定范围内调整。队满在写 user 前返回 429，避免产生无终态半轮。调度器使用同步互斥锁线性化接收、取消和晋升，锁内不执行模型或文件 I/O。JSONL 增加未知事件，旧读取者可忽略。失败正文由消费端决定，原始错误只进入受控日志。

### 数据流和失败路径

```text
POST prompt_async
  -> validate session/provider/body
  -> same session active? 409
  -> scheduler capacity available? reserve running : enqueue FIFO
  -> queue full? 429 before user write
  -> append user + queued/running turn_outcome
  -> AgentLoop executes when permit available
       -> completed / failed / cancelled
  -> append terminal turn_outcome
  -> release permit and promote next FIFO item

Host startup
  -> scan session JSONL
  -> fold latest outcome per turn
  -> queued/running without terminal -> append failed(host_restarted)
  -> GET /session/:id/turns exposes recovered facts
```

queued abort 必须从队列移除且不调用 Provider。panic、Provider 错误和持久化失败都必须释放 permit；持久化失败不得伪装 completed。

### 实现方案和选择理由

采用进程内 FIFO 和 RAII permit，因为当前 Host 是单进程本地服务，能在不引入数据库或消息中间件的前提下提供确定背压。终态作为 session JSONL 的未知事件追加，复用唯一写入路径并保持旧客户端兼容。没有把失败文本写成 assistant 消息，避免错误进入下一轮模型上下文；Gateway 可按 turns 契约将脱敏失败投影到对话正文。
