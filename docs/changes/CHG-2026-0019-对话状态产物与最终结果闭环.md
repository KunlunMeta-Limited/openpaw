## 2. 变更原因

真实运行数据证明三个问题彼此相关但不应混成动画 v2：

1. Host 动作带有 `sessionId/workspaceId`，Gateway `/office/workspaces?sessionId=...` 也保存了六人活动，但首页和“智能体”面板仍优先读取无会话作用域的 `/office/agents`；只有 desk-visit mission 存在时才短暂覆盖场景快照，因此普通 thinking/working 活动会显示为空闲。
2. `.js` 已被产物扫描发现，但被归类为 `other/application/octet-stream`，没有明确的脚本类型和只读代码预览验收；用户无法确认它是可查看源码还是不支持文件。
3. Gateway 把 completed marker 插在第一个空工具 user 消息之前，Controller 又允许 completed marker 独立结束监视。若最终消息和 marker 投影不同步，监视器会用旧消息快照结束并拒绝迟到 REST 对账。工具循环的多个 assistant 过程正文同时作为普通回复展示；OpenPaw attached 提示也没有禁止工具阶段过程播报或要求最终产物清单，真实记录因此可能以“正在检查……”结束。
4. 新现场会话 `afc86a27fc06436893f37de0c5882099` 证明 AgentLoop 的迭代预算在最后一个工具结果后耗尽时直接返回 `EndTurn`，Host 随即提交 completed；最后一条 assistant 仍是 `tool_use`，不存在无工具最终正文。提示词无法修复该状态机缺口。
5. 文件中心当前只展示全局扫描结果，无法证明文件属于哪次对话；会话产物接口对主空间能从 transcript 重建，但无 workspace 参数时不会合并已登记的子 Agent 产物。JavaScript 也只有源码文本，没有语法解析和结构摘要。
6. 主空间产物扫描把 transcript 中所有成功写入都当成交付物，又在未指定 workspace 时合并子空间登记文件，导致 `.py/.mjs` 等子 Agent 过程文件污染“我的空间”；扩展名不能可靠区分过程文件与最终交付物，必须以最终答复明确列出的真实相对路径为准。
7. `delegate_task.name` 和已持久化的 `workspace_name` 可直接使用英文 slug，导致子 Agent/其他空间出现英文名；只改提示词无法约束历史数据或模型偶发错误，Host 必须在创建和恢复时归一化中文展示名。

## 6. API 变化

不新增 HTTP 路由，不改变现有请求或响应字段。`GET /office/workspaces?sessionId=` 继续作为选中会话的空间状态来源；`GET /office/agents` 保留 legacy 兼容。`GET /office/conversations/:id/messages` 仍返回相同白名单结构，只删除无可见文本的工具脚手架消息并修正 completed marker 顺序。`GET /office/conversations/:id/artifacts` 无 workspace 参数或指定主空间时，只返回主 Agent 最终答复明确列出且实际存在的交付文件；候选文件可来自主 Agent 成功文件工具或子空间成功登记，但未被最终答复列出的子空间过程文件不合并。指定子 workspace 时只返回该子空间登记的文件。

## 7. 字段变化

无线协议字段变化。`.js/.mjs/.cjs` MIME 从 `application/octet-stream` 收敛为 `text/javascript; charset=utf-8`，`.ts/.tsx` 为 `text/typescript; charset=utf-8`，`.jsx` 为 `text/jsx; charset=utf-8`；产物 `kind` 复用现有 `text`，不扩展公共联合类型。

## 9. 数据流、实现和替代方案

```text
Host AgentEvent(session A)
  -> Gateway session A / workspace A 六人快照
  -> App 当前 selectedSession=A
  -> 首页和智能体面板显示 A 的 thinking/working/idle

SSE assistant delta
  -> 当前 generation 的临时最后答复
session.idle / completed marker
  -> 最终 REST messages 对账
  -> marker 放在该回合所有可见 assistant 之后
  -> 同 generation 的最终正文落地后结束 pending
  -> 旧的中间 assistant 正文折叠为“执行过程”，最后正文作为结果

write/edit 产物登记
  -> Gateway 扩展名白名单
  -> 会话文件夹按 conversationArtifacts 因果记录组织
  -> 主空间仅保留每回合最终答复明确列出的真实交付路径（含被主 Agent 明确提升的子空间文件）
  -> 子空间仅展示对应子 Agent 的成功登记文件，不跨空间合并
  -> Acorn 静态解析 JS/MJS/CJS 并显示结构摘要和语法错误
  -> TS/TSX/JSX 明确只读源码
  -> 永不执行产物脚本

delegate_task 创建或恢复
  -> 原始 name 继续生成稳定 logical_key/workspaceId
  -> 中文名称保持不变
  -> 纯英文名称按任务职责确定性映射为中文展示名
  -> 旧持久化英文 workspace_name 在加载时同步归一化

AgentLoop 工具循环
  -> 正确消费 min 到 max 的迭代预算及 grace
  -> 耗尽且最后响应仍为 tool_use
  -> 使用相同上下文、空 tools 和强制总结 system 指令再调用一次模型
  -> 只有非空文本可提交 completed；否则返回 Provider 错误并由 Host 记录 failed
```

选择现有 `/office/workspaces` 快照而不是给 `/office/agents` 增加 query，是因为 App 已按 selected session 每 1.2 秒读取同一数据，复用它可避免第二条轮询和两份状态源。选择 UI 折叠中间正文而不是删除 Host 历史，是因为历史记录仍需诊断；Gateway 只删除没有可见文本的工具脚手架。选择 attached 系统提示约束最终格式，而不是在 Gateway 编造结论或按 mtime 猜产物，是因为只有模型和已登记产物知道业务语义与因果归属。
