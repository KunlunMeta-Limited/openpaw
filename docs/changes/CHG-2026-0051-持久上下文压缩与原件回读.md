## 4. 原件与 Goal 模型接口

### 工具结果

1. 继续先调用可靠ExecutionRecorder保存系统实际收到的完整ToolCallOutcome，再生成模型
   ToolResult预览。真实generated、媒体原件、结构化outcome及公开历史不以预览替换。
2. 新增只读工具 `read_context_record`，参数为 `reference`、`start`、`limit`。
   start/limit按Unicode标量字符计数，拒绝负数、越界和超限；输出含reference、kind、content、
   start/end、total_chars、total_bytes、is_error、has_more/next_start。空正文范围明确。
3. 引用是版本化会话记录标识，由会话身份及已登记的稳定记录身份构成。工具记录身份包含
   原turn和对应响应/调用，不能仅用供应商可重复的call_id，也不使用任意文件路径。
   已接收的完整正文是原件，不能用重跑工具补齐。参数及引用格式随实现记录在此处。
4. 预览初始上限6000字符且不超过24KiB UTF-8；回读默认/上限4096字符且不超过16KiB。
   实际模型窗口更小时进一步下调；提示、引用和元数据计入上限与请求总预算。
   长中文、英文和无换行文本同样受控，分页边界不会切坏UTF-8。
5. 回调从当前会话可见历史及可靠事实取原件，禁止借共用工作目录访问其他主/子会话。
   原件无效、隐藏、跨会话或缺失明确报错；媒体继续使用既有read_attachment。
   分支从实际继承记录重建目标会话引用，不能接受来源会话任意引用。

### Goal

prompt、goal_read和成功goal_update使用同一精简模型视图，包含目标、版本、phase、当前
完整任务定义、依赖、状态、验收条件、人工来源及必要依据引用；历史计划、执行尝试和
观察正文改为数量/简短摘要/稳定引用。更新返回实际变更与必要当前状态。
观察正文通过上述只读入口及Goal原件解析能力分页回读。若需要扩展GoalRuntime，限于
当前会话原件只读解析接口，不包含授权、writer或AgentLoop类型，仍须完整中文Rustdoc。
current()、session_goal_state_v1及Office完整只读投影保留原事实，不因模型精简改变验收。
必需计划本身装不下时返回固定输入过大，不能静默删除任务或用户约束。

## 5. 执行、预算与命令

每次业务请求前计算system、序列化后的完整工具定义（名称/描述/schema等）、全部消息、
调用参数、结果与媒体，采用当前实际模型窗口，并保留max_tokens输出和估算余量。
本轮初始策略：误差预留max(1024,窗口5%)；可用输入额度扣除输出及余量后，80%触发
提前整理，100%为发送硬限；固定必需输入不能容纳则明确失败。估算不是精确计费。
若实测需要调整默认值，在实施记录说明依据，不沿用参考项目的magic number。

不再把整个generated设为保留尾部；只在本批工具结算后整理，切点保持call/result完整。
真实最新用户意图与必要近期内容保留，摘要文字不参与可信命令识别或Goal授权。
摘要输入独立预算：最多32000估算token且须满足实际窗口减输出/余量，输出最多2048；
必要时有限缩减可回读旧细节，最多3级确定性降载，不循环反复摘要直到成功。
摘要应涵盖目标、约束、决定、完成/执行/待做/阻塞、失败、下一步与原件引用；禁用业务
工具。空白、截断或未完整结束拒绝安装，摘要请求usage计入原有用量及适用token预算。

自动整理在原run_turn中继续，不重置迭代、token预算、权限或取消令牌。摘要等待必须可取消。
原生ContextTooLong仅在当前逻辑请求尚未产生不可安全回放输出时允许一次强制整理、
重新预检和重试；不重新执行已经结束的工具，也不通过网络重试刷新该一次恢复额度。
第二次拒绝、固定输入超限或摘要失败明确终止并保留可靠事实及原Goal暂停语义。

可信主用户输入准确的 `/compact` 时由runtime确定性分派到同一压缩核心；仍经过原来的
admission/幂等/忙碌闸门，不新增控制队列。不从子委派、工具结果或摘要识别用户命令。
无可整理内容显示“无需整理”，成功/失败/处理中走既有聊天文本或状态，不暴露完整摘要
到Office动作或日志。手动整理不调用Goal.begin授予执行、不恢复paused/blocked Goal。

## 6. 持久化、可见性与兼容

新增私有版本事件 `model_context_checkpoint_v1`，采用SessionEvent::Unknown兼容载体；
Core只提供中立数据类型。至少包含会话身份、版本、provider/model、源历史稳定边界及
校验值、替代模型消息/必要尾部、生成元数据。源覆盖必须由已可靠保存且仍可见的记录解释。
不把摘要保存成真实用户或工具产出，不覆盖原始transcript、Goal或execution_attempt_v1。

候选检查点在回合内可供后续模型使用，但持久发布须在生成消息稳定ID映射之后，与对应
成功产出在同一追加事务中提交；恢复只认完整提交。错误、取消、丢弃future、半写入及
提交失败不使依赖未提交产出的候选成为最新有效检查点，原RestoreGuard一起恢复模型状态。
CLI的完整消息追加同样不能把无效候选独立发布。先记录原件不等于允许提交未完成摘要。

加载从适用检查点及其后可见原始记录恢复。回退/取消回退/提交回退、fork以及模型变化
均重新校验覆盖及身份；失效从当前可见原件重建，禁止继续使用包含隐藏内容的摘要。
分支默认不直接复制来源摘要，改由继承的完整可见记录建立自己的模型上下文和引用。
旧会话无检查点时可正常加载，先建立有界模型视图；不要求清空历史或删除数据。
服务重启只恢复状态，不恢复执行许可、不重跑工具或自动继续Goal。

老reader忽略新事件时仍能看到完整已提交原件，但会失去持久压缩能力并可能再次超限；
不能以此宣称旧版本具备新能力。既有committed-revert兼容要求不变。
