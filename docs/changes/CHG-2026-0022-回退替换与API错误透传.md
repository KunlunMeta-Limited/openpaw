# CHG-2026-0022：回退替换与 API 错误透传

本变更修复 OpenPaw attached OpenWork 的三个已复现问题：回退后重发会短暂恢复旧历史、
上游 API 失败只显示 accepted/no-result、已发送的输入直到输出结束才出现。
修复位于 OpenPaw Host；OpenWork 业务代码保持原样，只允许修改本文件登记的测试代码。

**当前状态：已批准（approved），已完成修复与核心功能验证，发布门禁未通过。** 用户于当前会话回复“OK 开始干活”，批准本 CHG 的设计与范围。

## 2. 缺陷事实与根因

诊断证据位于工作区 `artifacts/revert-api-error-audit/report.md`、`evidence.json` 和 `probe.ts`。
证据使用复制的部署程序、隔离 home/workspace、本地模拟 provider 和真实 HTTP/SSE，

| 问题 | 实际观测 | 根因与现有消费者能力 |
| --- | --- | --- |
| revert 后替换，旧消息重现 | 后端正确保持 4 条消息；旧 snapshot 渲染 6 条，刷新 snapshot 后恢复 4 条；流程未调用 unrevert | Host 只清游标，未发 `message.removed`；OpenWork 已支持同时移除 transcript 与 snapshot 的消息 |

## 5. 推荐语义与兼容契约

### 5.1 Revert 后接收替换

保留现有 `session_revert_committed_v1`：裁剪旧尾部与接收新 user 在同一 append-only 事务中生效。
在写盘与内存投影成功之后，按提交前后共享 wire 消息投影的 ID 差集发布删除事件：

```text
durable revert commit + new user admission
message.removed(old public message IDs)...
session.updated(revert cleared)
message.updated(new user)
message.part.updated(new user text)
session.status(busy / existing queued semantics)
assistant events...
```

`message.removed.properties` 为 `{sessionID,messageID}`。ID 必须属于提交前公共消息投影；
已折叠的内部 ToolResult 不被当作独立 UI 消息。旧数据的 fallback ID 与 REST 一致。
无输出失败的展示 assistant ID 也参与差集，避免刷新或 snapshot 合并恢复旧错误。
回退提交按真实 user 边界裁剪对应私有错误元数据，staged revert 则仍保留完整历史。

接收拒绝、append 失败、requestID 重放不发布新删除、用户正文或执行事件。
接收失败保留 staged revert 与原历史；收到 204 后替换已经提交，即使模型随后失败也保留新输入，
不能借模型失败恢复已撤销历史。Unrevert 只在尚未提交时恢复旧历史，沿用既有规则。

### 5.2 已发送输入

接收持久化成功后、启动后台任务前，发布完整 text part，ID 为 REST 的 `prt_<userMessageID>_0`。
正文是既有请求文本拼接结果；不重放用户输入、不把文本写入额外日志。
事件必须先于任何 assistant 输出；幂等重放不再创建消息或正文。

### 5.3 API 失败实时与刷新恢复

保留 admission HTTP 204 与后台失败的区别。模型执行最终失败时使用现有 OpenCode 错误形状：

```json
{
  "name": "APIError",
  "data": {
    "message": "模型服务当前负载过高，请稍后重试。 HTTP 503：service temporarily unavailable",
    "statusCode": 503,
    "providerID": "openai",
    "code": "provider_overloaded",
    "isRetryable": true
  }
}
```

`message`、`code`、`isRetryable` 为必要字段；`statusCode` 和 `providerID` 仅在可靠可知时出现。
缺少结构化 HTTP 状态时不编造状态码。普通 Host 执行失败使用 `UnknownError` 和既有安全说明。
取消保持 cancelled，不能伪装成 provider APIError；重试期间沿用引擎，最终失败才发布错误。

成功保存 failed 终态与安全元数据之后，发布该回合 assistant `message.updated`，
再发 `session.error.properties={sessionID,error}`，最后发 idle。assistant header 即使没有文本输出
也必须存在，让 OpenWork 将实时错误绑定到本回合，避免错误挂到前一轮或按 session 重复。
相同安全 error 投影到消息查询中的 assistant `info.error`；详情在刷新、断线恢复和 Host 重启后仍可读。
输入、部分已提交工具输出及失败展示保持顺序，不把无结果的失败伪造为成功正文。

### 5.4 安全详情边界

公开内容仅包含 HTTP 状态、实际 provider 的稳定名称、既有错误分类码、retryable 与有界安全说明。
上游说明仅从已保留的 HTTP 错误摘要中提取白名单字段 `error.message` / `message`，
或处理无 JSON 结构的短说明；最长 300 个 Unicode 字符。损坏、无法安全处理或超界结构使用安全分类说明。
不能传完整响应 JSON、响应头、URL、请求体、完整 Prompt、路径、工具输出或原始 `Error::to_string()`。

在进入 JSONL、SSE 和 REST 之前移除控制字符，并过滤已知 API key、Bearer/Basic/token 类片段、
当前输入及可识别的凭据/路径/请求回显；无法确定安全的说明直接舍弃。
本方案省略 `responseBody` 与 `responseHeaders`，仍以 message 展示允许公开的具体上游原因。
现有 LLM 层已截断 HTTP 摘要；Host 不重新请求上游或扩大原始内容采集。
测试用显式敏感哨兵证明这些内容不出现在 SSE、REST 和 JSONL。

## 6. 私有持久化与恢复

选择在现有 `TurnFinishCommitV1` 增加可选 `openCodeError`，保存错误对应的稳定 assistant message ID
与第 5 节的安全 error；turn/user 归属使用已有 terminal，不再复制输入或生成消息。
该字段使用 serde default 与省略 None；旧 commit 仍可读，旧版 reader 忽略新增字段。
禁止扩大公共 turns error Schema 或把原始 Provider 错误写入该字段。

runtime 在现有 snapshot gate 下同时发布 messages、terminal 与私有错误缓存。
恢复只接受已验证 finish commit 中的元数据；prepare 残留、不完整或写盘失败的批次不发布新错误详情。
消息归属与 terminal 的 failed 状态必须验证，错误详情不得跨 turn 或 session。

共享消息投影将错误附在已存在的对应 assistant；没有 assistant 时，在该 user 回合之后提供
只用于 wire 展示的 assistant，`parts=[]`，其 ID 与实时 header 一致。
该占位从私有 metadata/outcome 派生，不能加入 `Session.messages`、模型请求或生成消息 ID 清单。
旧 failed outcome 没有详细元数据时，仍可派生已有安全分类说明，不能恢复不存在的上游详情。

对可验证的失败占位 ID，回退规范化到对应的真实 user 边界；显式 fork 边界映射到同回合的
真实消息前缀。不能猜测未知 ID 或使用词典序比较。
Fork 沿用现有不复制 turn/admission 状态的行为，私有执行错误元数据不复制到新分支；
原会话错误仍可查询。该规则不得导致错误说明进入新分支模型上下文。

写盘失败优先呈现 `persistence_failed` 安全说明，不能声称错误详情已持久化。
若磁盘持续不可写，实时错误仍应结束 busy，但刷新恢复的限制必须如实记录。

## 7. 替代方案与取舍

1. **推荐：补齐 Host 的现有 OpenCode 消费协议，使用私有 finish metadata。**
   三个问题在同一个适配边界修复；Gateway turns 字段不变，OpenWork 只增加真实回归测试。
2. 扩展公共 TurnError 保存 HTTP/provider/details，再由它生成 UI 错误。内部缓存更简单，
   但会改变 Gateway 公共合同与 Schema，不符合此次尽量收窄范围的目标，未登记实施。
3. 修改 OpenWork 乐观输入、snapshot 对账或 turns 轮询。可以补偿现象，但不符合用户的业务代码边界，
   不作为本次实现路径；不能只用强制刷新代替消息删除与持久化错误。

这里修改的是已有 Host 接收、结束与 OpenCode 投影流程，未新增服务、消费适配器或重组模块边界。
`message_projection` 仅提取必须共享的现有转换。若实施发现必须改变公共 turns、Core/Provider 或消费者
接口，brainstorming 路径升级为 architectural，不能在本批准内静默扩展。

| 验收 | 观察断言 |

## 9. 风险与回滚

主要风险是事件逆序使旧缓存复活、零输出失败错误挂错回合、虚拟展示消息影响历史边界，
以及恢复/回退未同步裁剪私有 metadata。上述矩阵分别覆盖，必须以真实消费者 journey 验证。

回滚代码可恢复到 `0f7c2fa` 或仍识别既有 revert/finish 事务的兼容 Host。
新增字段可被旧 finish reader 忽略，无数据迁移；回滚后详细错误展示会退化，不能承诺旧程序仍展示新详情。
不得回滚到不识别 `session_revert_committed_v1` 的程序，不删除或重写 session JSONL。
正式部署和合并另行按用户授权及 CODEOWNER 流程执行。
