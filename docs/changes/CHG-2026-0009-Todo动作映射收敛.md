# CHG-2026-0009：Todo 动作映射收敛

## 先说结论

本变更移除 Todo 工具到办公室人物的未登记映射，使 `todo_add`、`todo_update`、`todo_list` 只更新 Todo 数据并发送 `todo.updated`，不再产生 `desk_visit` 或占用角色。web、read、write 的既有动作映射不变。源码和测试用例已存在，但旧变更单没有当前候选版本的完整测试记录，也没有正式 PR 或人工审批证据。

## 2. 变更原因

旧 `office.rs::tool_role` 将三个 Todo 工具映射到 5 号角色，首个 Todo 工具开始时会产生未在 master-plan 登记的拜访动作，并可能占用每回合唯一一次拜访名额。Todo 是工作区状态更新，不等于网页搜索、文件读取或文件写入动画；错误映射会造成无真实协作任务时人物仍移动。

## 9. 影响、数据流和实现

### 影响分析

Todo 工具调用者、Todo 数据文件和 `todo.updated` SSE 不变；AI Office 不再接收 Todo 触发的拜访或角色状态。并发、权限、取消、性能和依赖均不变。日志可继续记录 Todo 工具执行，但不能用日志反向驱动 Office 动作。

### 数据流和失败路径

```text
todo_add/update/list ToolResult
  -> runtime 更新工作区 Todo 数据
  -> events::todo_updated
  -> SSE todo.updated
  -X-> OfficeDispatcher desk_visit/set_state
```

Todo 失败按工具结果处理，不产生成功 SSE，也不得产生 Office 动作。

### 实现方案和选择理由

直接从 `tool_role` 删除 Todo 分支，由单元测试固定返回 `None`。没有新增“Todo 专用人物”，因为 master-plan 没有该协议，且产品要求动画必须由真实登记任务驱动。
