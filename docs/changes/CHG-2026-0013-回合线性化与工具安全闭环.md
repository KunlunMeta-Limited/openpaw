# CHG-2026-0013：回合线性化与工具安全闭环

## 先说结论

本变更用于闭环 Rust/OpenPaw 专家审查确认的稳态回合、工具、LLM 流与 Host 传输阻断。除既有 B01-B11 外，本草案正式归档测试大纲 G01、G02、G06、G07 和 G08 中属于稳态请求链路的部分：`prompt_async` 请求幂等、SSE 慢消费者显式 gap/reconnect、全局并发/队列/FIFO 公平性、长回复组合 fixture，以及 HTTP 请求与 Provider/Host 流的累计资源预算。G03-G05 及 G08 的 session 历史预算由 CHG-2026-0015 管理；G06 的关闭期 admission、排队取消和任务收割也由 CHG-2026-0015 管理。

**当前裁决：已批准实施，但发布阻断尚未全部闭环。** 当前会话已明确批准登记范围内的修复；批准不等价于发布通过，既有历史绿测也不能替代竞态、安全、取消、故障注入、真实 Provider 和 T10 冲突证据。

## 9. 影响、数据流和实现

### 9.1 B01：turn gate 迟到清理竞态

**根因**：`run_turn` 在 session 锁和 turn gate 范围内写 terminal 并设置 `active=false`，但释放 gate 后才刷新 `message_cache`、清 activity、调用 `office.clear_owner` 并发送 `session.status(idle)`/`session.idle`。`finish_turn` 与 `TurnCleanup::drop` 也存在“先释放 active/gate，后投影清理”的分叉。

**拟修改符号**：`SessionHandle::release_turn`、`rollback_reserved_turn`、`TurnCleanup::drop`、`run_turn`、`finish_turn_projection`、`finish_turn`；新增唯一私有终态提交 helper。

**实现不变量**：正常完成、失败、排队取消、running 持久化失败、panic/Drop 和 reservation rollback 汇入同一清理协议。终态和最终 session snapshot 形成后，旧回合在持有 `turn_gate` 时完成 cache/updatedAt、activity、Office owner/working、`active=false`、idle status 和 idle event，最后释放 gate。新回合 busy 后不得出现旧回合 idle、owner 清理或 cache 覆盖。

**并发/压力验收**：用 barrier 在旧回合 terminal 已形成但清理未提交处暂停；同 session 第二请求在 gate 释放前稳定 409，释放后才可 204。断言 `turn1 idle < turn2 busy`。定向循环至少 1,000 次、Tokio 至少 4 worker，零永久 busy、零旧 cache 覆盖、零事件逆序；两个不同 session 仍能真实重叠。

### 9.2 B02：默认 parallel_tools validator 绕过

**根因**：`execute_tools_phased` 从 tool use 直接进入 guardrail；只有 sequential 路径调用 `validate_input`。

**拟修改符号**：`execute_tools`、`execute_tools_phased`、`execute_tools_sequential` 和共享输入准备 helper。

**实现不变量**：无 hook 时，每个调用按 validator -> guardrail -> approval -> execute。validator 拒绝时，不调用 Before/After hook、guardrail、ApprovalManager 或 ToolHost；同批其他合法工具继续。串行和并行必须复用相同安全阶段。

**测试**：默认并行批次至少两个工具，一个 validator 拒绝。拒绝项 validator 计数 1，其余安全组件和 call 计数 0；合法项执行 1 次。串行/并行表驱动结果一致，循环 500 次无绕过。

### 9.3 B03：BeforeToolCall Replace 二次安全校验

**根因**：当前 Replace 在 guardrail/approval 后改写输入，并直接进入 `execute_one`；插件契约明确替换 payload 未校验，调用方必须负责。

**拟修改符号**：拆分 `execute_with_hooks` 为 Before 输入变换和 execute + After 结果变换；把 Before 阶段移到 validator 与 guardrail 之间。

**最终顺序**：原始 input validator -> Before hook -> 若 Replace 则对最终 input 再次 validator -> 对最终 input guardrail -> 必要时以最终 input approval -> execute -> After hook。Continue 不重复 validator；Replace 不复用原 input 的分类或审批。

**测试**：至少覆盖合法变非法被 validator 拒绝、Allow 变 Deny、Allow 变 Confirm 且审批看到替换后 JSON、合法替换只执行一次、Replace 缺少 `/input`。串行和默认并行各跑一组，非法场景 ToolHost 调用均为 0。

### 9.4 B04：首条 outcome 的 fsync 回滚

**根因**：`SessionWriter::append` 先 `writeln!` 再 `sync_data`。首条 outcome append 使用 `?`，因此“字节已写入、fsync 失败”直接返回，不执行已取得的 rollback point。

**拟修改符号**：`append_user_and_turn`、`writer_snapshot`、`restore_writer_snapshot`，以及 runtime 私有 `SessionAppender`/等价 seam；生产实现委托现有 `SessionWriter`，测试实现可精确失败，不修改 Store API。

**实现不变量**：首 outcome 和 user append 任一失败都截回同一个写前长度、重开 appender，并保持 Session、message cache、turn_outcomes/current_turn 与磁盘一致。rollback 失败返回组合错误并保持回合 closed，不伪装成功。

**故障注入**：精确 failpoint `AfterWriteBeforeSync` 必须先向真实临时 JSONL 写入完整 outcome 行，再返回模拟 sync 错误。普通 write 失败、关闭 writer 或权限错误不能替代。直接单元测试验证回滚；HTTP 现有错误映射测试验证失败返回 500。

**压力/恢复验收**：首 outcome、user、terminal 三阶段分别注入至少 100 轮；文件长度恢复、Reader 无孤儿状态、内存无半轮、`active=false`。同 session 后续回合成功，Host 重启后仍无孤儿 queued/running；每 turn 恰好一个终态或完全未接收。

### 9.5 B05：AgentLoop 单实例并发

**根因**：三个 `run_turn*` 入口接收 `&self` 且文档允许 Arc 共享，但入口会替换 cancel token、reset 共享 iteration budget，并使用实例级 token budget tracker。

**拟修改符号**：`AgentLoop` 新增私有单活动回合原子闸门和 RAII guard；三个公开入口及 `run_turn_inner` Rustdoc 收紧。

**实现不变量**：同一实例同时最多一个活动回合；第二调用在改写 token、reset budget 或 session 前通过既有 `Error::Session`/`Error::session` 路径确定性拒绝。RAII 在成功、错误、取消和 unwind 时释放。不同 session 通过独立 AgentLoop 实例保持并行。

**并发/压力测试**：两个 Session 共享一个 `Arc<AgentLoop>` 同时进入，恰好一执行一拒绝；运行中 token/预算不被第二调用改变。取消首回合后下一回合成功。至少 1,000 组，零双执行、零永久闸门、零交叉取消。

### 9.6 B06：compaction/approval/validator/guardrail 可取消

**根因**：`compact_session(...).await`、`approval.request(...).await`、`validate_input(...).await`、`guardrail.check_with_context(...).await` 位于取消 select 外。

**拟修改符号**：在 `agent_loop.rs` 建立统一的 biased cancel-vs-operation helper，覆盖四类 await；不修改 Provider/Core trait。Before hook 移位后也必须继续使用既有可取消包装。

**实现不变量**：取消优先；future 被 drop 后不得发布 classifier、approval、tool 或 compaction 事件。任意自定义实现即使永不返回，也不能阻塞回合。Host `abort_all` 继续清 pending permission，Engine 不假定具体 ApprovalManager 类型。

**故障注入/压力**：分别提供永不返回且带 Drop 观察器的 compaction provider、ApprovalManager、ToolHostValidator、ToolGuardrail。取消后单测 250ms 内返回、Drop 被观察、ToolHost 调用 0；每类 200 次无 task 泄漏、迟到事件或后续回合损坏。生产验收目标 P99 小于 2 秒。manual Host abort 后 permission 为空、session idle，idle 后无 delta/tool result。

### 9.7 B07：T2 固定 fixtures

**根因**：fixtures 目录只有 README，动态构造 roundtrip 不是固定 wire 样例。

**拟交付**：三个登记 JSON 文件；测试通过 `include_str!` 或固定路径只读加载，禁止运行时生成或覆盖。

**验收**：session fixture 固化 id/title/slug/directory/time；events fixture 覆盖 created/updated、busy/idle、message、text/reasoning part、delta、tool running/completed/error、permission asked/replied、todo；provider fixture 固化四个 id/model 和 connected。全部 JSON parse、serde decode/encode/decode，关键 camelCase 字段逐项断言；缺失不得 skip。

### 9.8 B08：T6 CLI help snapshots

**根因**：`Cli` 已定义三个 Host 旗标，但 root help snapshot 未断言。

**拟修改符号**：`help_snapshot.rs` 的 root help 断言。

**验收**：engine-host feature 下精确包含 `--engine-host`、`--engine-host-hostname`、`--engine-host-port` 及 hostname/port 默认值；sidecar + engine-host 组合同时存在且子命令数量不回归；feature-off 时三个旗标均不存在。必须检查实际 help 输出，不能只读字段。

### 9.9 B09：T10 第 5 号角色基线冲突

**事实**：根计划 §4.2 要求 completed/failed 后将 5 号角色设为 `working`，task 为“整理回合结果”，并保持到下一轮。当前 `OfficeDispatcher::turn_ended` 释放全部角色，单测明确禁止 5 号 working；即使只改 `turn_ended`，`runtime.rs::finish_turn_projection` 随后 `clear_owner` 仍会立即清掉 5 号状态。

**人工必须二选一**：

- **方案 A：根计划优先。** 同时调整 `office.rs` 和 `runtime.rs`：completed/failed 释放 1/工具/审批角色，但由 owner 保留 5 号 working；终态 projection 不清除此整理 owner；下一轮 `turn_started` 先释放该 owner 的旧 5 号状态再进入 thinking。补充多 session owner 仲裁和动作顺序测试。
- **方案 B：真实活动才动画优先。** 保持全部归零，但根计划负责人必须先正式修订 `master-plan.md` §4.2、T10 和 M5，删除第 5 号整理要求；不能只改测试宣称满足原计划。

### 9.10 B10：SSE 增量 UTF-8 解码损坏中文和 emoji

**根因**：`crates/openpaw-llm/src/sse.rs` 当前对每个 HTTP byte chunk 独立执行 `String::from_utf8_lossy(bytes)`。HTTP chunk 边界不是 Unicode 边界；当 chunk 结束在中文三字节序列或 emoji 四字节序列中间时，本次调用立即写入替换字符，后续字节到达后已经无法恢复原文。

**实现不变量**：解析器持有最多 3 个未完成尾字节。每次 `feed()` 将尾字节与新输入拼接，只把完整、合法的 UTF-8 前缀送入现有 SSE 行缓冲；合法但尚未完整的末尾保留到下一次调用。位于完整输入区域的非法 UTF-8 必须返回可区分错误，不得继续使用有损替换。`finish()` 发现残缺尾序列时必须失败，并保持已经产出的完整事件不被重复发送。OpenAI 和 Anthropic 流式路径必须复用同一解码契约。由于 `feed/finish` 从 `Vec<Frame>` 收紧为可失败结果，两个 Provider 调用方必须同步传播错误，不能只改 decoder 而忽略失败。

**确定性测试**：使用版本库内可重建的固定正文生成器，包含 ASCII、中文、emoji、CRLF/LF、引号、反斜杠和 Markdown，对每个可能的单字节切分边界执行一次；再使用记录在 fixture 元数据中的固定随机种子重放随机 chunk size。50,000 和 180,000 UTF-16 code units fixture 分别记录生成算法版本、种子、provider 原文与最终 assistant 正文的 UTF-8 SHA-256，断言逐字节一致、`U+FFFD` 数量为 0。另覆盖完整非法序列、`finish()` 残缺序列、跨多个 `feed()` 的 2/3/4 字节码点，以及 OpenAI/Anthropic 两种事件形状。临时目录中的损坏 JSONL 只作复现佐证，不能替代版本化 provider 原文 fixture。

**注释要求**：2026-09-16 定向检查发现 `crates/openpaw-llm/src/sse.rs` 有 10 个公共声明缺少标准中文 Rustdoc。B10 实施必须在不扩大行为范围的前提下同时补齐功能、参数/字段、返回、错误、状态、并发与取消、权限和关联编号；修复后的目标文件注释检查必须为 0 缺口。

**2026-09-16 复现证据**：隔离 OpenAI-compatible SSE provider 将 payload 按 Unicode code point 生成后交由真实 HTTP 传输。50K 预期长度 50000、SHA-256 `1df9604431a8093408ed7159a473bd226f66b11465071000efe89d31268fa194`；Host/JSONL/Gateway/Store/DOM 长度 50004、SHA-256 `920532cfed5980ae61ba76d73ea8b29e982c14c02032cd988afd01ed5a909aa5`，首个差异约在 UTF-16 索引 2823，原应连续的“中文 + emoji”之间出现两个 `U+FFFD`。180K JSONL assistant 长度 180004，替换字符 7 个，SHA-256 `515f4e8aa19ee545fe5907ac94d1811b049b67c7a4041db38667af48282d86c0`。临时根分别为 `C:\Users\86187\AppData\Local\Temp\ai-office-long-transport-50000-1789592714570` 和 `C:\Users\86187\AppData\Local\Temp\ai-office-long-transport-180000-1789592769931`；这些目录是本机复现工件，不作为长期版本库证据。

### 9.11 B11：流终止完整性、畸形帧和缓冲上限

**根因**：decoder 当前把 JSON 解析失败静默变成 `null`；OpenAI 在 HTTP EOF 时没有调用 decoder `finish()` 就直接执行 assembler `finish()`；Anthropic 虽会 flush decoder，但没有收到 `message_stop` 时仍可 `finalize()`。因此 TCP 连接在 25%、50% 或 99% 处正常关闭、最后 JSON/tool arguments 被截断、或最后 UTF-8 码点残缺时，部分正文可能进入 `Final` 并最终写成 completed。

**实现不变量**：SSE decoder 输出显式 `SseData::Json(Value)` 或 `SseData::Done`，不能再把非 JSON `[DONE]` 静默转换为 `Value::Null`。OpenAI 必须看到且只接受一次 `SseData::Done`，Anthropic 必须看到且只接受一次 `message_stop`；终止后任何非空 data 帧、重复终止、Provider error-after-terminal 或两个 `Final` 候选都必须失败。协议明确的 error 帧立即失败。decoder 的 UTF-8、SSE 行、JSON frame 和 tool arguments 任一未闭合都必须产生脱敏 Provider 错误，不能产生 `Final`。line buffer 和单个 data event 的字节上限分别固定为 2 MiB；超过上限显式失败并释放缓冲，不能截断、丢前缀或注入替换字符。

**测试**：50K/180K 分别在 25%、50%、99% 处干净 EOF；最后一个 2/3/4 字节码点截断；最后一帧 JSON 截断；tool arguments 未闭合；缺少 `[DONE]`/`message_stop`；畸形 JSON；重复终止；终止后额外帧；error-after-terminal；单帧 180K 合法成功；恰好 2 MiB 和超过 2 MiB 的边界。每个失败场景不得产生 `Final`、completed turn 或部分 assistant 持久正文；成功场景恰好产生一个 `Final`。

**fixture**：`long-stream-v1.json` 固定 `generatorVersion`、字符片段表、重复算法、50K/180K UTF-16 长度、随机分块种子和 UTF-8 SHA-256。测试在内存中按元数据重建正文，不把 180K 完整正文重复提交到版本库；`sha2` 仅作为 `openpaw-llm` dev-dependency，生产依赖树不得出现。两种 Provider 共享同一原文 fixture 和哈希期望。

### 13.1 G01：异步请求幂等合同

- `POST /session/:id/prompt_async` 和同步 `POST /session/:id/message` 接受可选 `requestID`。键的作用域是单个 session，长度 `1..128` 字节，只允许可打印 ASCII；未提供时保持现有非幂等行为。
- Host 对正文 text parts 顺序、`providerID`、`modelID` 和协议版本生成稳定 SHA-256 指纹。认证信息、路径、时间和随机编号不得进入指纹。
- 同 session、同 `requestID`、同指纹的首次请求与任意重放必须返回原 `turnID`，不得重复写 user/turn、调用 Provider、申请工具权限或执行工具副作用。异步端保持 `204`，同步端返回原回合当前/最终投影；两者都通过 `OpenPaw-Turn-ID` 响应头返回稳定回合编号。
- 同 session、同 `requestID`、不同指纹返回 `409 idempotency_conflict`，且零新增 JSONL、零 Provider/工具调用。不同 session 可复用相同键。
- 幂等事实必须以新增 JSONL `request_admission` 未知事件或等价向后兼容记录持久化，至少包含 `requestID`、指纹、`turnID`、`userMessageID` 和接收状态。仅内存 HashMap 不满足重启重放要求；日志和错误不得输出正文或原始键。

### 13.2 G02：SSE 慢消费者 gap/reconnect 合同

- session/global broadcast 出现 `Lagged(n)` 时禁止继续静默过滤。Host 必须先发 `stream.gap` 控制事件，字段至少包含 `scope`、可选 `sessionID`、`dropped>=1`、`recoverVia=[status,turns,message]`，随后主动结束该 SSE 连接。
- 当前草案不承诺 delta 重放。客户端重新连接后必须以 `GET /session/status`、`GET /session/:id/turns`、`GET /session/:id/message` 恢复事实；终态和完整正文必须在 gap 后 2 秒内可读取。重连后的新事件不得伪装成连续旧流。
- 正常消费者不得收到 gap；慢/停读消费者不得拖慢 turn、持久化或其它订阅者。连接结束后相关 task、handle 和 buffer 必须回落到基线。
- `stream.gap` 是新增公共控制事件，必须新增 Schema，并由消费端另行批准兼容处理；不能只增大 256/512 broadcast 容量掩盖丢失。

### 13.3 G06：稳态并发、队列与公平性边界

- 本 CHG 负责稳态调度：默认 `4 running + 32 queued`，配置边界保持 `1..=32` 和 `0..=1024`；容量已满稳定返回 `429 queue_full`，拒绝请求不得写 user/outcome。
- 跨 session 按已接收 ticket 严格 FIFO 晋升；同 session 仍最多一个活动回合并快速返回 409。排队取消与 permit 晋升竞争必须由调度锁给出唯一结果：要么取消并释放队列位，要么晋升并持有唯一 permit，不得双释放、丢 permit 或队列位置倒退。
- 门禁为 4 个阻塞 running、32 个 queued、100 个额外提交；另做 32 session × 1,000 回合、10,000 次随机取消和 30 分钟 soak。最终 running/queued/registry 均为 0，零饥饿、零串 session、零资源单调增长。
- CHG-2026-0015 负责 shutdown admission 线性化、任务 registry 和关闭期间 permit/queued 释放。两份 CHG 必须在同一候选联合验收，任何一份未批准时 G06 保持阻断。

### 13.4 G07：长回复组合 fixture

固定可重建 fixture 必须覆盖普通文本、中文长难句、emoji、组合字符、CRLF/LF、Markdown 表格、链接、引号、反斜杠、代码围栏、多 content block、reasoning/text 交替和 tool arguments JSON。OpenAI/Anthropic 共享相同原文，按 1/2/3/4/7/31/1024 字节及固定随机种子切块。50K、180K 和边界预算样本逐层记录 UTF-8 字节数、UTF-16 长度和 SHA-256；Provider 原文、LLM Final、Host JSONL、message REST 必须逐字节一致，`U+FFFD=0`，且每回合恰好一个 terminal。
