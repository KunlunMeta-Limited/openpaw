## 实现、协议与替代方案

复用 MainOffice 原 records 同步锁，将已有成员及临时预留一起计数；预留 guard 在失败、取消或 future 丢弃时释放。只对已经绑定 main 父会话的办公室实行成员预留，不给原 OpenWork/feature 入口另加展示前置。网络不参与准入，gateway 故障不改变已经开始的 Engine 结果。新会话生成后先以真实 ID 登记员工，沿用最先空闲且从未绑定的五个槽位，额外员工 sceneActorId 为空；失败明确返回，未成功登记不接收回合、不调用子模型或工具。事实提交后快照失败保留事实及内存身份，不静默丢弃；返回错误包含真实子 ID，便于核对。

沿用所有现有 HTTP/SSE/Office 字段；没有新产品接口或依赖，不复制会话/历史存储。未采用先执行后投影、按空闲状态回收人物或拿模型信号量充当成员容量的方案，分别会造成隐藏员工、身份串线或限制错位。

2026-10-21 按真实 main `integration/docs/dashboard-integration.md` 确认：200只是条目上限，请求还受64KiB限制。发布容量属于本票准入，不新增看板能力：在原子预留时检查整个当前初始化目录，计入每个尚未登记名额1000字节（最长新员工及执行任务），另保留4096字节供最多四个在途子回合/当前事件及协议封装。超出时在创建前明确拒绝，不截断员工或删除历史。既有 task_id 续办不申请新成员；此预算不改变真实模型并发和协议大小。

## 测试和回滚

预先确认的测试边界为 Host HTTP/SSE Router → 真实 Engine/Store，Provider/gateway 是外部受控边界。逐条 RED→GREEN：满200含主员工前拒绝第200个子身份；竞争仅剩一个名额；满员明确 task_id 续用不占名额；六个真实子会话及第六人只读详情、无借用其他人物动作；本地登记失败不执行。fixture 只在临时 home 预置已存在办公室成员，真实新请求通过公共 Router。保存 RED/GREEN、Host 回归、严格单包 Clippy、fmt/diff 检查；浏览器截图由集成调度者以原版 main 补充。全 workspace 门禁统一由集成分支执行，已有基线失败如实保留。

回滚当前提交不删除会话或产物；临时预留自然释放，已有员工事实保留。旧快照/未知记录仍兼容读取，不重放动作或工具。实际命令与退出码在完成时补充。
