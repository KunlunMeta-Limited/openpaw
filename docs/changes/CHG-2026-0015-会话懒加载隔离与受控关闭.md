# CHG-2026-0015：会话懒加载隔离与受控关闭

## 先说结论

本变更用于闭环 2026-09-17 多专家交叉审查新增确认的三个 Host 生命周期阻断：一个冷 session 的磁盘/工具加载会持有全局生命周期锁并阻塞其它 session 的 prompt/abort；重启恢复只处理最后一个未终态回合；异步回合的 `JoinHandle` 被丢弃，真实进程关闭时没有停止接收、统一取消和有界等待。

**当前状态：草案（draft），未实施，发布阻断。** 现有 reliability 7/7 只覆盖单个悬挂回合、FIFO、取消和持久化失败，不覆盖本变更。人工批准前不得修改 Rust、Cargo 或测试源码。

## 2. 变更原因

当前 `AppState::get` 在取得全局 `session_lifecycle` 后跨越 `SessionReader::read`、torn-tail 修复、provider 创建、workspace 解析、`tool_host.list_tools().await` 和 writer 打开。任一 session 的慢磁盘、超大 JSONL 或 ToolHost 枚举都会阻塞其它 session 的 `get`，而 prompt、abort、todo、message 等路由都依赖 `get`。这与“不同 session 可并行、取消必须及时”冲突。

`load_existing` 只检查 `turn_outcomes.last()`。历史文件若存在多个不同 turn 的 `queued/running` 快照，或旧版本已经留下多个孤儿，只有最后一个会被转换为 `host_restarted`，其余会永久保持非终态。

HTTP prompt 使用 `tokio::spawn` 后不保存 `JoinHandle`。`axum::serve` 没有 graceful shutdown、全局取消 token、后台任务注册表或等待期限。当前“丢弃 Router/AppState 后重新加载”的测试不等价于 Windows 进程在 queued、stream、approval、tool 和 terminal 持久化临界点退出。

## 9. 影响、数据流和实现

### 9.1 按 session 懒加载隔离

```text
get(A) -> 取得/创建 slot[A] -> 释放全局 slot-map 锁
       -> 锁 slot[A] -> 二次检查缓存 -> read/list_tools/open writer -> publish A
get(B)/abort(B) -> slot[B]，不等待 A 的磁盘或 ToolHost
delete(A) -> 同一 slot[A]，与 A load 串行且不复活已删除 session
```

全局锁只保护 slot map 的短临界区，不跨文件 I/O、ToolHost await 或 session 构造。load 完成前后都检查删除 tombstone/generation，确保 delete 与 load 竞争不会复活 session。失败的 load 不把半构造 handle 发布到共享 map，下一次调用可以重试。

slot map 必须有确定回收：不存在的随机 session id 不创建长期 slot；失败 load 在最后 waiter 离开且没有缓存 handle 时移除；delete tombstone 只保留到所有旧 generation future 完成，随后回收；空闲无 handle 的 slot 使用显式 `last_used` 进行有界 LRU 清理。10,000 个随机 404、1,000 次失败 load 和 1,000 次 load/delete 后 map 必须回到与真实 session 数量同阶，不能用永久 tombstone 换取安全。

### 9.2 全量未终态恢复

读取历史事件后先按 `turn_id` 取得每个回合的最终快照。对每个最终状态仍为 queued/running 的 turn，按原始顺序追加一次 `failed/host_restarted`；已有 terminal 的 turn 不重复写。第二次和后续重启必须零新增恢复记录。恢复错误不能只修改内存而不写 JSONL。

### 9.3 受控关闭

```text
shutdown signal
  -> 原子设置 accepting_turns=false，并触发 listener graceful shutdown
  -> 与并发 prompt 的 reserve/admission/register 在同一线性化边界决胜
  -> 已关闭侧请求返回 503 host_shutting_down，且不得写 user/outcome
  -> cancel 所有 queued/running session
  -> 等待每个任务走现有 terminal/cleanup 路径
  -> 5 秒上限内 join；超时任务记录脱敏诊断并强制终止
  -> 保留 JSONL，退出进程
```

任务 registry 使用受所有权约束的 `JoinSet` 或等价结构；prompt 只有在 registry 接受任务后才 disarm reservation。注册失败必须回滚 admission、active 和尚未提交的接收状态。任务正常结束、取消、panic 和强制 abort 都由 registry 收割；panic 记录脱敏诊断并确保 session 清理，不能静默丢失 JoinError。测试入口接收可注入 shutdown future 和已绑定 listener，生产 `run_blocking` 使用 Ctrl+C。

关闭不能等待 Office 动画投递成功，也不能把 Office 故障变成 turn 失败。对无法在期限内完成的任务，5 秒后强制 abort 并保留 JSONL；下次启动由全量恢复转换为 `host_restarted`。5 秒期限是本草案的发布默认值，真实负责人可在批准前调整；批准后只能通过新 CHG 改变。Windows 服务管理器硬杀进程不保证 graceful，仍需依赖重启恢复。

## 13. G03/G04/G05/G06/G08 正式归档附录（draft）

> 状态：**待审批、未实施、未通过。** 本节正式归档 `docs/b-line/testing.md` G03、G04、G05、G06-SHUTDOWN 和 G08-SESSION。相关文件已同步登记到主允许表和禁止范围；未经人工重新审批不得修改 Rust、测试、Cargo、公共错误或 Schema。

### 13.1 G03：session load 错误分类

`AppState::get/load_existing` 不得再以 `Option` 把全部失败折叠为普通 404。批准后的内部结果必须区分：

| 分类 | 典型原因 | HTTP/行为合同 |
| --- | --- | --- |
| `not_found` | 文件确实不存在或 session id 非法 | 404；不创建长期 slot |
| `corrupt` | 中段 JSON 损坏、缺 meta、meta id 不匹配 | 409 `session_corrupt`；原文件只读保护，不自动截中段，不伪装 404 |
| `permission_denied` | Windows ACL/只读目录拒绝读取或打开 writer | 403 `session_permission_denied`；不得输出绝对路径、正文或凭据 |
| `unavailable` | I/O、磁盘、ToolHost 枚举或 writer 暂时不可用 | 503 `session_unavailable`；标记可重试，不发布半构造 handle |

torn tail 仅在 reader 明确证明“最后一行撕裂”时允许幂等修复；修复前保留原文件哈希和诊断。列表接口可以跳过坏文件继续返回其它会话，但必须增加脱敏指标，不能让详情接口把坏文件当作不存在。

### 13.2 G04：真实 `taskkill /F` 五阶段恢复

必须启动真实独立 Host 二进制，在以下五个阶段分别执行 `taskkill /PID <pid> /F`：admission/outcome 提交前后、user fsync 前后、assistant 消息批次中、terminal fsync 前后、terminal 已提交但投影/响应未完成。每阶段至少 20 次，共至少 100 次。

重启后的合法结果仅允许“请求完全未接收”或“同一 turn 最终恰好一个 terminal”。JSONL 必须全部可读，最多只修复最后 torn line；禁止删除中段、重复 user、重复 terminal、永久 busy 或重复工具副作用。G04 与 CHG-2026-0013 B04/G01 联合验收：硬杀后的相同 `requestID` 必须回到原 turn 或确定性冲突，不能创建第二回合。

### 13.3 G05：shutdown 覆盖面

- 第一次 Ctrl+C 原子设置 `accepting_turns=false` 并停止 listener 接收；与并发 prompt 的 admission/registry 必须在同一线性化边界决胜。
- 关闭令牌必须覆盖空闲/lagged SSE、同步 `/message`、异步 `prompt_async`、queued/running turn、approval/tool 等待和半上传请求体。已接受请求走终态持久化；关闭侧请求返回 503 `host_shutting_down` 且零写入。
- 总关闭期限 5 秒，包括 HTTP connection drain、任务取消、terminal fsync 和 registry join；超时后强制 abort，下一次启动由全量孤儿恢复闭合。第二次 Ctrl+C 允许立即强制退出，但必须记录脱敏原因。
- 端口在进程退出后 1 秒内可重新绑定。不得等待 Office 动画投递，也不得用丢弃 Router/AppState 代替真实 listener 和进程测试。

### 13.4 G06：与稳态调度的跨 CHG 边界

CHG-2026-0013 负责正常运行期 4/32 容量、FIFO、公平性、429 和排队取消唯一结果；本 CHG 负责关闭期 admission barrier、registry 所有权、queued/running 统一取消、permit 归还和 panic/超时收割。两份 CHG 必须使用同一候选联合执行 P01/P03/P10/P11，最终 `running=0`、`queued=0`、`registry=0`、pending approval=0，且无 session 饥饿。任何一份仍为 draft 或失败时，G06 整体保持阻断。

### 13.5 G08-SESSION：session 历史资源预算

| 资源 | draft 上限/门禁 | 超限行为 |
| --- | --- | --- |
| 单 session JSONL | 256 MiB | 详情加载返回 413 `session_too_large`；原文件不改写 |
| 单 session 事件数 | 1,000,000 | 同上；扫描计数有界，不先完整 materialize |
| 单 session message 数 | 100,000 | 同上；不得构造无界 message cache |
| 单条 JSONL 行 | 4 MiB | `corrupt` 或 `session_event_too_large`；不得截断后继续 |
| 历史冷加载 | 10/50/100 MiB 三档近似线性；100 MiB 中位数不得超过 10 MiB 的 15 倍 | 超门禁不得直接放宽，先 profile 并消除重复复制 |
| 冷加载峰值内存 | 文件字节数的 3 倍与 128 MiB 增量中的较大者 | 超限为发布阻断 |

预算检查必须在 session slot 内执行，但不得跨 session 持有全局锁。错误、404、失败 load 和 delete/load 竞争结束后 slot 数回落到真实 session 数加 32 以内。
