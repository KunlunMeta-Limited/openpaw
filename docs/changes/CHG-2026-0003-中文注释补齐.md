## 2. 变更原因

当前 B 线新增 Host 代码和 CLI 入口存在大量仅有英文、仅有名称或没有 Rustdoc 的公共声明。开发人员和 AI 无法从函数签名判断 session 所有权、SSE 顺序、审批清理、Office 失败隔离和 feature 边界，后续修改容易发明不一致行为。注释补齐只增加设计证据，不改变二进制行为；历史其他 crate 的注释缺口另行分批处理。

范围边界（2026-09-18 澄清）：本 CHG 以"新增公共项"为界。既有文件中既有的公共声明不因本次改动而强制中文化，第 4 节只保留新增或新暴露的公共入口所属文件；`crates/openpaw-engine/src/agent_loop.rs` 属既有文件，注释维持英文。

## 9. 影响、数据流和实现

### 影响分析

注释必须描述真实代码当前行为：HTTP -> runtime session -> AgentLoop -> AgentEvent -> SSE/JSONL/Office 投影。不得把注释写成未来计划，不得把六个 Office 角色描述成独立 agent，不得声称 Office 失败会取消回合。公共注释中的 API/REQ/CHG 编号必须存在于项目基线或本 CHG。

### 数据流和失败路径

```text
请求 -> http.rs 校验 -> runtime.rs 保留 -> AgentLoop
  -> events.rs SSE / runtime JSONL / office.rs 异步投影
```

注释补齐不增加任何调用、写入、网络请求、锁或错误分支。

### 实现方案和选择理由

按项目内注释示例逐文件补齐模块 `//!`、公共类型/字段 `///` 和复杂不变量 `//`。先覆盖本次 B 线新增/修改的高风险公共边界，再单独处理历史其他 crate。选择分批是为了让每个 PR 的注释与真实行为可由对应负责人审核，不制造无意义的大 diff。
