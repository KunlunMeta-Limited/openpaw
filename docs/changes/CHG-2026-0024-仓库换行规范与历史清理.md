# CHG-2026-0024：仓库换行规范与历史清理

状态：已实施，待人工审查。依据：用户明确要求将 `c85f7b1` 按 LF 规范化并重写提交历史。

## 原因与范围

`c85f7b1` 将父提交中原本为 LF 的 327 个文本文件写成 CRLF，导致 Git 产生大规模无意义差异，且 Linux 下的 shell 脚本可能出现 `bash\\r` shebang 或语法错误。本变更只修复仓库文本换行和提交历史可审查性，并对原提交中同一批功能改动所在的两份 Rust 文件执行 rustfmt；不改变既有业务逻辑、协议、依赖或运行数据。

## 允许修改文件

| 文件 | 必要性及影响 |
| --- | --- |
| `.gitattributes` | 统一文本文件使用 LF，阻止 Windows 编辑器再次提交 CRLF 噪声；不影响二进制文件。 |
| `docs/changes/INDEX.md` | 登记本变更。 |
| `docs/changes/CHG-2026-0024-仓库换行规范与历史清理.md` | 记录原因、范围、验证、回滚和提交历史处理。 |
| `c85f7b1` 中已有文件 | 仅将换行符恢复为 LF；保留原提交的真实业务改动，不新增业务文件。 |

## 接口、数据流与安全边界

- 不新增或修改 Rust、HTTP、SSE、Office、AgentLoop、Host 协议和公共 API。
- 不读取、修改或删除 session、产物、凭据和运行时数据。
- `.gitattributes` 只约束 Git 文本归一化；二进制文件由 `text=auto` 保持二进制处理。

## 实施方式

1. 为原 `c85f7b1` 创建本地备份引用。
2. 以父提交 `ebc69bf` 为基线保留工作树中的真实改动。
3. 添加 LF 规则并执行 Git 规范化，使 327 个 EOL-only 文件回到 LF。
4. 对原提交中未通过 rustfmt 的功能改动代码执行格式化。
5. 重建一条新的单提交历史，保留原提交说明和真实功能改动。
