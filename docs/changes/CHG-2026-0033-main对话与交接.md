## 接口、字段与数据流

新增受控服务端配置 OPENPAW_MAIN_URL、OPENPAW_MAIN_API_KEY，前端仅公开 VITE_PAWOFFICE_CHAT_URL=/api/chat。浏览器 Basic 与上游 Bearer 分离。只代理固定上游的页面、配置、SSE、reply、ui；不提供浏览器任意转发地址或业务密钥。

main chat 1.0 请求包含 teamId、conversationId 和最近完整历史；只将最新 user 消息交给现有 schedule_turn。首次绑定在 runtime 创建 Session 后、模型执行前原子保存。不同对话拒绝、同会话并发拒绝、已完成历史核对，不新增文本哈希去重。

main 业务客户端 POST /api/pawoffice/messages，保留原七消息 envelope、状态与无 null 合同。会话事实仍在 sessions JSONL；办公室身份、workspace、conversation、session、完整 snapshot 与 seq 放在同一 OPENPAW_HOME 的办公室记录。版本与内容一起原子提交后发送；重启恢复状态、不重放动作、不自动继续执行。

真实 AgentEvent/委派驱动人物；task.assigned 只发一次，成功返回用反向 office.visit。工具保持同一 Agent。main decision.request 桥接现有 permission，仅允许本次/拒绝；父子各自授权。聊天断连/停止/180 秒取消对应回合、前台子执行及 pending decision HTTP。场景故障独立于执行结果。
