## 2. 预期行为和边界

1. Host显式使用已有IterationBudget，将每回合常规最大迭代25调整为128，仍为8起始、按需扩展、1次宽限，最终禁工具终答保持；普通聊天、Goal及子Agent走同一Host配置。Engine和CLI默认不改，不通过无限循环、额外新回合、重新授予权限或重置预算修复。
2. 固定审核、压缩、委派等待、Goal续行均沿本回合剩余预算；停止/取消/模型截断/审批边界保持。128仍是有限上限，不承诺所有Goal必在该额度内完成。
3. 最后一项通过时明确指引独立整体验收：不重新选中已验收任务，先回读原件/实际交付，取得当前版本whole_goal观察，再逐条件accept_goal。拒绝单项旧依据时，错误明确说明缺少整体复核，不再误导要求选中任务。正常EndTurn仍由既有Goal continuation在原预算内继续。
4. 真实迭代预算耗尽时保存明确原因。正在执行或已有产出的任务中断，任务说明区分“已中断/待复核”和真实执行阻塞，保留已有结果、原件和验收事实。不得把聊天有正文直接当accepted，不伪造完成或阻塞原因。
5. 普通无关提问不自动追加完整旧计划，不覆盖旧暂停原因；实际计划修改和新版本审核仍展示完整计划。暂停权限、明确continue才能恢复、人工阻塞边界保持，不通过关键词猜测自然语言是否修改计划。
6. 原版三条阶段上限保留；现有summary/detail明确任务总数、已验收数和未完成任务/原因，避免把“展示前三条”写成总共只有三项。对于四任务，当前目标摘要能包含第四项并逐行组织；更多任务按原300字摘要上限给出完整任务列表入口说明，不宣称摘要展示全部任务。
7. 后端输出普通换行。原版前端真正保留换行需要额外样式批准，具体见display-proposal.md；未批准时不修改AI Office，不以HTML注入或特殊Unicode字符绕过显示规则。
