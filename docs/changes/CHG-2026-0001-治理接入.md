## 9. 影响、数据流和实现

### 影响分析

本次只新增治理文件，不改变编译产物和运行时数据流。新增的项目设计基线会冻结 Host 的路由、事件、状态、依赖和 Office 投影边界；新增的 profile、check.py、CI 和 CODEOWNER 会把边界转成可执行检查。历史实现中触及 L3/L4 的文件详见《当前实现反向审查报告》，后续需由负责人决定是否拆成补充 CHG。

### 数据流和失败路径

```text
需求/基线 -> AI 起草 draft CHG -> 人工审核 -> approve -> AI 受控编码
                                      -> Git PR diff -> CI + CODEOWNER -> 合并
```

如果 AI 需要修改未列文件、公共 API、依赖或数据写入点，必须停止并更新 CHG；治理检查失败时不得以删除检查、改成报告模式或手工勾选替代。当前没有 Git，因此首次接入只能先完成人工审核和文件落地，不能宣称已通过真实 PR 门禁。

### 实现方案和选择理由

采用中文 Markdown CHG 作为人和工具共同读取的唯一事实源，避免 TOML 字段堆叠导致审批人看不懂；profile 只存项目路径和命令；Schema 只做机器契约；CI 负责阻断；CODEOWNER 负责身份和责任。没有把治理规则写进业务源码，也没有在本次接入修复历史注释，以保证接入可回滚且不改变 B 线行为。
