## 1. 问题、范围与预期行为

OpenWork 上传附件时生成供模型、工具使用的路径说明，并标记 `synthetic: true`。OpenPaw engine-host 在请求解析时丢失标记及元数据，返回消息时把说明作为普通用户正文；首轮还可能把说明作为会话标题。图片原件仍以内联方式保存，说明没有替代图片。

本变更只修复 OpenPaw 的 OpenCode 协议兼容与相应持久化：新会话和继续对话均应显示真实用户正文及图片，辅助说明隐藏，模型仍收到附件与必要路径说明；自动标题排除辅助说明。OpenWork 已有过滤逻辑应直接消费修复后的响应。

贴图后中文组合输入只保留第一段的问题是另一项已复现缺陷，发生于本地输入框、发送前。本变更不修改 OpenWork，也不以中文输入恢复作为后端修复的交付承诺。临时操作为贴图后先输入普通空格，再开始中文输入；浏览器组合输入模拟已验证，微信输入法实际候选窗口仍未验收。

## 2. 协议来源与缺陷归属

| 项目 | 核实结果 | 归属 |
| --- | --- | --- |
| `synthetic` | 运行容器安装的 `@opencode-ai/sdk@1.18.18`，`TextPartInput` 与 `TextPart` 均有可选布尔字段 | OpenCode 消息协议字段，非 OpenWork 独有，也非所有 Agent/LLM 都必须具备的字段 |
| `metadata` | 同一 SDK 的两个文本类型均允许任意键的对象 | OpenCode 文本 part 元数据容器；不直接作为模型正文 |
| `metadata.openworkAttachments` | OpenWork 为不直传模型的附件记录名称、MIME 与 URL | OpenWork 自定义元数据键，Host 保留，不让 Store/Core 解释其业务含义 |
| 英文路径说明 | `attachment-file-part.ts` 生成 | OpenWork 生成的辅助正文，模型/工具仍可能需要 |
| 字段丢失 | Host `MessagePart` 未声明上述字段；`MessageRequest::message()` 转换后不保留属性；REST/SSE 文本投影也无该字段 | OpenPaw engine-host 的 OpenCode 适配缺口，非 Core 的图片理解能力缺失 |
| 中文输入中断 | 贴图后发送前出现；英文对照正常；先插入空格可恢复 | OpenWork composer 的独立问题，具体 Lexical 根因尚未确认 |

SDK 证据来自容器 `/opt/openwork/apps/app/node_modules/@opencode-ai/sdk/dist/v2/gen/types.gen.d.ts`：`TextPart` 在 248 行、`TextPartInput` 在 2097 行；OpenWork 正是从 `@opencode-ai/sdk/v2/client` 导入这两个类型。核查的是当前实际依赖版本，不将其等同于实现整个 OpenCode 最新协议。

Core 定义共享的模型消息、内容块、工具和 Provider 概念；engine-host 将 HTTP/SSE 的 OpenCode part 转成共享消息并投影回客户端。此次缺陷在 adapter 入口已经发生，因此由 Host 负责修复；为跨重启保留属性，需要 Store 的小范围中立扩展，不需要改 Core、AgentLoop 或模型适配器。

## 4. 实施方案：Host 适配与 Store 展示注解

### 4.1 请求解析与分块

- Host `MessagePart` 接收可选 `synthetic: boolean`、`metadata: object`；缺省为普通文本。只扩展现有提交入口，不新增路由。
- 带展示属性的 text 保留独立内容块及顺序，避免把辅助正文与真实用户正文合并；无展示属性的旧纯文本快捷路径兼容原行为。
- 直接 `text` 字段继续优先于 parts 中的 text；忽略掉的 text part 属性不能被转移到直接正文。
- `synthetic` 保留来源/展示语义，不等于删除正文或改成 system 消息。辅助正文仍在原 user 消息中供模型使用，不制造新用户回合，也不绕过能力或权限校验。
- `metadata` 作为展示注解保存，不注入模型 Prompt；不主动访问其中的 URL，不复制一份媒体原件，不输出到日志。沿用既有请求体预算。
- SDK 的 `ignored` 是另一个字段，本轮不把它与 `synthetic` 混用，也不声称补齐整个 SDK 消息协议。

### 4.2 持久化与生命周期

保持 Core `Message` / `ContentBlock::Text` 不变，把属性放在既有 Store 接收事务的可选扩展中：

```text
OpenWork text/file parts
  -> Host：共享模型内容 + 对应内容块的展示注解
  -> runtime：原子接收
  -> turn_accept_v1：message + outcome + requestAdmission + messagePresentation（可选）
  -> Store replay：完整 Message + 按消息 ID 查询的展示注解
  -> Host：REST / SSE 共用投影，恢复 synthetic/metadata
```

`messagePresentation` 使用中立结构：版本、内容块索引、辅助标志、可选元数据。Host 将辅助标志映射为 OpenCode `synthetic`；Store 不解析 OpenWork 英文说明或自定义键。属性不是 Core 的模型内容，也不是仅在 Host 内存中缓存的数据。

具体约束：

- 属性与 user 消息在同一个接收提交点生效。append 失败时均不发布，重启后不存在半份消息。
- 旧记录缺省无注解；新记录的索引必须指向合法 text block。重复、非法或错配索引按已登记记录损坏处理。
- 幂等指纹包含规范化展示属性；同一请求键但属性不同不得静默覆盖已接收事实。
- Fork 保留复制消息的注解，并随新 message ID 重新绑定。已有独立 Message 分支格式可配套中立 `message_presentation_v1` 事件，由既有分支文件发布事务整体提交；普通接收不拆成两次独立写入。
- Staged Revert / Unrevert 按既有完整历史与可见游标语义处理。提交回退后，注解与消息一同裁剪，不能错误关联下一条输入。
- 压缩只影响模型视图；完整历史的正文、原件、注解仍按原消息身份保存。注解不作为额外模型内容参与压缩。

### 4.3 REST、SSE 与标题

- REST 历史、同步提交响应及即时 `message.part.updated` 使用同一投影规则：辅助 text part 带 `synthetic=true` 与原 `metadata`。
- part ID 稳定；刷新、重连、重启后不把辅助文字重复追加到普通正文。纯 text 和 text/file 混合输入均覆盖。
- OpenWork 已有过滤直接生效：隐藏辅助正文，保留真实正文和附件。图片/file part、attachmentID、工具读取能力按既有协议保留。
- 自动标题只使用非辅助的真实用户正文，沿用 80 字符上限；仅附件时使用明确的附件默认标题，不能回退到辅助路径。
- 显式创建或修改的标题优先；继续对话上传附件不覆盖已有标题。Store 标题选择与 Host 持久化自动标题路径必须一致。

## 5. 历史兼容与已知限制

旧记录已经丢失 `synthetic` 与元数据，无法无损判断哪些文字是辅助内容。本轮完整修复新增消息的属性流转，不通过英文前缀猜测和隐藏旧正文，也不批量改写历史或自动重命名旧会话。

已有会话继续对话时，新提交的附件消息采用新方案；旧消息及已污染的旧标题保持已有数据，标题可用现有修改入口纠正。如果后续要求清理旧显示，需另行评估严格模板、附件证据和误识别负例，补充草案范围。

后端发布后中文输入问题仍待独立处理，不能宣传为“贴图中文输入已修复”。在当前约束下可采用临时空格操作，后续通过 OpenWork 上游修复或已验证的版本升级解决。

## 8. 实施顺序、替代方案与回滚

实施顺序：先补 Host 契约失败用例，再实现注解构造、原子保存及恢复，统一 REST/SSE 和标题处理，验证生命周期与旧记录，最后用当前原样 OpenWork 验收新消息。Core 和 OpenWork 不进入实施范围。

| 替代方案 | 取舍 |
| --- | --- |
| 仅 Host 内存保存标记 | 不采用：重启后重新暴露辅助正文，Fork/回退容易错配 |
| Core Text 直接增加 synthetic/metadata | 不采用：客户端展示语义可在接收包装保留，无需扩大共享模型结构影响 |
| 删除全部辅助说明 | 不采用：工具仍可能需要路径；不能破坏模型输入来掩盖展示问题 |
| 按英文前缀自动隐藏正文 | 不采用：新消息应依赖协议属性；旧属性丢失不能靠宽泛匹配恢复 |
| 修改 OpenWork 过滤或输入框 | 当前范围外：已有过滤可以复用；IME 单独留待上游修复或版本升级 |
| 批量重写旧历史和标题 | 不采用：来源不可无损重建，增加误改与回滚成本 |

新增存储字段使用可选默认。旧 reader 是否安全读取新记录必须实际验证；降级忽略展示注解后可能重新显示辅助文字，不是功能等价。回滚保留会话卷、原始 JSONL 和既有回退事件语义；不删除记录规避兼容问题。
