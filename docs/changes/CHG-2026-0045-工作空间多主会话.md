## 目的与边界

同办公室支持独立主会话并行，保留原单绑定数据，按会话区分人物、工具、审批和只读详情。共享实际目录及服务器模型配置；刷新续看，重启中断而不自动执行。只读分析后登记以下范围，沿用既有 Runtime/Store 和权限策略。

主集成工作区的规格、执行范围和证据可更新。main 仅允许 ConnectedOfficeWorkspace.tsx 的已授权创建接线和 officeCreation.test.mjs、integration-e2e/office.spec.ts 两个现有测试；不改其他 main 源码、gateway 或样式。Core、Engine、Store、protocol/events/approval/runtime、Cargo/lock/CI 不改：既有引擎支持多 Session 并发，缺口在 Host 办公室映射。用户 README 本地修改保留，不纳入提交。不新增服务、容器常驻依赖或模型权限。

## 接口和数据

复用 POST /api/pawoffice/workspaces 的 name/201 快照与 POST /api/pawoffice/chat 的 send/history/resume/cancel；请求字段和响应流不变。取消“一空间一主会话”的临时拒绝，保留同会话活动回合保护与 turnId 幂等。目录仍与实际工作目录一一对应，主会话和子会话历史由 Runtime/Store 唯一写入。

在现有办公室记录中兼容增加会话集合，旧绑定原身份原名称保留；新增会话独立快照和标题。聚合出站办公室版本随任一会话事实单调前进；每个动作、审批和详情都明确会话归属。先记录事实再投影，Office 离线不改变 AgentLoop 结果。标题沿用 main 首条消息合并空白后 UTF-16 前36位，不改 OpenWork 命名。

替代方案：只删除409会串用办公室人物/审批和详情；逐会话新办公室会混淆目录且消耗办公室容量；逐会话目录或修改main聊天结构超出已确认需求，均不采用。
