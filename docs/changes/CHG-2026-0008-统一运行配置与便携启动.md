# CHG-2026-0008：统一运行配置与便携启动

## 先说结论

本变更统一 OpenPaw CLI、Host 与 Kunlun 启动脚本的配置来源和优先级，使真实 provider 能从受控环境或 `.env` 加载，并在缺少密钥或地址非法时明确失败。它不修改 Host HTTP 路由、AgentLoop 或 Office 动作协议，也不允许把真实密钥写入 Git。历史实现和测试已有记录，但正式跨仓库 PR、CODEOWNER 审核和本次复测仍待完成。

## 2. 变更原因

原 CLI 将 Host 和 chat 的 provider 默认写死为 mock，启动脚本只继承当前终端环境。即使 OpenPaw 根目录存在本机 `.env`，进程也可能进入回显或模拟模式；固定同级目录假设还会使 Windows/Linux 移植失败。配置必须有单一优先级、明确来源、脱敏诊断和可验证的失败语义。

## 9. 影响、数据流和实现

### 影响分析

CLI 和脚本启动行为会读取统一配置来源；显式值仍最高优先。密钥只进入 provider 进程内存，配置显示仅输出“已配置”。默认 feature 和 HTTP 协议不变。新增 dotenv 依赖必须通过锁文件和默认依赖树验证。启动时解析一次，不提供热更新，避免多线程运行期间改变全局环境。

### 数据流和失败路径

```text
CLI flag -> process env -> selected .env -> safe defaults
    -> provider/model/base URL validation
    -> OpenPaw Host/chat + Gateway/Vite child process environment
    \-> missing key or invalid URL -> Chinese error + non-zero exit
```

dotenv 不覆盖已经存在的进程变量。脚本自定义 Web 端口只追加到允许来源，不改变 Gateway 响应字段。

### 实现方案和选择理由

选择单一解析模块和两种平台脚本共享同一优先级，而不是在每个子命令中重复读取环境。没有把密钥写入项目配置或命令输出，也没有在非法自定义地址时回退到公共服务，以避免意外泄密和不可诊断行为。
