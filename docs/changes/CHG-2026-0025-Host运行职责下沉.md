## 2. 推荐职责边界

| 归属 | 推荐承担 | 调用方/必须保留的边界 |
| --- | --- | --- |
| Engine 的独立 scheduler 模块 | 有界 FIFO 接收、排队取消、运行 permit 和释放 | 接受中立容量参数；Host 保留环境配置；不把全局队列加进 AgentLoop |
| Engine 的独立 turn_execution 模块 | 调用现有 AgentLoop、执行前完整 Session 快照、错误/panic 恢复 | 只接受 Core/Engine 类型、Provider、取消令牌和事件回调；Q2 已确认 CLI 与 Host 共同接入 |
| Store | JSONL 写入事务、长度快照/回滚、writer 失效管理、损坏尾行修复、历史重放和变更投影 | 同步独占 writer，不 await；目录只读 API 不隐式修复或关闭回合 |
| Host | HTTP/SSE、鉴权、外部错误字段、Office 投影、会话表/协调锁、接收与发布顺序、服务关闭和恢复触发策略 | 通过 Engine 执行、Store 提交；成功落盘后才发布内存快照和终态 |
| CLI | 终端输入、审批交互、输出与 SQLite 搜索索引刷新 | 共用适用的执行与持久化能力；单会话串行入口不必创建全局 FIFO |

Engine 不依赖 Host、HTTP、Office 或终端，也不因本次抽取新增对 Store 的依赖。
Store 不执行模型和工具。Host 的接收线性化锁及协议级真实性检查仍在 Host；本轮没有
将整个 AppState 或 SessionHandle 迁出的推荐。

## 3. 分批实现范围与具体符号

### 3.1 持久化类型与历史投影统一

- Host `protocol.rs` 的持久化 Turn/Admission/Accept/Finish 类型与 Store 已有对应类型。
  验证 serde 字段一致后复用 Store 定义，必要时保留原 Rust 路径的 re-export。
- Host `session_mutation.rs` 的变更 DTO/投影复用 Store；删除经 JSON 往返转换的桥接。
- `restored_session_projection` 直接消费 `Transcript`；实时 Revert 与重放共用已有
  `retained_user_message_ids` / `retain_turn_state_for_messages` 过滤规则。
- Host 公共错误占位的真实性检查和外部展示字段仍由 Host 校验/适配，不让仅有格式正确
  的伪造 assistant ID 获得回退权限。

### 3.2 Store 写入与恢复基础机制

- 迁出 `persist_finish_transaction`、`writer_snapshot`、`truncate_session_file`、
  `restore_writer_snapshot`、`repair_torn_session_tail` 的文件操作。
- `retry_persist_turn_outcome` 的 rollback/reopen/retry 委托共享 journal；Host 保留
  `persistence_failed` 分类及失败时内存状态闭合。
- `recover_orphaned_turns_in_file` 委托 Store 读取、修复、重放和打开 writer，Host 保留
  孤儿回合终态策略、`host_restarted` 文案及何时触发恢复。
- 共享写入接口在同一 writer 独占临界区内完成 snapshot → append → rollback。
  rollback 失败时 writer 失效并拒绝继续写入，保留现有 fail-closed 行为。
- JSONL 的 type、字段、prepare/commit 顺序和 fsync 语义不因内部所有权迁移改变。

### 3.3 Engine 调度与受保护执行

- 迁出 `SchedulerState`、`QueuedEntry`、`TurnScheduler`、`ScheduleError`、
  `TurnAdmission`、`TurnPermit`、`QueuedTurn`。Host 保留默认 4/32、容量校验范围和环境读取。
- 提取 `run_turn` 内的完整 Session checkpoint、catch_unwind 和错误还原包装，
  调用 AgentLoop 既有入口，不把 Host SSE/Office/JSONL 提交加入 AgentLoop。
- `accept_turn` 继续协调幂等检查、同 session gate、Engine admission、Store 首状态提交。
- `run_turn` 继续协调协议投影与事务；模型执行委托 Engine，文件提交委托 Store。
- `TurnCleanup` 的执行快照能力与 Host 活动状态/Office 清理明确分开；取消及 future drop
  按 Q4 明确授权恢复完整 Session，不把故障修复冒充无行为变化的机械迁移。

### 3.4 Store 历史变换与 Fork 文件发布（Q5 已确认纳入本轮）

纯 `normalize_revert_boundary`、`failed_message_prefix_len`、Fork 消息引用重键，
以及临时文件写入、fsync、rename、重开/失败清理和分支序号扫描可迁入 Store。
Host 保留活动冲突检查、外部 ID 校验、Agent/Tool 构建、会话表登记和 SSE 发布。
用户已确认本轮完整迁移，并允许 Store 预算按实际职责规模调整。
Fork 重键采用 workspace UUID 的现有生成规则，登记 Store 依赖边；最终预算在实施后实测。

## 5. 已收敛的设计树与授权记录

已确认事实：AgentLoop 属于 Engine；模型执行循环已共享；Store 已有 replay/DTO；
Host 仍有重复类型和文件操作；FIFO 可独立于 Host；CLI 的 SQLite 是索引，JSONL 是会话记录。

第一轮问题与用户回答：

1. Q1：是否保持现有聊天、审批、取消、Revert、重启恢复和外部接口行为，仅调整职责？
   用户已确认“是，保持现有行为”，2026-10-13。迁移以行为兼容为边界，独立发现的
   ToolResult 漏存不能默认为已授权修复；完整快照恢复差异随后已获 Q4 明确补充授权。
2. Q2：CLI 是否同时接入迁出的适用执行/失败保护能力，还是先迁 Host？
   用户在解释后明确回复“是”，2026-10-13，已确认共同接入适用的执行与存储能力。
   候选为 Engine 的执行包装（快照、调用现有 AgentLoop、按明确策略处理错误/panic）
   及 Store 的消息提交能力。Provider、工具执行、审批核心已经共享，不是 Q2 要新增
   的功能。CLI 的单会话串行交互不接入 Host 多会话队列、HTTP/SSE 或 Office。
   行为兼容约束优先；两个入口故障策略存在差异时，先保留原策略并明确公共接口，
   不把共同接入解释为自动改变 CLI 错误退出或取消/持久化失败语义。

- Fork 重键复用 workspace UUID：该包已在仓库依赖树使用，Store 只新增明确依赖边，

- 设计理解达成后收敛最终具体批次与实施清单；未回答问题不按默认选项当作批准。

## 6. 接口、状态和并发不变量

- 新共享 Rust API 已登记在下表，新增公共函数/方法使用八栏目中文 Rustdoc。
- HTTP 路由、JSON 字段、错误码、SSE 顺序、JSONL/SQLite 格式及外部模型配置维持当前合同。
- 接收顺序保持：同 session gate 内幂等/活动检查 → scheduler admission → 持久接收事实
  → 发布输入与启动任务；重复 request 不产生第二次模型调用。
- 完成顺序保持：提交持久消息和 terminal → 原子发布 messages/outcome/error 快照
  → 协议终态和 idle；Office 失败不改变结果。
- 默认 CLI 依赖树不含 Axum；Engine/Store 不能导入 OpenCode/Office/终端适配类型。
- 取消/晋升/future drop 释放 permit，不泄漏容量；单 session 不并行活动回合。
- Store API 接受调用方独占 writer；本轮不宣称支持 CLI/Host 跨进程同时写同一 session。

| 所有者 | 共享 Rust 接口 | 调用及状态责任 |
| --- | --- | --- |
| Engine scheduler | `SchedulerLimits`、`TurnScheduler::new/admit/queue_position`、`TurnAdmission::is_queued/queue_ticket/wait`、`TurnPermit/QueuedTurn/ScheduleError` | Host 转换已校验容量；Engine 只持有容量与 FIFO，凭据 drop 自动释放 |
| Engine turn_execution | `SessionCheckpoint::capture/restore`、`TurnOptions`、`TurnExecution`、`run_turn` | 两端接收输入后捕获；异常/取消/drop 恢复完整 Session；成功返回可用于提交失败恢复的检查点 |
| Store journal | `snapshot/restore/append/append_messages/finish/append_with_retry/read_repaired/publish` | writer 独占同步事务；失败回滚、回滚失败失效；显式重开先修复尾行并验证重放 |
| Store transcript | `retain_turn_state_for_messages/normalize_revert_boundary/failed_message_prefix_len/clone_messages_for_fork` | 纯历史与身份变换；公开错误占位真实性和活动冲突仍由 Host 验证 |
| Store catalog | `next_fork_ordinal` | 调用方持有创建闸门；读取复用身份、路径及目录安全校验 |

Host 沿用原持久类型 Rust 路径的 re-export，删除重复 DTO 和 JSON 往返转换。
单事件写入的快照、追加及回滚只在 Store 的一次 writer 独占临界区内完成，Host 不重复回滚。
