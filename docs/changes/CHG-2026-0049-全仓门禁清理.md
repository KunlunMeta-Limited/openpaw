# CHG-2026-0049：全仓门禁清理

status=approved / 2026-10-26 用户明确授权清理 scrub 命中、修复 Clippy 警告并调整行数预算，要求保存一个本地提交。

## 原因与范围

当前 `feature/adjust-v2` 的功能测试、格式检查和 Host 自身检查已通过，但全仓 Clippy、scrub 和行数门禁仍失败。用户授权本次只做行为不变的工程门禁修复，不改变 Office、聊天、会话、审批或工作区创建合同。

## 实施内容

- 将 Clippy 要求的格式参数改为内联捕获，删除常量已知非空的冗余断言；字符串结果和错误类型保持不变。
- 将测试证据中的内部任务编号、内部记录名和内部文档文件名改为公开描述；不放宽 scrub 规则。
- 按当前实测规模调整行数上限：Host 业务代码 `7,000 → 13,500`，辅助代码 `11,500 → 12,500`，Host 测试 `4,000 → 5,000`。预算计数方式不变，仍由 `xtask lines` 严格执行。

## 验证与回滚

已执行 `cargo fmt --all -- --check`、`git diff --check`，并用与 `xtask scrub` 相同规则复核全仓，结果 clean。Windows 环境缺少 `link.exe`，无法在本机链接 Cargo 二进制；此前 Linux 工具容器中的测试结果保持通过。提交回滚只需撤销本变更提交，不涉及数据迁移或运行服务。
