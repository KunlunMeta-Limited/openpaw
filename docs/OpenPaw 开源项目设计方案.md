## 执行摘要

本方案提议从 FreeAgent（约 29.8 万行 Rust / 40 crates / 6,067 项测试，2026-08-30 实测）中拆卸出一个轻量化开源项目 **OpenPaw**（**定名**，同名共存防御战略见 §1），核心主张：

- **体量**：40 crates → **9 + 1 + 1 + 1 crates**（核心 9 + Reflect-Lite 幼脑 + 引擎位兼容层 + 目标存折），目标总上限 ≤ 6.9 万行 Rust（口径定义见 §3.3），冷构建 < 5 分钟，零重型依赖（无 V8、无默认嵌入模型）。
- **定位**：**自进化 Agent 的开源实验场**——一个内核极小、接口全开、专为社区贡献者重塑而设计的 Agent 内核。
- **Sidecar 引擎模式 + OpenWork 引擎位**：**OpenWork 可作为 OpenPaw 的客户端使用 OpenPaw 的能力**，双通道进场——① **E6 Sidecar**：`openpaw --sidecar` 以标准 MCP 服务器身份拉起本地端点，OpenWork 及任意 MCP 客户端作为客户端接入调用（协议级拥抱）；② **E8 引擎位**：OpenWork 与 OpenCode 为解耦架构（客户端宿主 + 可替换引擎），OpenPaw 以 `openpaw --engine-host` 兼容 OpenCode 的**公开引擎接口**坐进引擎位——**OpenWork 桌面端由此成为 OpenPaw 的图形客户端，OpenPaw 保持零 GUI 代码**（[待验证]，见 §4.5 域 E8 / §8 验证关卡）。团队技能与共享网关为我所用，OpenPaw 的进化与记忆能力反哺整个团队工作流。**协议级拥抱、产品级不绑定、引擎位即客户端**：对 OpenWork 私有 API 永不触碰，不开私有适配的倒车（§4.5 域 E / §7.10.3 防线五）。
- **核心机制**：**进化引擎闭源为增值，进化策略接口开源为苗圃**。FreeAgent 的自进化闭环（微反思/全量反思/策展器）保留为商业专有；OpenPaw 内置开源轻量大脑 **Reflect-Lite**（三步最小闭环，§4.3 决策四）开箱即能进化，并开放 `EvolutionPolicy` 等策略接口，让社区自由实验"Agent 如何进化"这一命题——**幼脑开箱即用，成年大脑只在闭源侧，差距是定性代差**。
- **战略落点**：这是 KunlunMeta「开源筑基，自研增值」原则在 Agent 侧的落地——GPT-Station 定位「跑 OSS Agent + FreeAgent」，OpenPaw 正是那个 OSS Agent 座席的官方答案，同时构成 FreeAgent 的人才漏斗、路线漏斗与品牌漏斗。
- **信任底座**：默认零遥测（§7.12）——知识文件 100% 本地、不设开源侧云账户、错误报告自愿匿名；防线的源码与数据政策同日开源，**社区不仅能审计代码，还能审计"我们没有偷偷看什么"**。

一句话：**FreeAgent 是产品，OpenPaw 是苗圃；社区在苗圃里种出的最好路线，将毕业为 FreeAgent 的下一程。**

## 1. 命名定案与同名共存防御战略（P0 决策项——已决策）

**结论先行：命名已定案为 OpenPaw。** 尽管检索显示该名已有占用（见 §1.1），经决策评估：**"OpenPaw" 的名字资产——Paw 意象与母项目"猛兽与幼爪"的血缘暗示、Open 前缀的开源正统性、双音节全球可读——大于同名冲突的代价**；冲突可通过差异化定位、命名空间占位与发布节奏管理对冲（§1.2–1.4）。本节同时保留风险事实，作为对外质询时的应答口径。

### 1.1 同名项目盘点（事实基础，2026-08-27 检索）

| 同名项目 | 性质 | 冲突等级 |
|----------|------|----------|
| Flexasaurusrex/**OpenPaw** | **OpenClaw 的 fork**，14,274 commits，自称 "security-hardened, personality-forward fork of OpenClaw"，配套 PawHub 技能市场、Telegram/Discord/WhatsApp 接入 | **高——正面撞车** |
| OrigoZero/OpenPaw | Rust 编写的 AI Agent 框架（Coming Soon），含持久记忆、动态技能、MCP、沙箱 | 中 |
| daxaur/openpaw | Claude Code 多技能个人助手（38 种技能，本地化运行） | 中 |
| sucxay/OpenPaw | Python 终端 AI 编程助手（OpenAI 兼容 API） | 低 |

关键事实：由于 OpenClaw 生态在 2026 年初的改名与分叉事件，"OpenPaw" 在开源社区中已被广泛认知为 **OpenClaw 系项目名**。而本方案 §9.5 竞品坐标系已将 OpenClaw 列为竞品（《FreeAgent 技术白皮书》v0.1.1 未点名竞品）——因此，沿用此名意味着必须正面管理三重风险（对冲手段见 §1.2–1.4）：

1. **品牌混淆**：被解读为蹭 OpenClaw 生态热度，损害 KunlunMeta 技术原创性形象；
2. **检索与包名冲突**：GitHub / crates.io / npm 搜索与安装均冲突，社区可发现性受损；
3. **商标与法务风险**：先占项目具备在先权利主张基础。

### 1.2 防御战略一：差异化叙事锚点——「正名宣言」

同名项目（尤其 OpenClaw fork）占据的是"名字"，我们占据的是**叙事与工程事实**。对外发布时以一条**正名宣言**作为命名质询的标准应答，把"为什么也叫 OpenPaw"从尴尬问题转化为立场表达：

> **正名宣言**（发布文案与 README 首屏引用）：
> "Paw 属于每一只想长大的幼兽。OpenClaw 系的 OpenPaw 是一个既存分叉；而这里的 OpenPaw 是**从生产级自进化 Agent FreeAgent 拆卸出的独立内核**——不属 OpenClaw 系，与其无代码血缘、无共同维护者。我们与同名项目唯一的共同点，是都相信 Agent 应该属于用户。"

该宣言的三个功能：

1. **切割血缘**：一句"无代码血缘、无共同维护者"正面排除蹭生态解读；
2. **建立血统**：把命名故事锚定在"FreeAgent 拆卸"这一独占事实上——任何同名项目都无法复制的叙事；随着工程事实积累，"OpenPaw" 的检索结果将被逐步改写；
3. **抢占道德位**：不指责、不回避，以"共同点只有信念"的姿态占据社区好感。

### 1.3 防御战略二：命名空间占位矩阵

**原则：代码与渠道包名可以共存，但"官方名"必须唯一且无从混淆。** 所有占位动作集中在 Phase 0 完成：

| 占位点 | 目标态 | 占位理由 |
|--------|--------|----------|
| GitHub org + repo | `openpaw` org 下的 `openpaw`（或 `kunlunmeta/openpaw`） | 与同名项目物理区隔；org 名即身份 |
| crates.io | `openpaw`、`openpaw-core`、`openpaw-engine` 等 12 个 crate 名（核心 9 + 幼脑 1 + 引擎位 1 + 存折 1） | 若已被占用，则采用 `openpaw-kernel` 系列 + 文档显著声明 |
| npm / PyPI | `openpaw`、`@openpaw/cli` | 面向 JS/Python 生态的桥接包占位 |
| 域名 | `openpaw.dev`（主）+ `openpaw.ai`（重定向） | 官网独立于同名项目 SEO |
| 文档站 | docs.openpaw.dev | 正统文档锚点 |
| 社交/社区 | X、Discord、Reddit r/openpaw（若存在则协商） | 社区主阵地唯一化 |

**包名冲突的降级预案**：若 crates.io 上 `openpaw` 已被既有项目持有，则全线采用 **`openpaw-kernel` / `openpaw-agent`** 前缀系列，并在 README 首屏以正名宣言声明正统性——名字可以撞，身份不能撞。

### 1.4 防御战略三：发布时机策略

撞名环境下的发布不是"选个好日子"，而是"选个无法被淹没的叙事窗口"：

1. **首宣以"拆卸"为标题词**：发布标题定为《从 29.8 万行生产级 Agent 中，我们拆出了一个 9 + 1 + 1 + 1 crate 的开源内核》——让首波曝光绑定"FreeAgent 拆卸"这一独占事件，而非"又一个新的 OpenPaw"；
2. **T0 集中弹药**：GitHub + 官网 + Hacker News / Reddit / X 同步首发，首周内完成 9 + 1 + 1 + 1 crates 全部占位包的 `cargo publish`（空壳版亦可；engine-host 占位包随 Phase 2 验证关卡放行），让 crates.io 搜索页第一屏出现"连续 12 个 openpaw-\*"的矩阵效应；
3. **绑定母项目叙事带流量**：FreeAgent 白皮书、GPT-Station 发布渠道同步引用 OpenPaw，用母项目既有声量稀释同名项目的搜索权重；
4. **不做负面对比**：所有官方物料不点名、不影射同名项目——正名宣言是唯一一次"正面回应"，此后只用工程事实说话。

### 1.5 否决记录与残余风险声明

**否决记录**（决策过程留痕，防止未来复议时重复论证）：

| 原候选 | 否决理由 |
|--------|----------|
| FreePaw | 失去 "Open" 前缀的开源检索正统性；FreeAgent/FreePaw 双 Free 易生母子混乱 |
| CubAgent / OpenCub | 幼崽意象依赖解释，国际语境辨识度弱 |
| PawKit | 工具箱感强但弱化 Agent 血统 |
| MetaPaw | 企业色彩过重，损害社区中立性 |

**残余风险声明**（定名 OpenPaw 后仍无法消除、需长期管理的风险）：

| 残余风险 | 等级 | 长期管理手段 |
|----------|------|--------------|
| 与 OpenClaw fork 持续共享搜索词，SEO 长期互耗 | 中 | 正名宣言 + 域名/文档站独立 SEO + 工程事实持续积累 |
| 先占项目的潜在商标主张（若其完成注册） | 低-中 | Phase 0 法务检索确认在先权利范围；KunlunMeta 在主营业务类别完成自有注册 |

| 未来 OpenClaw fork 项目更名/衰落时的"名存实亡"窗口 | 低 | 无需动作——搜索权重自然向我方迁移 |

## 2. 战略定位：为什么拆卸

### 2.1 三个动因

**动因一：体量即门槛。** FreeAgent 的约 29.8 万行代码、40 个 crate、deno_core（V8）与 fastembed 等重依赖，对社区贡献者意味着数小时的构建等待与数周的架构理解成本。开源社区的创新密度，与项目的**可理解半径**成正比——看不懂的代码无人贡献。

**动因二：战略座席空缺。** KunlunMeta 的既定战略是「开源筑基，自研增值」：GPT-Factory 跑 OSS 模型 + BaiZe 自研矩阵；GPT-Station 跑 **OSS Agent** + FreeAgent。GPT-Station 的"OSS Agent"座席目前没有官方答案——OpenPaw 正是为填补这一座席而生，并可同时作为五层硬件矩阵（尤其 AI PC 与 Pocket Agent Gateway）上 Agent 能力的**参考实现**。

**动因三：赛道卡位。** 两大竞对各有结构性缺口：OpenClaw 生态活跃但**技能需手动维护**、进化缺位；Hermes 全自动进化但**缺一道人对齐的护栏**。"进化策略实验场"这一生态位目前无人占据——谁开放了"Agent 如何进化"的实验接口，谁就拥有这条赛道的话语权。

### 2.2 OpenPaw 的三重角色

| 角色 | 服务对象 | 价值 |
|------|----------|------|
| **社区创新苗圃** | 全球开发者、研究者、学生 | 一个小到一周读完、开放到任你重塑的 Agent 内核 |
| **端侧参考实现** | GPT-Station 硬件生态 | AI PC / Pocket Gateway 上可运行的轻量 Agent 基线 |
| **FreeAgent 上游漏斗** | KunlunMeta 自身 | 人才漏斗（贡献者→招聘池）、路线漏斗（实验→毕业→产品化）、品牌漏斗（开源口碑→商业信任） |

### 2.3 与 FreeAgent 的关系：同源双轨

| 维度 | FreeAgent（商业） | OpenPaw（开源） |
|------|-------------------|-----------------|
| 定位 | 生产级自进化 Agent 产品 | 轻量自进化 Agent 实验内核 |
| 代码量 | 约 297,700 行 / 40 crates（39 个 workspace 成员 + 1 个测试基建 crate，2026-08-30 实测） | 目标总上限 ≤ 69,000 行（核心 9 crates ≤ 5 万 + Lite 3 千 + Sidecar 2 千 + 引擎位 2 千 + 目标存折 2 千 + 测试辅助 1 万，口径见 §3.3） |
| 自进化 | 完整闭环（微反思+全量反思+策展器） | Reflect-Lite 幼脑（三步最小闭环）+ Null 策略 + 社区策略接口 |
| 浏览器引擎 | 自研 Rust 无头浏览器（CDP/V8） | 无（社区经 MCP 提供） |
| IM 网关 | 飞书/钉钉/企微/微信/QQ 五大平台 | 无官方网关（PlatformAdapter trait 开放，社区做插件） |
| 知识资产 | Skill Hub 市场 + 团队记忆同步 | 本地技能/记忆文件格式（100% 兼容） |
| 界面 | CLI / TUI / 网关 / ACP（GUI 已删除，两侧均无） | CLI 优先（经 E8 引擎位借 OpenWork 得图形客户端，[待验证] 以 Phase 2 验证关卡为准） |
| 治理 | KunlunMeta 产品路线 | 社区 RFC + 毕业机制 |

两者共享同一套**知识文件格式**（Markdown + YAML frontmatter）与核心 trait 语义——用户在 OpenPaw 里积累的记忆与技能，可无损迁入 FreeAgent；这是"开源筑基、商业增值"最优雅的衔接点。

> 功能级的逐项对比（六大能力域 45 项）见 §4.5 功能对比总表；边界判定原则见 §4.4 边界总纲。

### 2.4 思想承接：OpenPaw 是 FreeAgent 思想的正式载体（灵魂三传 + 世界观一传）

前三节回答了"为什么拆、拆成什么角色、与母项目是什么关系"；本节回答一个更根本的问题——**拆卸拆走的是代码，还是思想？** 本方案的回答：代码只是形态，思想才是本体。OpenPaw 承接的不是 FreeAgent 的功能子集，而是 FreeAgent 作为产品的思想资产，并以此作为整个项目的"存在理由"条款——**§9.5 的 13 条主张回答"开发者为什么来"，本节回答"OpenPaw 为什么在"。**

#### 2.4.1 承接什么：灵魂三传 + 世界观一传

**FreeAgent 的世界观**（转译自《FreeAgent 技术白皮书》v0.1.1（2026-08-23）§2.1 三大痛点：无状态遗忘 / 黑盒不可控 / 生态割裂——v1.5 起引用锚与实际版本对齐）：AI 竞赛正从「能力竞赛」进入「信任竞赛」——用户真正焦虑的不是模型不够聪明，而是**它不记得我、它不可被审视、它把我锁死**（"信任竞赛论"为本方案对白皮书三大痛点的开源侧升维命名，待白皮书后续版本定稿后回钉原文）。OpenPaw 完整承接这一世界观判断，并将其从商业论证升级为开源宣言：三大焦虑，以免费开源、全程可审计的方式逐一拆解（记得 ← §4.5 域 C 全量对齐；可审视 ← 代码与数据政策双开源；不锁死 ← 格式兼容 + 模型中立 + 商标独立于代码）。

**三大产品灵魂，以代码物证逐条转译**：

| 产品灵魂 | 在 FreeAgent 中的含义 | 在 OpenPaw 中的承接形态（代码物证） | 对应守护条款 |
|----------|----------------------|--------------------------------------|--------------|
| **自进化（Self-Evolving）** | 越用越聪明，知识跨会话累积 | `EvolutionPolicy` trait + Reflect-Lite 幼脑（开箱即进化）+ 社区策略接口 + D8 进化数据格式兼容 | §6.1 / §4.3 决策四 / §7.4 毕业判定 |
| **用户主权（User Sovereignty）** | 知识可审计、可编辑、可撤销，写入必经人点头 | `requires_human_alignment` 底线签名 + Markdown/YAML 纯文本知识文件 + 默认零遥测 + 数据政策同仓开源 | §6.1 / §4.4.2 硬边界 / §7.12 |
| **开放生态（Open Ecosystem）** | 多模型多平台多工具，永不锁定 | 24 HookPoint + 模型中立（A5/A6）+ PlatformAdapter trait + 知识格式 100% 兼容 + E6 Sidecar / E8 引擎位开放接入 | §6.2 / §4.5 域 A / §4.5 域 E |

转译遵循一条总纪律——**每个灵魂的承接口径必须可回指到具体章节，与 strategymeta 同受 ADR 纪律约束；承接是工程事实的陈述，不是情怀修辞**。

#### 2.4.2 思想承接的三大机制

思想不能只靠宣言存活，须有机制保障它不随版本迭代稀释：

1. **毕业机制 = 思想的回流通道（§7.4）**：社区实验进入 FreeAgent 产品路线的判定标准第三条即"与三大产品灵魂的一致性"——**思想是毕业的门槛，不止是 README 的引言**。贡献者带着与三大灵魂同构的价值观进入，毕业的代码反向强化灵魂本身；
2. **边界宪法 = 思想的不可让渡条款（§4.4）**：五条硬边界中四条是三大灵魂的直接代码物证——进化边界守"自进化"（策略接口永远开放竞争）、人类对齐边界守"用户主权"（覆写只能更严不能放松）、格式与入口边界守"开放生态"（来去零锁定、多平台自由接入）；第五条商标边界守其外层前提：品牌中立与同名共存防御（§1.3）。**硬边界的"硬"，本质是思想的不可让渡**；
3. **信任底座 = 世界观的兑现（§7.12）**："零遥测、不设云、知识文件全本地"三军规，把"它不可被审视"的焦虑在开源侧以最强形式拆解——**社区不仅能审计代码，还能审计"我们没有偷偷看什么"**（§7.12 镜像条款：防线与数据政策同日开源）。

#### 2.4.3 可证伪承诺：思想承接不是免检金牌

思想声明若无证伪条件，就是营销。本节承诺接受以下三个证伪条件，任一触发即视为思想承接失败，须在《边界白皮书》（§7.6 防线四）中公开复盘：

| # | 证伪条件 | 触发后果 |
|---|----------|----------|
| F1 | 社区健康看板（§7.9）中，三大灵魂对应指标连续两季恶化（如"用户主权"对应指标恶化：非组织 PR 占比、`unverified` 产物占比等） | 边界裁决会启动灵魂守护失效复盘，修订守护条款或公开承认承接失败 |
| F1′ | 恶意插件事件（§7.10 T1）实际发生且防线的开源审计未能提前预警 | 安全纪要公开复盘防线失效根因，防线升级方案走 RFC |
| F2 | 毕业评审连续两年以"灵魂一致性"以外的理由否决全部社区毕业候选（与 §7.9 红线一"独角戏"联动判定） | 承认"灵魂"沦为否决工具而非创作坐标——标准失效，须 RFC 重订 |

**这三条证伪条件本身入 strategymeta，与 §7.9 看板红线联动巡检**——思想承接因此不是一次性的发布会修辞，而是**每季度可检验、可复盘、可问责的常设纪律**。

#### 2.4.4 一句话口径（入 strategymeta 与对外物料）

> **"OpenPaw 拆下的是 9 + 1 + 1 + 1 个 crate，装进去的是 FreeAgent 的全部灵魂——自进化、用户主权、开放生态，每一个都以代码物证的形式在开源侧活下来，并接受社区检验。"**

配套对外纪律：本口径与 §4.4.4 一句话边界并列使用，禁语纪律同样适用——**禁止把思想承接表述为"OpenPaw 继承 FreeAgent 的伟大愿景"类空泛修辞，所有承接表述必须可回指到具体条款**（§2.4.1 表格四列即标准回指格式）。

## 3. 产品定位

### 3.1 一句话定位

> **一个 9 + 1 + 1 + 1 个 crate 的自进化 Agent 内核——幼脑开箱即转，存折记得托付，小到一周读完，开放到任你重塑。**

### 3.2 三大设计原则

三大设计原则是三大产品灵魂（§2.4）在工程侧的直接投影——**灵魂决定原则，原则约束代码**：

- **小内核（Small Core）**：核心只做三件事——跑 Agent 循环、管知识文件、开扩展接口。其余一切皆可插拔。**（承接"开放生态"：小是开放的前提，看不懂的代码无人贡献）**；
- **开放进化（Open Evolution）**：进化不是黑盒特权，而是一组公开 trait。社区可以 implements 自己的进化哲学，与 Hermes/OpenClaw 的路线正面竞争。**（承接"自进化"：把产品灵魂升维为社区命题）**；
- **实验友好（Hacker-Friendly）**：5 分钟构建、5 分钟上手；每个扩展点都有可运行的最小示例；文档第一性。**（承接"用户主权"：开发者的时间主权与理解主权，是用户主权的开发者侧镜像）**——DX 有专属工程体系（§6.4）、硬指标（§6.4.6）与看板红线（§7.9），任何 PR 合并前须回答"它让第几级漏斗变好还是变坏"。

### 3.3 "三个五"工程指标

| 指标 | 目标 |
|------|------|
| 冷构建时间 | < 5 分钟（含零重依赖） |
| 上手时间 | < 5 分钟（cargo install → 配 API key → 跑通首轮对话） |
| 核心代码量 | ≤ 5 万行（不含测试与生成代码） |

**行数口径定义（单一事实源，strategymeta 引用本条）**：

- **核心 ≤ 5 万行**：9 个核心 crate 的手写业务代码（不含测试、生成代码与注释折算）；
- **总上限 ≤ 6.9 万行**：核心 5 万 + 测试与辅助 1 万 + Reflect-Lite 幼脑 3 千（Lite 单列红线，见 §4.3 决策四）+ Sidecar 引擎模式 ≤ 2 千（`--sidecar` MCP 服务器封装，§4.5 域 E6）+ 引擎位兼容层 ≤ 2 千（`openpaw-engine-host`，OpenCode 公开引擎接口替身，§4.5 域 E8）+ 目标存折 ≤ 2 千（`openpaw-goal-ledger`，RunLoop-Lite，§4.5 域 A9 / §4.3 决策五）——四者均单列红线同 Lite 纪律：超限回滚走 ADR；
- 全文出现的"≤ 6.9 万 / 69,000"均指总上限口径，"三个五"中的 5 万专指核心口径——两口径换算关系以此为唯一解释；**总上限 = 5 万核心 + 1 万测试与辅助 + 3 千 Lite + 2 千 Sidecar + 2 千引擎位 + 2 千目标存折，六项相加恰好 6.9 万**，核心 5 万与测试 1 万承诺完整保留。

## 4. 拆卸策略：40 → 9

### 4.1 处置四分法

对 FreeAgent 的 40 个 crate 逐一裁决，归入四类：

1. **保留**（原样或近原样进入 OpenPaw）——架构灵魂与开放性所在；
2. **简化**（保留骨架、削减深度）——去掉重依赖与高级特性；
3. **剥离**（留在 FreeAgent，为商业增值）——重资产、企业特性、市场体系；
4. **开放接口**（引擎剥离、trait 留下）——把"闭源引擎"翻译为"开源插槽"。

### 4.2 逐 crate 处置映射表

| FreeAgent crate | 处置 | OpenPaw 去向 | 说明 |
|-----------------|------|--------------|------|
| `freeagent-core` | **保留** | `openpaw-core` | 25 个 trait 的地基（LlmProvider / ToolHost / ToolGuardrail / ApprovalManager 等；Session 为核心类型而非 trait），原样开放——这是整个生态的地基；`EvolutionPolicy` / `LongHorizonPolicy` 为本方案新增定义（§4.3 决策一 / 决策五），不是 FreeAgent 现存 trait |
| `freeagent-engine` | **保留** | `openpaw-engine` | AgentLoop、三阶段工具执行、上下文压缩、重试降级；含配置与 ContextSources（并入原 context 职责） |

| `freeagent-tools`（+fs/exec/web/meta） | **简化** | `openpaw-tools` | 19 个核心工具；bash-ast 安全分析并入；media/LSP 剥离为社区 feature |

| `freeagent-plugins` | **保留** | `openpaw-plugins` | 24 个 HookPoint——社区创造力第一现场 |

| `freeagent-tui` | **剥离** | —— | TUI 后续视社区需求以 plugin 形式回归 |
| `freeagent-context` | **合并** | 并入 `openpaw-engine` | 配置解析与 ContextSources 属引擎职责 |

> crate 口径注：OpenPaw 共 **12 crates（9 + 1 + 1 + 1）**——核心 9 + Reflect-Lite 幼脑 1 + 引擎位兼容层 1 + 目标存折 1。其中 `openpaw-engine-host`（≤ 2 千行，feature-gate 隔离，`openpaw --engine-host`）实现 **OpenCode 的公开引擎接口**（前提待验证，[待验证] 标记与 Phase 2 验证关卡见 §8），使 OpenWork 桌面端可作为 OpenPaw 的客户端直接驱动 OpenPaw 内核；`openpaw-goal-ledger`（≤ 2 千行，RunLoop-Lite 目标存折，`openpaw goal` 子命令）提供长程目标的档案 / 账本 / 续跑 / 留痕（§4.3 决策五）。行数预算：核心与测试 6 万 + Lite 3 千 + Sidecar 2 千 + 引擎位 2 千 + 目标存折 2 千 = 总上限 6.9 万（口径定义见 §3.3）。

**OpenPaw 最终 crate 清单（核心 9 个 + 幼脑 1 个 + 引擎位 1 个 + 存折 1 个，共 12 个）**：

```
openpaw-core          # trait：LlmProvider / ToolHost / EvolutionPolicy / LongHorizonPolicy / PlatformAdapter
openpaw-engine        # AgentLoop / 压缩管线 / 重试降级 / 配置
openpaw-llm           # 多 LLM 提供者 + 降级链
openpaw-tools         # 19 核心工具（fs / exec / web / meta）
openpaw-mcp           # MCP 客户端（stdio + Streamable HTTP）
openpaw-store         # JSONL + SQLite FTS5 持久化（含目标档案 / 账本存储）
openpaw-memory        # 记忆 + 技能（文件格式与 FreeAgent 兼容）
openpaw-plugins       # HookPoint 系统 + EvolutionPolicy / LongHorizonPolicy 装载

openpaw-reflect-lite  # 幼脑：官方参考进化策略（三步最小闭环，≤ 3 千行，§4.3 决策四）
```

### 4.3 关键决策论证

**决策一：自进化引擎为何"开接口、不开引擎"？**

FreeAgent 的白皮书 §20.1 将其归纳为四项核心价值，其中「自进化 + 用户主权 + 开放生态」三项构成本方案所称的护城河闭环；自进化闭环（微反思触发判断、质量门控 prompt 工程、策展器的置信度门控、相位信号系统）是数万行打磨出的工程资产——全部开源等于把护城河填平。

但"Agent 该如何进化"本身是一个**远未收敛的开放问题**（白皮书 §19.9 自陈六大局限：单 Agent 自进化、文本为主的知识表示、无规划能力的学习（被动反思）、无世界模型、无自我意识（元认知缺位）、LLM 依赖）。把问题开放给社区，把答案留在家里：OpenPaw 定义 `EvolutionPolicy` trait 与"写入必经用户审批"的底线，社区各显神通实现策略；FreeAgent 吸收毕业的最优解。**苗圃越热闹，良田越丰收。**

**决策二：浏览器引擎为何整体剥离？**

五个 crate + deno_core（V8）是全项目最重的依赖，冷构建以分钟计、二进制以数十 MB 计，与"三个五"指标根本冲突。且 MCP 生态已有成熟浏览器工具服务器——社区若需要，接入即可，无需自研重资产。

**决策三：知识文件格式为何必须 100% 兼容？**

这是双轨战略的**桥梁**：OpenPaw 用户养成的记忆与技能（Markdown + YAML frontmatter、九种记忆类型、技能五态生命周期），目录拷贝即可迁入 FreeAgent。开源版是"养成"，商业版是"投产"——迁移零成本，升级自然发生。

**决策四：为何内置一个轻量大脑（Reflect-Lite），而不是让引擎位继续空着？**

若引擎位空置（开箱即 NullPolicy，进化完全等社区），方案虽然纯净，但对新用户不友好——一个从没用过自进化 Agent 的人，第一次运行看到的是"什么都不会发生"，他要先读懂 trait 才能见到第一次进化。**完整内核 ≠ 完整体验**，这动摇 Q3 红线（"开箱即残废"质疑会从工具层转移到进化层）。

因此定案为**出厂自带幼脑**：OpenPaw 内置官方维护的开源简化进化引擎 **Reflect-Lite**（一个 crate，`openpaw-reflect-lite`）——"触发 → 反思 → 固化"三步最小闭环，纯规则驱动，零额外依赖，代码量控制在 ~3 千行以内。它回答"进化长什么样"，让用户第一天就亲眼看到知识文件变化；它不回答"进化能做多好"——那是留给社区策略与 FreeAgent 生产引擎的赛场。

**与闭源版的差距是定性的代差，不是定量的残缺**。Reflect-Lite 与 FreeAgent 生产引擎之间隔着四件不随 Lite 开源的东西，每一件都是数万行打磨的工程资产：

| 能力 | Reflect-Lite（开源幼脑） | FreeAgent 生产引擎（闭源成年大脑） |
|------|--------------------------|-----------------------------------|
| 触发智能 | 纯规则触发（单一固定阈值：轮数/错误数） | 多信号启发式触发矩阵（21 个中英文关键词 × 轮数 × 工具调用 × 输出长度）+ 空闲门控与冷却节流——规则式而非学习式，"时机选择"两侧共同留白（FreeAgent 自陈"被动反思"局限，§6.3 路线 1） |
| 质量门控 | 无——反思产物直接落盘 | 质量门控 prompt 工程（低质反思不污染知识） |
| 记忆策展 | 无——只追加，不合并去重 | 策展器（置信度门控 + 知识合并，防记忆膨胀与自我矛盾） |
| 相位信号 | —— 不存在 | 相位信号系统（进化阶段感知，D6 独占纵深） |

三条配套纪律，防止 Lite 越长越大、反噬决策一：

1. **规模红线**：Lite 定位"能读得懂的参考实现"，单一 crate、≤ 3 千行、零重型依赖——超限即拆出 Lite 范畴（CI 断言行数上限，与"三个五"同级别物证）；
2. **代差红线**：上表四件能力不进 Lite。若社区策略或 Lite 演化逼近生产引擎质量，触发 §4.4.3 既有裁决——**官方策略长期劣于社区策略，官方策略开源**；Lite 的质量上限写在明处，闭源正当性继续来自"官方做得最好"而非"官方藏得最深"；
3. **锦标赛基线**：策略锦标赛（§6.3 路线 1）的初赛基线即 Reflect-Lite——所有社区策略的第一场对手是它。**赢了幼脑只是入场，赢过成年大脑才谈毕业。**

一句话总结决策四：**NullPolicy 还在（想空转就空转），但出厂不再是空引擎位，而是一颗装好的幼脑——缺的是成年大脑，且"成年"的过程全世界都能围观和参与。**

两条 UX 兜底（与 §6.4.2 / §7.5 联动）：Lite 反思产物默认打 `unverified` 标记（区别于经用户审批写入的知识）；`openpaw evolve reset` 提供一键清空重建——**幼脑会犯错，且告诉你它错了，错了能一键反悔**。

**决策五：RunLoop（长程目标自动驾驶）如何拆解？——存折开源，大脑增值**

FreeAgent 新增的 RunLoop 把"交给 Agent 一个复杂目标"变成持久化的自动驾驶：目标拥有自己的档案（不随对话结束遗忘）、每日执行配额（预算用完降速挂起、次日续跑）、进度账本（做到哪了、花了多少随时可查）、停滞自动纠正（连续无进展注入重规划指令，反复无效才叫停）与全程审计留痕，配合 auto-resume 进入全自治——**从"一问一答的工具"变成"值得托付的同事"**。

对它过四问法（§4.4.1）：完整系统不命中 Q1（拿掉后 AgentLoop 主循环完整，仍称内核）、边缘沾 Q2（停滞纠正的重规划策略是可插拔智能）、弱命中 Q3（"跨会话遗忘"不构成开箱即残废，但**目标档案/账本格式若两侧不兼容会破坏知识互通桥梁**——决策三延伸）、Q4 分层命中（完整自动驾驶 > 6 人月可闭源；**极简存折 < 6 人月，按纪律必须开源**）。因此定案**三层拆解**：

| 层 | 归属 | 内容 |
|----|------|------|
| ① 格式层 | **同源件** | 目标档案 / 进度账本 / 执行日志格式 100% 兼容（决策三延伸：OpenPaw 里记的账，FreeAgent 接着记） |
| ② 策略层 | **开源接口** | `LongHorizonPolicy` trait（进 core）：停滞纠正、续跑节奏、叫停时机全部可插拔——社区可编程，接 §6.3 路线 6 |
| ③ 执行层 | **◐ 简化内置** | OpenPaw 内置 **RunLoop-Lite「目标存折」**（`openpaw-goal-ledger`，≤ 2 千行）：档案 + 账本 + 断点续跑 + 留痕四件套；`openpaw goal` 子命令与 `openpaw goal status` 可视化 |

**四件自动驾驶智能不进 Lite**（与 Reflect-Lite 代差四件同构）：每日配额智能管理、停滞自动重规划注入、并发保护调度、全自治 auto-resume。**代差一句话：OpenPaw 的 Agent 记得做到哪了（存折），FreeAgent 的 Agent 自己决定怎么做完（大脑）。** 配套三条纪律：规模红线（≤ 2 千行 CI 断言）、代差红线（四件智能不进 Lite）、格式同源（账本格式黄金用例入 §7.6 防线二）。

### 4.4 闭源/开源边界总纲（核心章节）

> 前文四分法回答了"40 个 crate 各去何处"；本节回答更根本的问题：**未来 5 年，每一行新代码该写在哪一侧？** 边界不是一次性拆迁决定，而是需要长期执行、可仲裁、可演进的"宪法条款"。

#### 4.4.1 判定四问法（每行新代码的速测）

任何新特性（FreeAgent 或 OpenPaw 侧）动工前，依次过四道闸门，**任一问命中即归开源侧**：

| # | 问题 | 命中 → 开源 | 理论依据 |
|---|------|------------|----------|
| Q1 | 拿掉它，项目还能不能叫"Agent 内核"？ | 不能 → 必须开源 | 内核定义性能力（循环/工具/MCP/记忆格式/存储）是开源承诺，不是恩惠 |
| Q2 | 它是"Agent 如何进化"这一开放命题的候选答案吗？ | 是 → 接口开源 | 未收敛问题交给社区竞逐（§4.3 决策一） |
| Q3 | 它的闭源是否会伤害社区信任或引发"开箱即残废"质疑？ | 会 → 必须开源 | 拆卸项目的生死线是"开箱完整可用" |
| Q4 | 它的可复制性 / 壁垒强度如何？ | 复制门槛 < 6 人月 → 开源 | 低于此强度的"闭源"守不住，闭了反而显得小气 |

四问全部不命中 → 归闭源（增值）侧。此判定由 §7.6 的"边界裁决会"执行，仲裁记录公开。

#### 4.4.2 三层边界模型

**第一层：硬边界（不可协商，写进 README 与 RFC 模板）**

| 边界线 | 开源侧（OpenPaw） | 闭源侧（FreeAgent 专有） | 边界的"物证" |
|--------|-------------------|--------------------------|--------------|
| **进化** | `EvolutionPolicy` trait、NullPolicy、**Reflect-Lite 幼脑（简化引擎，§4.3 决策四）**、进化数据格式 | 微/全量反思引擎完整实现、质量门控 prompt 工程、策展器、相位信号系统 | 策略接口与参考实现开源、生产引擎闭源——差距是定性代差（触发智能/质量门控/策展/相位四件不进 Lite） |
| **人类对齐** | `requires_human_alignment()` 底线签名（默认 true；社区可覆写，但覆写后仍须保持 true——只能更严、不能放松） | 审批工作流的产品化实现（多级审批、审计流水、团队策略下发） | trait 开放，工作流收费 |
| **入口** | CLI + PlatformAdapter trait + ACP feature | 五大 IM 官方网关（飞书/钉钉/企微/微信/QQ） | trait 开放、网关闭源 |
| **知识格式** | 文件格式读写（双向 100% 兼容） | Skill Hub 市场、团队记忆同步 | 格式开放、市场闭源 |
| **商标** | Apache-2.0 代码自由 | "OpenPaw" 名称与 Logo | 代码开源、商标不开（同名共存下商标护城河更关键，§1.3） |

第一层边界的特点：**每一条都有代码物证**—— trait 签名、格式规范、目录结构。物证让边界可验证，而非停留在口头承诺。硬边界共五条（FreeAgent 已删除 GUI，两侧均无界面层差异，TUI 归入第二层软边界）。

**第二层：软边界（默认闭源，社区可挑战）**

- 嵌入检索（fastembed + IVF）、bash-ast 安全分析、ssh 远程执行环境（tools-exec）、TUI：随社区需求降级开放（feature / plugin / 捐入）；
- 挑战通道：任何"闭源件"若有成熟社区实现 + RFC 通过，可降级为官方开源组件；
- **只软不开硬边界**：反思引擎与策展器不在可挑战清单内（Reflect-Lite 是官方提供的参考实现而非引擎本体，生产引擎闭源正当性由 §4.3 决策四"代差红线"持续捍卫；Lite 自身超限或劣化按该节纪律处置）。

**第三层：流动边界（毕业通道）**

社区实验 → RFC → 孵化 → 毕业 = 代码从右向左流动的唯一合法通道（§7.4）。流动方向不可逆：毕业进 FreeAgent 的社区代码，以 Apache-2.0 授权回归开源主干，产品化打磨部分闭源。

#### 4.4.3 灰色地带裁决记录（预置六例）

对最容易撕扯边界的六个典型场景，预置裁决先例，后续争议援引执行：

| 场景 | 裁决 | 理由（四问法回放） |
|------|------|---------------------|
| 社区实现了一个效果媲美官方反思引擎的 EvolutionPolicy | **接受毕业评审，引擎仍闭源，但官方策略如果长期劣于社区策略，官方策略开源** | Q2 命中 → 策略层永远开放竞争；引擎闭源的正当性来自"官方做得最好"，失去正当性即失去闭源资格 |
| 某云厂商 fork OpenPaw 加闭源网关后商业分发 | **合法（Apache-2.0 允许），但不得使用 OpenPaw 商标与官方命名** | 商标硬边界独立于代码许可生效 |
| 社区要求开源 Skill Hub 市场代码 | **拒绝，但开放市场协议规范 + 客户端 SDK** | 格式与协议开放（Q3），运营层（推荐/计费/审核）为增值层；"开放协议、闭源运营" |
| 新工具"浏览器自动化"应该进 openpaw-tools 还是留 FreeAgent | **进社区：以 MCP 工具服务器形式提供官方参考实现（开源），不进内核** | Q1：非定义性能力；Q3：闭源浏览器工具会引发"开箱即残废"质疑，但 V8 重依赖违反轻量原则——MCP 是两全解 |
| FreeAgent 想把 24 个 HookPoint 改成商业版独有的增强版 HookPoint | **禁止** | HookPoint 属内核定义性能力（Q1）；两侧 HookPoint 签名必须一致，否则插件生态分裂，双轨互喂机制瓦解 |
| OpenPaw 是否原生支持 OpenWork（跨 Agent 工作流共享层，~2 万★，基于 OpenCode 引擎） | **双通道原生支持：E6 Sidecar（● 内置）+ E8 引擎位兼容（● 内置，[待验证] 以 Phase 2 验证关卡为准）；对 OpenWork 私有 API 不做适配** | E6：Q1 命中 → MCP 服务器封装属内核接入面定义性能力，Q3 命中增强中立性，Q4 达标（≤2 千行）。E8：Q1 命中 → OpenCode 引擎接口是**开源公开面**（非私有靶），兼容它等同兼容一个开放标准；Q3 命中 → OpenWork 由此成为 OpenPaw 的现成图形客户端，OpenPaw 保持零 GUI 代码；Q4 达标（≤2 千行，feature-gate 隔离）。**不做的部分**：适配 OpenWork **私有/内部 API** 永不触碰——依赖单向（engine-host → OpenCode 公开接口）、内核零 OpenWork 符号。边界口径：**协议级拥抱、产品级不绑定、引擎位即客户端** |
| FreeAgent 新增 RunLoop 长程目标自动驾驶系统（持久化档案 / 每日配额 / 进度账本 / 停滞纠正 / 全自治）如何归属 | **三层拆解（A9，◐ 简化内置）**：目标档案/账本/日志格式归同源件；`LongHorizonPolicy` trait 开源（进 core）；OpenPaw 内置 RunLoop-Lite 目标存折（`openpaw-goal-ledger` ≤2 千行）——**完整自动驾驶系统留 FreeAgent** | Q1 不命中 → 拿掉后 AgentLoop 仍完整，RunLoop 是内核之上的增值层；Q2 边缘命中 → 停滞纠正/续跑策略是可插拔智能，trait 层开源接路线 6；Q3 弱命中（格式层）→ 档案/账本格式不兼容将破坏知识互通桥梁（决策三延伸），格式必须同源；Q4 分层命中 → 完整自动驾驶 > 6 人月可闭源，极简存折 < 6 人月按纪律必须开源。**四件自动驾驶智能不进 Lite**（配额管理/自动重规划/并发保护/全自治），与 Reflect-Lite 代差同构。边界口径：**记得做到哪了是存折，决定怎么做完是大脑——存折开源，大脑增值**（§4.3 决策五） |

#### 4.4.4 对外表述口径（一句话边界）

所有对外沟通（README、官网、发布会、社区答疑）统一使用以下口径，杜绝"哪些开源"被问倒：

> **"OpenPaw 是完整的 Agent 内核：装好就能跑、进化策略任你换、知识格式与 FreeAgent 无缝互通。FreeAgent 在此之上加了三样东西：把进化策略打磨成生产引擎、把 IM 入口开到五大平台、把知识沉淀变成团队市场。内核是大家的，纵深是我们的。"**

配套三条禁语：

1. 禁用"阉割版 / 精简版 / 试用版"描述 OpenPaw——它是**完整内核**，不是残缺产品；
2. 禁用"商业版更强所以请买商业版"的推销话术——OpenPaw 的价值自洽，不靠贬损自身成立；
3. 禁止在 OpenPaw 文档中植入 FreeAgent 付费转化弹窗——转化靠格式兼容的"自然升级"，不靠围栏。

#### 汇总统计与三条结论（§4.5 收尾）

**45 项功能分布**（计数口径：**按 OpenPaw 列，即开源用户实际所得**）：

| 状态 | 项数 | 占比 | 含义 |
|------|------|------|------|
| ● 开源侧完整内置 | 24 | 53.3% | 内核承诺的底盘（含 A6 本地模型、F5 端侧部署、**E6 Sidecar 引擎**、**E8 引擎位兼容**四项**开源侧反超**闭源侧 ◐ 的条目） |
| ◐ 简化或可选 | 8 | 17.8% | 保留路径，不做绝（D3–D5 Reflect-Lite 使开源侧自 ○ 升 ◐；A9 RunLoop-Lite 目标存折） |
| ○ 接口开放待社区 | 9 | 20.0% | 苗圃的实验田（B5/B7/D7/E3/E5/**E7**/F1/F2/F3） |
| —— 闭源独占 | 4 | 8.9% | 纵深：Skill Hub 运营、团队同步、组织策略、相位信号 |

> 口径注记：A6 / F5 / **E6 / E8** 严格而言是"开源侧 ●、闭源侧 ◐"的反超项，计入 ● 是按开源用户所得口径；若按"两侧全等"严格口径则为 ● 20 / 反超 4 / ◐ 8 / ○ 9 / —— 4（合计 45）。本表为 strategymeta「45 项对比结论」的单一事实源，口径或数值修订须走 ADR（§9.2；44 → 45 的扩表依据为 ADR-003 RunLoop 目标存折）。

**三条结论**：

1. **底盘不残缺，且进化开箱即得**：● + ◐ 合计 **71.1%**——开箱即得的完整度过 Q3 红线（"开箱即残废"质疑在工具层、进化层与长程执行层均不成立），"完整内核"的口号有逐项清单背书；Reflect-Lite 让"能看到 Agent 进化"从装机第一天开始，RunLoop-Lite 让"Agent 记得托付的事"同样从第一天开始；
2. **差异只有两类，且都写成代差**：结构性差异集中在域 D（自进化引擎，双轨互喂的引擎室）与域 A9（长程自动驾驶）——Lite 与生产引擎的差距是四件能力的定性代差（触发智能/反思深度/策展质量/相位信号），RunLoop-Lite 与完整 RunLoop 的差距同为四件自动驾驶智能的代差（配额管理/自动重规划/并发保护/全自治），**不是功能有无**；其余差异均为"组织维度"（市场/同步/管理面）——个人开发者几乎感知不到边界，企业客户才会触达纵深；
3. **开源侧并非下位**：A6（本地模型）、F5（端侧部署）与 **E6（Sidecar 旁挂）/ E8（引擎位）**四项开源侧反而 ● 强于闭源侧 ◐，且 GUI 已从 FreeAgent 删除——两侧界面层同为 CLI/TUI，而 OpenPaw 以 E8 借 OpenWork 之壳获得图形客户端，**OpenPaw 不是 FreeAgent 的子集，而是分工不同的姊妹实现**，这句话本身就是对"阉割版"叙事的釜底抽薪。

### 4.6 边界判定与功能对比的衔接

功能表（§4.5）是四问法（§4.4.1）的历史快照：表中每一项的归属，都能回放到一次四问作答——● 项全部命中 Q1/Q3，○ 项命中 Q2，—— 项四问均未命中。今后边界裁决会每判定一个新特性，即在对应域的表中追加一行并标注 ADR 编号，**功能表因此是一份"活的台账"，而非静态宣传页**；年度边界白皮书（§7.6 防线四）以表中 ●/○/—— 三项占比的年度变化作为"开放度指数"，对外披露。

## 6. 社区创造力接口

### 6.1 EvolutionPolicy：进化策略即插件（本方案的核心创新）

```rust
#[async_trait]
pub trait EvolutionPolicy: Send + Sync {
    fn name(&self) -> &str;

    /// 每轮对话后：本轮是否值得反思？（频率由策略自定）
    async fn should_reflect(&self, ctx: &TurnContext) -> bool;

    /// 从会话转录中提取候选知识（记忆/技能/思维路径）
    async fn extract(&self, transcript: &Transcript)
        -> Vec<KnowledgeCandidate>;

    /// 候选处置：合并、淘汰、去重、路由到用户审批
    async fn resolve(&self, candidates: Vec<KnowledgeCandidate>)
        -> Vec<KnowledgeCandidate>;

    /// 不可协商的底线：写入必须经过用户审批（人类对齐）
    fn requires_human_alignment(&self) -> bool { true }
}
```

内核默认装载 `NullPolicy`（不进化，纯对话），社区通过插件装载任意策略：RL 反思、图记忆沉淀、群体进化……唯一不可逾越的是 `requires_human_alignment` 这条底线——**开放进化的自由，不开放失控的自由**。

### 6.2 HookPoint 全景（继承 FreeAgent 的 24 个）

覆盖 Agent 全生命周期：`BeforeAgentLoop / AfterAgentLoop`、`BeforeToolCall / AfterToolCall`、`BeforeMemoryStore / AfterMemoryStore`、`BeforeReflect / AfterReflect`、`OnError / OnApproval`……每个 HookPoint 提供可运行的 minimal example，作为社区第一贡献的模板。

**示例的 DX 规范**（对齐 §6.4.6 指标 4/5）：每个 minimal example 必须 ① 单文件、≤ 80 行、`cargo run --example <name>` 即跑（不依赖真实 LLM 的示例必须真的不依赖）；② 文件头三行注释说明"演示什么 HookPoint + 改哪一行能看到行为变化"；③ 与 §6.4.4 脚手架联动——`cargo openpaw new` 生成的骨架即以对应 example 为模板，**示例与脚手架同源，学完即用**。

### 6.3 六条官方实验路线（社区 Showcase）

|---|------|----------|---------------------------|

### 6.4 开发者体验（DX）工程：让"接口开放"兑现为"人人能试"

§6.1–6.3 回答了"社区能做什么"（接口层），本节回答"开发者多快能开始做"（体验层）。**苗圃的生死不在 trait 有多优雅，而在第一个陌生开发者从 clone 到自我认可"我改得动它"的全程摩擦**。开源项目的流失不是在"能力不够"处发生，而是在 `cargo build` 失败、示例跑不通、"不知道从哪读起"处发生。因此把 DX 作为工程体系而非文档态度来建设，组织为五级漏斗——每一级都有可度量的出口条件与 CI 化的守卫。

#### 6.4.1 五级 DX 漏斗

| 级 | 主题 | 出口条件（开发者视角） | 守卫机制 |
|----|------|------------------------|----------|
| L1 | **装得上** | 一条命令完成安装，零手工排障 | 安装烟测（三平台每日实测） |
| L2 | **跑得通** | 五分钟内跑通首轮对话 + 首个插件加载 | "三个五"指标 CI 化 |
| L3 | **看得懂** | 30 分钟内建立全局心智地图，知道"改哪个文件" | 架构速览 + 代码导读路径 |
| L4 | **改得动** | 首个 PR 从分支到合并全程 < 1 天 | 脚手架 + PR 模板 + good first issue 流水线 |
| L5 | **值得留** | 第二个、第三个 PR 持续发生 | 承认机制 + 上游优先律红利 |

#### 6.4.2 L1/L2：装得上、跑得通——零摩擦的第一次接触

- **一条命令安装**：`cargo install openpaw-cli`，无系统依赖、无环境变量、无手工步骤。发布物三平台（Linux / macOS / Windows）预编译二进制，GitHub Releases 直下；`brew install openpaw` 作为 macOS 快捷路径。
- **首次运行零配置可用**：`openpaw hello` 内置演示（不依赖任何外部 API——跑一个内置 echo 模型 + 演示知识文件读写），让开发者在**没有任何 key 的情况下 30 秒内看到 Agent 活着**；配置真实 LLM 的向导在下一步自然出现，而非前置障碍。`openpaw hello` 第二幕即 Reflect-Lite 幼脑首秀——演示知识文件被一次真实的"反思→固化"更新（产物打 `unverified` 标记），**进化从第一次接触就可见**；
- **进化健康自检**：`openpaw evolve status` 查看当前策略（NullPolicy / Reflect-Lite / 社区策略）、Lite 产物 `unverified` 占比与磁盘占用；`openpaw evolve reset` 一键清空幼脑产物重建（§7.5 幼脑反成短板的官方自救命令）——**幼脑会犯错，且永远给你一键反悔的余地**。
- **Sidecar 首秀（L2 第三幕）**：`openpaw --sidecar` 一条命令在本地拉起 MCP 服务器端点（默认 `127.0.0.1:<随机端口>`），教程给出把该端点粘贴进 OpenWork / Claude Code / Cursor 的 10 秒接线步骤——**你的 Agent 从命令行窗口走进团队工作台，只需一次复制粘贴**；端点默认仅绑定回环地址，`openpaw sidecar status` 随时查看连接方清单，`--sidecar stop` 一键收摊。
- **引擎位首秀（L2 第四幕，[待验证] 以 Phase 2 验证关卡为准）**：`openpaw --engine-host` 一条命令以 OpenCode 兼容引擎身份启动，OpenWork 桌面端在引擎设置中选择"OpenPaw"即完成接入——**不需要复制粘贴，你的 Agent 直接获得一个桌面客户端**（该 UI 路径属设计预期，OpenWork 当前 v0.1.9 API 未冻结，接口验证通过后方可写入正式教程）；教程含三步截图指引（安装 → OpenWork 引擎设置选 OpenPaw → 验证对话），并明示"OpenPaw 内核零 OpenWork 依赖：关掉 OpenWork，`openpaw` 命令行一切照旧"。
- **配置即代码**：`config.toml` 全量 schema 化，`openpaw config doctor` 一键体检——诊断到不完整配置时给出**可复制的修复命令**而非错误码。
- **失败即文档**：所有运行时错误信息遵循"发生了什么 / 为什么 / 下一步命令"三段式；错误码与文档一一对应，`openpaw explain <code>` 直接打开对应文档锚点。

#### 6.4.3 L3：看得懂——一周读完，一小时定位

"小到一周读完"（§3.1）不能只是口号，要给出**带里程碑的阅读路径**：

- **《架构速览》**（一页纸）：五层架构图（§5.1）+ 9 + 1 + 1 + 1 个 crate 的职责一句话表（含 Reflect-Lite、engine-host 与 goal-ledger）+ "我想做 X 该改哪里"反查表（X 覆盖社区高频意图：加一个工具、换一个模型、写一条进化策略、写一条长程策略、接一个新入口）；
- **三条代码导读路径**（docs/walkthrough/）：① 追一轮对话（`openpaw-cli → engine::AgentLoop → llm`）；② 追一次知识写入（`tools → memory → store`）；③ 追一次策略装载（`plugins → EvolutionPolicy → requires_human_alignment` 底线触发）。每条路径以一次真实执行的单步日志串讲，读者照着日志在代码里逐帧对位；
- **文档分层**：`README`（5 分钟）/ `ARCHITECTURE`（60 分钟）/ rustdoc（随时）/ `docs/walkthrough`（半天）——每层只做一件事，互不越界；rustdoc 中每个 crate 的 crate-level doc 以"这个 crate 解决什么问题 + 三行最小示例"开篇；
- **文档与代码同步率入 CI**：文档引用的代码行会漂移，示例代码全部取自 `examples/` 目录实体（CI 验证文档块与实体文件一致），**文档中的示例永远编译通过**——文档腐烂是 DX 的头号慢性病，用 CI 而非自觉来防。

#### 6.4.4 L4：改得动——从想法到合并 PR 全程 < 1 天

**cargo-openpaw 脚手架**（本节的核心工具）：`cargo openpaw new policy <name>` 一条命令生成**可编译、可测试、已挂好钩子**的策略插件骨架——含模板代码、单测桩、本地运行指令、提交前 checklist。同类命令覆盖三条高频创作路径：

```
cargo openpaw new policy   <name>   # EvolutionPolicy 插件（苗圃主打）
cargo openpaw new tool     <name>   # 自定义工具（挂入 ToolHost）
cargo openpaw new adapter  <name>   # 平台入口（实现 PlatformAdapter trait）
```

**贡献流水线的低摩擦设计**：

- **PR 模板内置自检清单**：复现步骤 / 影响的漏斗级（§6.4.1）/ 稳定级影响（§7.8）/ 知识格式影响（§4.4.2 物证）——让贡献者第一次 PR 就理解项目纪律，而非被驳回后才学；
- **good first issue 流水线**：`good-first-issue` 标签的 issue 必须自带"验收标准 + 涉及文件 + 参考示例链接"三件套，由 Maintainer 在每周巡检中维护存量 ≥ 5 个——**新手的第一 PR 不应消耗在"理解需求"上**；
- **审 SLA**：社区 PR 首响应 ≤ 48h、小 PR（< 200 行）全链路 ≤ 1 周；审意见遵循"建议附带可运行的修改片段"惯例——评审即教学；
- **本地验证一条命令**：`cargo openpaw check`（fmt + clippy + 受影响 crate 测试 + 文档同步检查）与 CI 完全同构，贡献者本地绿即 CI 绿，杜绝"本地过了 CI 挂"的挫败。

#### 6.4.5 L5：值得留——从第一个 PR 到持续贡献

吸引一个贡献者靠 DX，留住一个贡献者靠**回报感**：

- **承认前置**：首个 PR 合并即自动进入 CHANGELOG 贡献者栏 + README all-contributors 表 + Release note 具名致谢（"本版本包含 @xxx 的第一个贡献"）；
- **成长路径显性化**：CONTRIBUTING 中公开 Committer / Maintainer 的晋升标尺（合并数 × 影响域 × RFC 参与），让贡献者看得见下一级台阶；
- **上游优先律的红利**：§7.7 的 bug 修复上游优先使社区贡献的修复**必然先于商业版发布**——给社区贡献者的不仅是致谢，还有"我的修复跑在最前面"的实质地位；
- **毕业叙事的参与感**：社区策略被 FreeAgent 采纳（§7.4 毕业）时，原作者是该能力的产品叙事一部分——"这条进化路线由 @xxx 首创"写进 FreeAgent 文档，社区创造力获得商业级署名。

#### 6.4.6 DX 硬指标（CI 化守卫）

DX 若无数字，就只是口号。七条硬指标全部纳入 CI 与看板（§7.9）：

| # | 指标 | 目标 | 守卫方式 |
|---|------|------|----------|
| 1 | 冷构建（三平台） | < 5 min | CI 每日实测，回归即红 |
| 2 | 五分钟上手成功率 | ≥ 95% | 脚本化"新手上路"路径每日实测 |
| 3 | `openpaw hello` 首响 | < 30 s（无 key 环境） | 安装烟测断言 |
| 4 | 脚手架生成件编译通过率 | 100% | 三条 `new` 命令产物入 CI 编译矩阵 |
| 5 | 文档示例编译通过率 | 100% | 文档块 ↔ `examples/` 实体一致性检查 |
| 6 | issue 首响应（中位） | ≤ 24 h | 看板自动统计，超标触发 Maintainer 值班表 |
| 7 | 社区 PR 首响应 | ≤ 48 h | 同上 |

**DX 的组织保障**：Phase 1 起设 **DX Owner**（可由 Maintainer 兼任），职责是每周以"完全新机器"的标准环境走一遍 L1→L4 全流程——**用新人的眼睛周检自己的项目，是 DX 不腐烂的最后保险**。

```
社区实验（openpaw-plugin 形式）
    → RFC 提案（证明价值：用户量/效果数据）
    → 孵化（进入 openpaw 官方 examples，标注实验性）
    → 毕业（进入 FreeAgent 产品路线，产品化打磨）
```

毕业的判定标准：**效果数据**（采纳率/质量门控通过率）+ **用户规模**（插件装机量）+ **与三大产品灵魂的一致性（标准与出处见 §2.4 思想承接——灵魂是毕业的门槛，不止是 README 的引言）**。FreeAgent 的"下一程"（知识联邦、多模态知识、主动学习）恰好对应 §6.3 的实验路线——**我们把产品路线图的空白，写成了社区的考题。**

### 7.5 风险对策

| 风险 | 对策 |
|------|------|
| 云厂商 fork 后商业化（Apache 允许） | 商标保留 + FreeAgent 增值层（进化引擎/网关/Skill Hub）构成事实差异化；"官方原生"的生态位 |
| 社区路线与商业路线冲突 | RFC 中的"产品保留区"申明：自进化引擎、IM 网关为 FreeAgent 专有，避免社区重复投入 |
| 维护成本拖累 FreeAgent 团队 | 9 + 1 + 1 + 1 crates 精简内核 + Committer 层级分担；示例项目交社区认领 |
| 命名共存风险应对失当 | 严格执行 §1 防御战略三件套（正名宣言 / 占位矩阵 / 时机策略），Phase 0 完成法务检索后再官宣 |
| **边界漂移**：团队图省事把新特性错放进开源侧泄密，或错放进闭源侧被社区指"虚伪开源" | 四问法速测（§4.4.1）+ 边界裁决会（§7.6）+ "物证清单"入 CI 检查：开源 crate 中出现闭源路径引用即构建失败 |
| **双轨漂移**：同名 crate 在两仓各自演化，18 个月后 trait 语义分叉、格式漂移，双轨互喂前提失效 | §7.7 三类代码流向清单（同源件禁止双仓手改）+ trait 快照测试两侧同灯 + bug 修复上游优先律 |
| **API 信用破产**：破坏性变更清零社区贡献者的 trait 投资，插件生态流失 | §7.8 稳定级制度 + 1.0 冻结三件套 + 废弃两版缓冲周期；破坏 stable 项的变更须 RFC 通过 |
| **DX 腐烂**：迭代中示例失效、文档漂移、上手路径断裂——开源项目的慢性死亡，且无告警 | §6.4.6 七条硬指标全量 CI 化 + 文档↔示例实体一致性检查 + DX Owner 每周新机巡检 + 残废红线（§7.9）回炉机制 |
| **恶意插件烧毁信任**：EvolutionPolicy/HookPoint 插件外传用户记忆或组合出未预期行为，社区不会区分"官方防线失守"与"个别插件作恶" | §7.10 默认不信任架构（权限显式化 / capability 沙箱 / 审批日志锚定）+ 信任分级 L0–L3 能力阶梯 + `openpaw doctor` 官方命名空间核对 |
| **供应链投毒**：crates.io 依赖污染、发布链路被篡改，12 个官方包整体沦陷 | §7.10.3 供应链四防线：签名发布（Sigstore）+ `cargo deny/audit` 白名单入 CI + 可复现构建 + 同名包运行时告警（对冲 §7.10 T3，源于 §1.5 残余风险） |
| **弃养/静默死亡**：公司业务调整后项目无人维护，社区投资清零——比闭源更伤品牌 | §7.11 弃养条款（6 个月公告 + 交接资产清单 + 永不静默弃养）+ 治理三级演进（目标：最终移交基金会，失去控制权即成功） |
| **遥测信任危机**：任何一次"悄悄上报"被社区发现（崩溃统计、匿名计数），即可烧掉"用户主权"叙事——开源项目的隐私丑闻杀伤力大于闭源项目 | §7.12 默认零遥测三军规 + 数据政策文档与代码同仓库开源 + 任何数据回传（未来若引入）须 RFC + 显式 opt-in |
| **物料口径失守**：README / 发布帖 / 大会演讲各说各话，"哪些开源哪些闭源"在不同物料中出现两个版本，被社区截图对照质疑 | §9 双语口径单一事实源（strategymeta）+ 四条发布物料的事实锁定矩阵 + 口径变更走 ADR 并同步刷新全部物料 |
| **幼脑越权**：Reflect-Lite 悄悄长成第二个生产引擎，闭源纵深被自家开源件填平，"代差"叙事在代码面前失守 | §4.3 决策四三纪律：≤3 千行 CI 断言 + 四件能力不进 Lite（触发智能/质量门控/策展/相位信号）+ 季度代码审计（DX Owner + 安全响应人联签，超限回滚走 ADR） |
| **幼脑反成短板**：Lite 反思产物无质量门控，低质知识持续污染本地知识文件，用户反怪"官方自带的进化不好用"，伤"完整内核"承诺 | Lite 反思产物默认打 `unverified` 标记 + 一条命令清空重建（`openpaw evolve reset`）+ 文档明示"幼脑会犯错，且告诉你它错了"——短板写成预期而非事故；D8 格式兼容保证污染文件可被 FreeAgent 策展器清洗 |
| **Sidecar 反客为主**：旁挂模式悄悄从"分身"长成"宿主依赖"——内核开始 import OpenWork 专属约定，或 `--sidecar` 默认开启外联，"协议级拥抱、产品级不绑定"在代码层面失守（对齐 §9.5.0 判词反转风险） | §4.5 域 E6 边界纪律三件：① Sidecar 代码 ≤2 千行 CI 断言且未启用时零激活（feature-gate 隔离）；② 端点默认仅绑回环地址、`openpaw doctor` 网络审计将 Sidecar 外联列为显式可选项（§7.10.3 防线五）；③ 断网烟测（§7.12）默认不加载 Sidecar——**无 OpenWork、无网络，内核必须完整自洽** |
| **引擎位长成寄生**：engine-host 悄悄从"替身"长成"宿主寄生"——为追平 OpenWork 体验开始适配其私有 API、或在内核中渗透 OpenWork 专属假设，"引擎位即客户端、私有 API 不碰"在代码层面失守 | §4.5 域 E8 边界纪律三件：① engine-host ≤2 千行 CI 断言 + feature-gate 隔离，未启用零激活；② **依赖单向性 CI 断言**——`openpaw-engine-host` 可依赖 OpenCode 公开接口签名，核心 9 crate 对 OpenWork/OpenCode 符零依赖（cargo deny 白名单强制）；③ OpenWork 私有 API 适配列入永不清单，违者回滚走 ADR——**客户端是借来的壳，内核必须能独立站立** |
| **存折长成自动驾驶**：goal-ledger 悄悄长成第二个 RunLoop——为"好用"偷偷加入配额智能管理、自动重规划或全自治，闭源纵深被自家开源件填平，"存折开源、大脑增值"代差叙事在代码面前失守 | §4.3 决策五三纪律：≤2 千行 CI 断言 + 四件自动驾驶智能不进 Lite（配额管理/自动重规划/并发保护/全自治，超限回滚走 ADR）+ 账本格式黄金用例入 §7.6 防线二——**存折只记账，不替用户做长程决策；策略怎么升级，走 `LongHorizonPolicy` 开放竞争** |

### 7.6 边界维护机制：让边界活过五年

边界最大的敌人不是竞争对手，而是时间——团队换血、路线摇摆、一次例外的破窗。为此设四道防线（时间口径：本节"五年"与 §4.4 导语同义，指边界宪法的长周期执行视野；§7.7 的"三年"为双轨同步的漂移观察窗口，两口径各自独立）：

**防线一：裁决流程制度化的"边界裁决会"**
每两周一次（可并入 RFC 例会），议题只有一张表：本期所有新特性在四问法下的归属判定。判定记录（含 Q1–Q4 的作答）以 ADR（Architecture Decision Record）形式公开归档到 `docs/boundary-decisions/`——**边界裁决本身开源**，这是对外公信力的来源。

**防线二：CI 强制的"物证清单"**
把 §4.4.2 硬边界的五条物证写成机器可查的断言，纳入两侧仓库 CI：
- openpaw 侧：不得出现 reflect 引擎 / gateway / skill-hub 的符号引用；EvolutionPolicy trait 的 `requires_human_alignment` 默认值必须为 true；
- 格式兼容：每日 CI 跑知识文件双向读写黄金用例（FreeAgent ↔ OpenPaw），任何一侧改格式未同步另一侧即红灯。

**防线三：例外审批的"破窗条款"**
确需临时例外（如企业客户紧急需求要借用闭源件演示），须由两位 Maintainer 联签 + 限定 30 天有效期 + 到期必须归还或正式改判。**不允许存在无到期日的例外**——无到期日的例外就是新边界的既成事实。

**防线四：年度边界审计与再版**
每年发布《边界白皮书》（年报性质）：盘点过去一年所有 ADR 裁决、统计两侧代码增量比、公开讨论"哪些软边界该转开源、哪些毕业件该产品化"，并**报告思想承接证伪条件（§2.4.3 F1/F1′/F2）当年的触发与处置情况**——思想承接失败必须在年度白皮书中公开复盘，不得低调处理。边界允许演进，但**演进必须经过公开程序**——这本身就是"开放进化"哲学对治理机制的自我应用。

### 7.7 双轨代码同步机制：防止两个仓库在漂移观察窗口（三年）内变成两个项目

五条硬边界（§4.4.2）画出了"什么在哪侧"，但**保留类 crate 同体存在于两个仓库**——`openpaw-core/engine/llm/tools/mcp/store/memory/plugins/cli` 在 FreeAgent 侧同样有对应物。没有同步纪律，18 个月后两侧同名 crate 将语义漂移：签名分叉、格式漂移、HookPoint 不一致——双轨互喂的前提（格式兼容、HookPoint 一致、trait 语义相等）将全部失效。毕业机制（§7.4）只管"社区 → 商业"一个方向的代码流，**反方向与平级方向的流动无章可循**。为此定三条规则：

**规则一：三类代码，三种流向。**

| 代码类别 | 定义 | 允许的流向 | 禁止 |
|----------|------|------------|------|
| **同源件** | 两侧语义必须完全一致（trait 签名、HookPoint、知识格式编解码、`requires_human_alignment` 默认值） | 以 OpenPaw 仓库为 **source of truth**，FreeAgent 侧以 git subtree/submodule 或 cargo git 依赖引用，**禁止双仓手改副本** | 任何一侧独立修改 |
| **对齐件** | 语义一致、实现深度不同（AgentLoop 的企业级压缩策略、降级链的高级参数、**进化引擎：Reflect-Lite vs 生产引擎**） | OpenPaw 为基线，FreeAgent 可增强但须通过共享测试集 | FreeAgent 增强后不回灌通用 bug 修复 |
| **分叉件** | 各自演化（反思引擎的内部实现 vs 社区策略、官方网关 vs 社区网关插件） | 无同步义务，仅共享 `openpaw-core` 的 trait 合约 | 闭源实现偷偷依赖开源内部符号（§7.6 防线二拦截） |

> **归属注记一（Reflect-Lite 与 D8 格式）**：Reflect-Lite 归**对齐件**——它是生产引擎的简化基线，两侧共享"触发→反思→固化"三步语义与共享测试集，FreeAgent 不得反向删改 Lite 语义；D8 进化数据格式（反思记录/知识变更日志）归**同源件**——Lite 产物必须能被 FreeAgent 策展器直接读取清洗，这是"幼脑产物可被成年大脑接手"的格式前提。
>
> **归属注记二（engine-host）**：`openpaw-engine-host` 归**分叉件（单向依赖外型）**——OpenPaw 独有、无 FreeAgent 对应物；允许依赖 OpenCode 公开接口签名（[待验证]，以 Phase 2 验证关卡为准），禁止反向依赖（内核 import engine-host 或 OpenWork 符号），CI 依赖白名单强制（对齐 §7.5"引擎位长成寄生"风险行与 §4.5 E8 边界纪律）。
>
> **归属注记三（RunLoop 三层，ADR-003）**：目标档案 / 进度账本 / 执行日志**格式归同源件**——OpenPaw 里记的账 FreeAgent 必须直接接手，账本格式黄金用例入 §7.6 防线二双向读写检查；`LongHorizonPolicy` trait 归**同源件**（进 openpaw-core，两侧签名一致）；`openpaw-goal-ledger`（RunLoop-Lite）归**对齐件**——FreeAgent 完整 RunLoop 是其生产化形态，共享账本 schema 与续跑语义，FreeAgent 不得反向删改 Lite 存折语义（对齐 §7.5"存折长成自动驾驶"风险行与 §4.3 决策五纪律）。

**规则二：Bug 修复流向三律。**
1. **上游优先**：公开于 OpenPaw 的 bug，修复必须先落 OpenPaw 主干，FreeAgent 侧随后拉取——**商业版永远不欠社区一个已知 bug 的修复**（商业版带病运行而开源版先好，是"虚伪开源"质疑的头号弹药）；
2. **闭源私有 bug 修复若涉同源件**：以净化后形式（不含闭源逻辑）同步回 OpenPaw；
3. **安全修复**：安全类修复跳过所有流程直接双侧同步，OpenPaw 侧按标准安全披露流程（embargo → advisory）发布。

**规则三：语义漂移检测。** 双向兼容黄金用例（§7.6 防线二）之外，增加**trait 快照测试**：CI 每次发布前对 `openpaw-core` 全部公开 trait 生成签名快照，FreeAgent 侧同步引用该快照编译——两侧 trait 语义一旦分叉，两侧 CI 同时红灯。

边界物证（§4.4.2）保证"什么在哪侧"，本节保证"两侧永远共享同一个内核事实"——**物证防止串台，同步机制防止漂移。**

### 7.8 发布工程与 API 稳定性承诺：苗圃的信用底座

社区贡献者的第一投资是"读懂并实现 trait"；一次破坏性变更就足以清零这份投资。**对 EvolutionPolicy 语义稳定性的承诺，就是 OpenPaw 对社区的信用承诺**——这条承诺同样约束 FreeAgent 侧（§7.7 同源件规则）。

**SemVer 全线执行**：9 + 1 + 1 + 1 个 crate 独立版本、独立 changelog（engine-host 在验证关卡通过前版本号挂 0.x 预发布），`openpaw-core` 的主版本号即全生态兼容性基准。cargo 依赖图在 CI 中强制检查：任何 `openpaw-*` 之间的依赖必须落在声明的版本区间。

**API 稳定级制度**：`openpaw-core` 中每个公开项在 rustdoc 中标注稳定级——

| 稳定级 | 标注 | 变更许可 | 适用对象 |
|--------|------|----------|----------|
| `#[stable]` | 1.0 冻结 | 仅能增不能改；废弃走两版周期 | EvolutionPolicy / PlatformAdapter / Guardrail / HookPoint 签名、知识文件格式 |
| `#[unstable]` | 默认隐藏，`--features unstable` 才编译 | 任意变更 | 实验性 trait 方法、新扩展点 |
| `#[internal]` | 文档不展示 | 无承诺 | 内部辅助（社区依赖即视为放弃兼容） |

**1.0 冻结三件套**（Phase 2 出口条件）：① 公开 trait 集合全部升为 `#[stable]`；② 知识文件格式发布 1.0 规范文档（含 schema 校验器与黄金样本库）——**含 D8 进化数据格式**（反思记录 / 知识变更日志 / `unverified` 标记位），Reflect-Lite 产物与 FreeAgent 策展器输入共用同一 schema；③ 发布《兼容性承诺》——1.0 后，任何 stable 项的破坏性变更须经 RFC + 一次大版本 + 两个小版本的废弃缓冲。冻结前大胆实验，冻结后信用高于便利。

**发布节奏**：双周 patch（bug 修复按 §7.7 上游优先律回流）、双月 minor（新 feature flag、新 HookPoint 示例）、年度 major（仅当 RFC 通过）。每次 release 附"毕业进展"栏——发布日志同时是双轨互喂的公示板。

### 7.9 成功度量：社区健康看板

苗圃是否成立，不取决于发布会声量，而取决于可公开验证的指标。设**社区健康看板**（公开网页，月度刷新），八类指标：

| 类别 | 指标 | 12 个月目标（示意基线） |
|------|------|------------------------|
| 活力 | 月活贡献者数、PR 合并数、issue 首响应时长（中位） | 月活贡献者 ≥ 60；issue 首响应 ≤ 24h |
| 分布 | 非本组织贡献的 PR 占比 | ≥ 40%（低于此值即"官方独角戏"警报） |
| 上手 | README → 首个 PR 的转化漏斗、五分钟上手成功率（CI 每日实测三平台）、L3→L4 漏斗通过率（§6.4.1） | 上手成功率 ≥ 95%；L3→L4 转化率看板公示 |
| 采纳 | crates.io 下载数、每月新增 EvolutionPolicy 插件数 | 月均新增策略插件 ≥ 2 |
| 代差 | 锦标赛中社区策略对 Reflect-Lite 基线的胜率、Lite 行数趋势、Lite 反思产物被 FreeAgent 策展器清洗采纳率、**Lite 反思产物 `unverified` 占比（本地统计，opt-in 后进看板，同旁挂占比纪律；§2.4.3 F1 证伪追踪指标）**、**编排赛道社区 `LongHorizonPolicy` 对 RunLoop-Lite 存折基线的胜率** | 基线胜率与代差健康度季度公示——**代差是承诺，承诺就要可度量**（两赛道基线：进化 = Reflect-Lite，编排 = 目标存折） |
| 毕业 | 进入孵化/毕业评审的实验数、FreeAgent 采纳数 | 首年 ≥ 1 件毕业 |
| 生态 | 实验路线（§6.3）覆盖率、MCP 工具服务器联动数、**旁挂占比**（`--sidecar` 会话数 / 总会话数，按客户端类型匿名分桶——本地统计，零上报，用户 opt-in 后才进看板）、**引擎位占比**（OpenWork 经 `--engine-host` 驱动的会话数 / 总会话数，同分桶同纪律） | 六条路线每条至少 1 个活跃种子；Sidecar 旁挂占比季度公示（OpenWork / Claude Code / Cursor 分桶）；引擎位占比季度公示 |
| 口碑 | HN/Reddit/X 自然提及中性/正面比、独立技术博客评测数 | 负面主导即触发叙事复盘 |

**四条护栏红线**（任一触发即启动应对预案，而非仅记录；**思想承接证伪条件 F1/F1′/F2（§2.4.3）与下列红线同表季度巡检，触发即按该节后果执行，复盘入《边界白皮书》（§7.6 防线四）**）：
1. **独角戏红线**：非组织 PR 占比连续两季 < 25% → 说明"社区创造力"叙事失败，重审 §6 实验路线的种子质量与 RFC 门槛；
2. **残废红线**：五分钟上手成功率 < 90% → 说明"开箱即残废"质疑成立，Phase 1 指标失效，回炉；
3. **幽灵苗圃红线**：连续两季零新增 EvolutionPolicy 插件 → 说明核心创新（§6.1）无感，重审 trait 设计或降低实验门槛——**优先动用 §6.4.4 脚手架与模板生成器**（含 Python/Rust 策略模板）而非先动 trait；
4. **幼脑红线**： Reflect-Lite 行数突破 3 千行上限，或社区策略锦标赛对基线胜率连续两季 ≥ 80% → 二者任一触发即启动 §4.3 决策四纪律复核：前者超限即回滚重构，后者说明"幼脑够用了"叙事开始侵蚀代差——**评估将 Lite 深度冻结为纯基线（只修安全 bug、停止功能演化），把创新空间让给社区策略与生产引擎**。同纪律适用于 goal-ledger（存折红线：≤2 千行 + 四件自动驾驶智能不进 Lite，§4.3 决策五）。

看板本身就是开放哲学的自我应用——**度量公开，就是允许社区审判我们是否言行一致**。

### 7.10 安全模型：开放即攻击面，防线先于生态

本方案反复强调"接口全开"（§6）——但每个开放接口同时是攻击面。EvolutionPolicy 插件拥有读写记忆的权限，HookPoint 能截停 Agent 的每一次决策，MCP 接入任意外部工具。**一个恶意插件足以烧掉整个苗圃的信用**：社区不会区分"OpenPaw 官方防线失守"与"个别插件作恶"，而 §1 的同名共存战略让第三方甚至有动机发布同名恶意包嫁祸本项目的搜索结果。因此，安全防线必须先于生态扩张到位，而不是后补。

**威胁模型（四类威胁，按危害 × 概率排序）**：

| # | 威胁 | 攻击路径 | 危害 |
|---|------|----------|------|
| T1 | **恶意 EvolutionPolicy 插件** | 以"进化策略"名义发布插件，在 `AfterReflect` 钩子中静默外传用户记忆/知识文件 | 致命：直接背叛"用户主权"灵魂，媒体标题即"自进化 Agent 变自泄密" |
| T2 | **供应链投毒** | crates.io 依赖投毒、CI 缓存污染、发布脚本被篡改 | 致命：污染的是 12 个官方包（9 + Lite + engine-host + goal-ledger），影响全部下游 |
| T3 | **同名包混淆**（§1 残余风险的安全化放大） | 发布 `openpaw-*` 恶意同名包，借本项目搜索流量分发 | 高：正名宣言防叙事，防不了 `pip install` 手滑 |
| T4 | **HookPoint 滥用** | 合法能力被用于合法功能，但组合出未预期行为（如记忆写出后无限重放） | 中：随生态规模线性增长 |

### 7.10.1 架构三原则：默认不信任（Zero-Trust Agent）

| 原则 | 内容 | 落地物 |
|------|------|--------|
| **权限显式化** | 插件声明所需权限集，未声明一律拒绝；权限清单在安装时以人话展示（"本插件将读写你的记忆文件"），而非藏在文档第 9 节 | `OpenPaw.toml` 的 `permissions` 声明段 + 安装时 diff 式授权确认 |
| **能力即沙箱** | 每个 HookPoint / trait 实现默认运行在受限 capability 环境：文件系统访问白名单、网络默认拒绝、进程创建需显式授权 | `openpaw-core` 的 capability token 机制，与 §4.5 域 B 的 bash-ast 分析同构复用 |
| **人类对齐是安全底线而非仅产品底线** | `requires_human_alignment = true`（§6.1）不仅保证"用户点头"，还保证高危动作产生**可审计的审批日志**——审批记录与插件执行记录双向锚定 | 审批日志独立 append-only 存储，插件无权读写自己的审批记录 |

### 7.10.2 插件信任分级：能力越大，关卡越多

不设"官方插件 vs 第三方插件"的二元信任，而按**能力危险度**分级——能力阶梯与审查关卡一一对应：

| 级别 | 能力 | 关卡 |
|------|------|------|
| L0 纯函数 | 不触网络/文件/进程的策略计算 | 无需审查，即时安装 |
| L1 持久化 | 读写指定路径的知识文件 | 权限声明 + 安装时确认 |
| L2 联网 | 访问声明的域名白名单 | L1 + 域名白名单静态校验 + 社区披露期 14 天 |
| L3 全能 | 任意网络/进程/审批链操作 | L2 + Maintainer 代码审查签名 + `--i-know-what-im-doing` 显式启用标志 |

### 7.10.3 供应链与外部协同面五防线（含 §1 同名混淆的安全应对）

1. **签名发布**：crates.io / GitHub Release 全部由 CI 签名（Sigstore），README 提供指纹校验命令——"我们的包只有这一种打开方式"；
2. **依赖冻结清单**：`cargo deny` + `cargo audit` 入 CI，依赖白名单变更须 RFC（依赖树是攻击面，更是社区信任的契约）；
3. **可复现构建**：相同源码 + 相同工具链产出比特一致的二进制，任何人可独立验证官方产物与 GitHub 源码一一对应；
4. **同名混淆防护**（对冲 §7.10 T3 同名包混淆，其源头为 §1.5 残余风险）：官方文档与 `openpaw doctor` 内置"官方命名空间核对"——`openpaw doctor` 检测到已安装的 `openpaw-*` 包不在官方签名清单时，立即红色告警"该包非官方发布，签名不符"；正名宣言（§1.2）之外的第二道护栏——**叙事上承认共存，运行时上拒绝冒名**。
5. **外部协同面防线（Sidecar + 引擎位）**：`--sidecar` 拉起的 MCP 端点默认仅绑定 `127.0.0.1` 并要求本机确认后接受首个客户端（如 OpenWork 桌面端——作为客户端接入方调用 OpenPaw 的三类能力）；连接方清单（来源 / 时间 / 已授权能力）进 `openpaw sidecar status` 与 `openpaw doctor` 网络审计报告；引擎位模式（`--engine-host`）遵循同一审计通道——OpenWork 作为客户端驱动 OpenPaw 的每一段连接同样全程可见。Sidecar 与引擎位让用户"进驻别人的工作台"，本防线保证**进驻动作本身全程可见、随时可断**；两模式的遥测基线与内核一致：零上报。

### 7.10.4 安全披露制度

- `security@openpaw.dev` 专线 + 90 天披露缓冲（严重问题可协商延长）；
- 每季发布安全纪要（处理了多少报告、平均响应时长），纳入 §7.9 看板"口碑"类目；
- **安全修复适用 §7.7 规则二第 3 条**：embargo 期内双侧同步，OpenPaw 侧先于或同时于 FreeAgent 侧获得修复——**安全问题上，开源侧永远不排队**。

> 本节的安全设计沿用 FreeAgent 已在代码中验证的安全机制（bash-ast 命令 AST 安全分析：bash + PowerShell 双解析、只读判定与破坏性 rm 语义识别；审批链 ApprovalManager 与三级 Guardrail 裁决；SecurityAuditor 的 prompt 注入 / 不可见 Unicode / 凭据泄漏检测；沙箱快照回滚与凭据保险库），OpenPaw 是其"最小可审计子集"——**防线从第一天起就是开源的，社区可以审计防线本身**（`requires_human_alignment` 底线签名为 OpenPaw 侧新增的 trait 级表达，§6.1）。

### 7.11 可持续性承诺：谁来养这个项目，以及它死了怎么办

开源项目最诚实的考题不是发布日，而是**第二年谁在维护**。社区投资 trait 的前提是相信这个苗圃三年后还在；本节把"可持续性"从愿景变成可审计的承诺。

**公司侧投入承诺（KunlunMeta，Phase 0 时随项目发布）**：
- **专职 FTE**：≥ 2 名全职 Maintainer（含 1 名 DX Owner，§6.4.6）+ 1 名轮值安全响应人，纳入 FreeAgent 团队编制与 OKR——**维护 OpenPaw 算正式业绩，不算业余贡献**；
- **响应 SLA**：issue 首响应 ≤ 24h（§6.4.6）、安全报告首响应 ≤ 48h、CI 红灯主干修复 ≤ 1 个工作日；
- **基础设施**：CI/CD、文档站、看板（§7.9）、签名基础设施的运维预算单列。

**商业自洽逻辑（为什么养得起）**：OpenPaw 不是慈善，而是 FreeAgent 的三项低成本外部职能——人才漏斗（Committer 即候选人池，招聘成本前置为社区声誉投资）、路线漏斗（毕业机制 §7.4 替代部分探索性研发）、获客漏斗（每一份双轨兼容的知识文件都是 FreeAgent 的免费试用装）。**苗圃的运营成本低于自建同规模探索团队，这是预算表上站得住的账。**

**弃养条款（Sunset Clause，项目发布时写入 GOVERNANCE.md）**：
万一 KunlunMeta 因业务调整决定停止官方维护——
1. **提前 6 个月公告期**：README 首屏、release、看板三处同步公示，期间完成 maintainer 招募冲刺；
2. **交接资产清单**：CI 凭据、域名（openpaw.dev）、签名密钥、官方账号，按清单移交给接任方（基金会、社区小组或其他公司）；
3. **中立过渡**：交接期内 FreeAgent 侧遵守 §7.7 全部同步义务直至协议到期或接任方修改——**弃养不免除历史承诺**；
4. **永不静默弃养**：不公告的弃养是所有开源项目最恶劣的死法。

**治理演进路径**（随健康看板 §7.9 数据推进）：
- **第一阶段（官方主导）**：Maintainer 以 KunlunMeta 员工为主，进程快速但公信有限——这是初创期的诚实状态；
- **第二阶段（混合治理）**：非组织贡献者占 PR ≥ 40% 持续两季 → 外部 Committer 晋升 Maintainer，边界裁决会（§7.6）引入外部席位；
- **第三阶段（基金会托管）**：若社区规模与第三方贡献持续健康，评估移交中立基金会（对标 Rust Foundation / CNCF 模式），KunlunMeta 降级为最大贡献者而非所有者——**我们期望最终失去控制权；失去控制权的那一天，就是苗圃真正长成森林的那一天。**

### 7.12 数据主权与遥测哲学：证明"我们自己也不作恶"

§7.10 防的是"外部作恶"（恶意插件、供应链投毒）；本节防的是"内部作恶"——**项目自己悄悄收集数据**。自进化 Agent 的知识文件承载用户工作方式的全部细节（技能、记忆、思维路径），是比聊天记录更敏感的资产；"用户主权"灵魂（FreeAgent 三大产品灵魂之一）若在开源侧有任何一处暗数据出口，就会被社区用 `netstat` 和抓包工具当场检验。因此数据主权不写成隐私政策，而写成**可执行、可审计、可验证**的三军规：

| # | 军规 | 内容 | 验证方式 |
|---|------|------|----------|
| 1 | **默认零遥测** | 不内置任何崩溃统计、匿名计数、使用分析上报——一行都没有。遥测开关不是"默认关闭"，而是"默认不存在"；CI 断言二进制产物不包含任何已知遥测 SDK 符号 | CI 符号扫描 + 社区可复现构建（§7.10.3 第 3 条）下任何"多出来的网络请求"无所遁形 |
| 2 | **知识文件 100% 本地** | 记忆、技能、会话转录全部落本地磁盘（§5.3 数据目录），不经任何云端中转；不提供"云同步"官方功能——同步是用户自己的功课（自选 git / 网盘 / 未来的社区插件） | `openpaw doctor` 网络审计：列出 Agent 进程建立过的全部外联连接清单 |
| 3 | **开源侧不设云账户** | 无登录、无注册、无设备指纹、无 license 校验回连。OpenPaw 对服务器没有"合法理由"知道你是谁；GPT-Station 硬件上的离线场景因此完全可用 | 离线烟测入 CI：断网环境跑通安装 → 对话 → 进化策略装载全流程 |

**两条配套规则**：

1. **错误报告自愿匿名**：崩溃时仅提示"运行 `openpaw report` 可生成匿名诊断包"，内容经用户查看确认后**由用户手动提交**到 issue——数据离开机器的最后一步永远是人按下回车，而非代码自动完成；
2. **未来若引入任何数据回传**（如社区投票通过的官方遥测）：必须走 RFC + 默认 opt-in + 独立开关组件 + 数据政策文档——且**开源侧的《数据政策》与防线源码同仓库、同许可证发布**，与 §7.10"防线从第一天起就是开源的"形成同一逻辑的镜像：**社区不仅能审计我们防得住谁，还能审计我们没在看什么。**

> 本节与 §7.10 合并理解：安全模型让用户敢用插件，数据主权让用户敢用内核。两者共同构成"用户主权"从产品口号到工程事实的闭环——**主权的最终形态，是机器上跑着的每一行代码都为用户工作，而非为它的作者。** 本节同时是 §2.4 思想承接中"用户主权"灵魂的最强代码物证——世界观（信任竞赛论）在此兑现为三军规。

### 9.5 OpenPaw 吸引力主张提炼：开发者为什么值得点进来

**提炼原则**：吸引力不是罗列功能，而是回答开发者刷到这个项目时心里的四个连续问题——**为什么注意（标题 3 秒）→ 为什么来（首屏 30 秒）→ 为什么留（第一周）→ 为什么传播（第一个 PR 之后）**。张力来自对比：先看下文「竞品坐标系」里 2026 年热度榜的四个结构性空位，再看以下 13 条主张如何逐一占位——每条锚定负责章节，任何物料引用时不得脱离其数据来源。

#### 竞品坐标系：热度榜的温度，与它照不到的空位

> **快照口径**：下表 star 数为 2026-05 公开快照，仅用于方案内部定调，不进入对外物料；对外引用竞品数字一律标注快照日期，口径变更走 ADR（对齐 §9.2）。

| 项目 | 热度（2026-05 快照） | 形态 | 结构性缺口（OpenPaw 的机会） |
|------|---------------------|------|------------------------------|
| OpenClaw | ~37 万★（含分叉） | 通用个人 Agent，社区狂热 | 工程纪律与安全模型跟不上热度（§1 同名项目即其分叉）；"改 Agent 行为本身"无开放接口 |
| Hermes | ~15 万★ | 自进化 Agent，最直接对手 | 自进化引擎闭门演进，社区只能围观不能定义规则；无毕业分发通道 |
| Claude Code | ~12 万★ | 闭源编码 Agent | 厂商绑定（Anthropic 路线）；订阅制门槛；零社区改造权 |
| Codex | ~8 万★ | 闭源编码 Agent | 同上（OpenAI 路线），开放性更弱 |
| OpenCode | ~18 万★ | 开源编码 Agent | 开源的是客户端壳，核心模型能力仍在厂商侧；无自进化命题。**判词兑现（条件句式）**：**若** Phase 2 验证关卡证实 OpenWork 引擎位开放（公开接口规范或上游 RFC 接受），OpenPaw 兼容其公开引擎接口坐进 OpenWork 引擎位，把"壳可替换"变成 OpenPaw 的获客通道——**兑现判词可以是对外叙事，工程承诺必须挂验证条件**（§8 验证关卡 / E8 [待验证] 标记） |

**热度榜照出的四个结构性空位**：

1. **生产血统空位**——热度榜被"从零攒起的框架"与"闭源厂商运行时"瓜分，"生产级血统 + 玩具体量 + 真开源"三者交集为空；
2. **自进化民主化空位**——自进化是 2026 决胜命题，但头部玩家全部闭门造车，没有一家把它做成社区可编程的公开 trait；
3. **模型中立空位**——头部项目均有"亲爹路线"，本地模型在它们那里是二等公民；
4. **数据主权空位**——没有一个热度榜项目敢把"零遥测、不设云"写进 README 首屏。

OpenPaw 的 13 条主张（§9.5 A–D 四层）就是对这四个空位的逐一占位。

**A. 为什么注意——三秒内让他停下滑动的鼠标**（占位：空位 1 生产血统 / 空位 2 自进化民主化 / 空位 4 数据主权 / 空位 3 模型中立）

1. **「29.8 万行闭源 Agent 的可运行内核，被拆到了 5 分钟能编译」**
   不是又一个玩具 Agent 框架，而是从 FreeAgent（约 29.8 万行 / 40 crates / 6,067 项测试，2026-08-30 实测）真实拆卸出的生产血统内核——**生产血统 + 玩具体量**的稀缺组合。对比锋芒：热度榜上星数最高的几个项目，或依附单一厂商的闭源运行时（Claude Code），或从零攒起的社区框架——"生产级血统 + 五分钟编译"的交集只有 OpenPaw。一句话钩子：*"A production-bred agent kernel that compiles in five minutes."*（锚：§2.1 / §3.3）

2. **「Agent 自进化是全行业最热的开放问题——这里是唯一把它做成公开 trait 的实验场」**
   自进化是 2026 年 Agent 竞赛的决胜局（Hermes / OpenClaw 都在闭门造车），OpenPaw 把决胜局搬到台面上：出厂自带一颗能跑的幼脑（Reflect-Lite，第一天就看到 Agent 变化），`EvolutionPolicy` 是一个普通 Rust trait，任何人 implements 一个新策略就能与幼脑、再与闭源巨头正面竞技。**你写的不是插件，是挑战者——第一场对手已经内置。**（锚：§6.1 / §4.3 决策四 / §2.2）

3. **「零遥测、不设云、知识文件全在本地——absent by design」**
   在"每个开源项目都在偷偷上报"的年代，敢把"我们没在看什么"写进 README 的项目本身就是稀缺品——热度榜 Top 5 中没有一个敢做同样承诺。对隐私敏感型开发者，这一条比任何功能都吸睛。（锚：§7.12）

4. **「模型无感知：Anthropic / OpenAI / Bedrock / Gemini / Ollama 同等一等公民」**
   热度榜的头部项目几乎都有一条"亲爹路线"——Claude Code 系于 Anthropic，Codex 系于 OpenAI，换一家模型体验立刻降级；本地模型在它们那里是二等公民。OpenPaw 的多提供者接入是内核定义性能力（§4.5 域 A：A5 全量对齐，A6 本地模型反而 ● 优于闭源版）——**换模型不换内核，本地模型不是降级方案**。（锚：§4.5 域 A / §2.2）

**B. 为什么来——首屏 30 秒让他觉得"今天就能跑起来"**（占位：空位 1 的低门槛兑现 + 空位 3 的上手验证）

5. **「30 秒无 key 演示 + 5 分钟跑通首轮对话」**
   `openpaw hello` 不需要 API key 就能看到 Agent 完整跑一轮；`cargo install` 后五分钟进真实对话。**不注册、不填表、不迷信 README 之外任何教程**——上手成本被"三个五"指标锁死并进 CI。对比锋芒：头部编码 Agent（Claude Code / Codex）的路径以订阅账号为前置，OpenPaw 的路径以编译为前置。（锚：§6.4 / §3.3）

6. **「cargo-openpaw 脚手架：三条命令生成一个可发布的插件包」**
   写第一个扩展不需要读源码：`cargo openpaw new` → `cargo openpaw dev` → `cargo openpaw publish`。每个 HookPoint 配可运行最小示例，文档示例永远编译通过（CI 强制）——**第一小时就能写出能跑的东西**。（锚：§6.4）

**C. 为什么留——第一周让他决定"这值得我持续投入"**（占位：空位 2 的接口落地 + 独有激励）

7. **「24 个 HookPoint + 9 个 ○ 接口开放项 + 双赛道官方基线：你的想法有真实落点」**
   不是"欢迎提 PR"的客套，而是结构化的创造力地形：24 个 HookPoint、9 项接口开放功能（B5/B7/D7/E3/E5/E7/F1/F2/F3，§4.5）、六条官方实验路线（进化策略实验 / 记忆系统研究 / 多 Agent 社会 / 端侧部署 / 新入口生态 / 编排实验，§6.3），且**两条赛道都有官方基线内置**——策略赛道对手是 Reflect-Lite 幼脑（§4.3 决策四），编排赛道对手是 RunLoop-Lite 目标存折（§4.3 决策五）。对比锋芒：热度榜的框架型项目（OpenClaw / Hermes）靠生态惯性聚集插件，却没有给"改变 Agent 行为本身"留接口——它们能被扩展，不能被重塑。**每个想法都能对着接口编号说出落点，每条赛道都有内置的第一场对手。**（锚：§6.2 / §6.3 / §4.5）

8. **「毕业机制：你写进 OpenPaw 的代码，可能跑进 2000 万台 AI PC」**
   OpenPaw 是 FreeAgent 的苗圃（同源双轨 + 毕业通道）：社区验证的优秀路线会毕业进入商业版，部署到 GPT-Station 的端侧矩阵。对比锋芒：这是竞品无法复制的独有激励——LangChain 类框架的"毕业"止步于被更多项目采用，Claude Code / Codex 的改进则根本没有社区通道。**开源贡献在这里不只是声誉，是真实的分发杠杆。**（锚：§7.4 / §2.3）

9. **「被认真对待的承诺：issue 24h 响应、API 三档稳定级、永不静默弃养」**
   Maintainer ≥ 2 全职（含 DX Owner）、CI 出口条件挂里程碑、弃养提前 6 个月公告且交接资产清单。对比锋芒：星数暴涨的项目最常见死法恰是"作者兴趣转移"——热度不等于承诺，OpenPaw 把承诺写成制度。**这不是一个"下班后维护"的 side project，是写进 GOVERNANCE.md 的正式承诺。**（锚：§7.11 / §7.8）

**D. 为什么传播——第一个 PR 之后让他忍不住写推文**（占位：把四个空位的差异变成社交货币）

10. **「可炫耀的问题 + 可引用的成绩单」**
   - **问题可炫耀**：自进化策略是能让任何工程师在 dinner table 讲明白的开放命题——"我教 Agent 怎么学习"天然具有社交货币属性；策略锦标赛（§6.3 路线 1，基线 = Reflect-Lite 幼脑）让优秀工作自带排行榜与可引用战绩——**"我的策略赢了官方幼脑"是第一条可发推的战绩**；
   - **贡献可引用**：健康看板（§7.9）记录每位贡献者的 merged PR / 毕业案例，贡献记录永久可查可引——**你的 GitHub 主页上多了一个"给 Agent 进化写规则的人"**；
   - **社区可信**：Apache-2.0 + DCO + 零遥测 + 签名发布（§7.1 / §7.12 / §7.10）构成可对外引用的信任背书——转发这个项目不消耗你的个人信用。

11. **「生产血统对玩具框架的碾压：6,067 项测试不是装饰」**
   热度榜上的社区框架（LangChain / CrewAI / AutoGPT 一系）用星数证明了需求，也用 issue 积压证明了缺工程纪律；OpenPaw 从 FreeAgent 拆卸时同步继承测试与 CI 血统——"三个五"不是营销数字而是 CI 出口条件。对比锋芒：**星数衡量好奇心，测试数衡量可信度；当你的生产业务跑在一个 Agent 内核上，可信度是唯一的硬通货。**（锚：§3.3 / §2.1）

12. **「知识文件 100% 兼容：来时无迁移成本，走时无锁定成本」**
   记忆 / 技能 / 策略全部是 Markdown + YAML frontmatter，与 FreeAgent 双向兼容（黄金用例入 CI）。对比锋芒：迁移到任何闭源 Agent 都意味着把积累的上下文知识交出去，迁移到 OpenPaw 只是换个内核继续用同一批文件——**进来零成本，离开也零成本，留下的唯一理由是好，而不是锁。**（锚：§7.7 / §4.4.2）

13. **「零 GUI 代码，白得一个桌面客户端：OpenWork 即 OpenPaw 的客户端」**
   OpenWork 与 OpenCode 是解耦架构——客户端宿主 + 可替换引擎进程。OpenPaw 实现 OpenCode 的**公开引擎接口**（`openpaw --engine-host`），直接坐进 OpenWork 的引擎位：开发者在 OpenWork 引擎设置里选"OpenPaw"，桌面界面、会话管理、团队协作全部现成——**OpenPaw 保持零 GUI 代码，却白得一个 ~2 万★工作台的客户端入口**（[待验证]：引擎替换接口公开性尚未见上游文档，v0.1.9 / 2026-08 快照，以 Phase 2 验证关卡为准）；同时 `openpaw --sidecar` 以标准 MCP 服务器身份服务任意 MCP 客户端，双通道进场（E6+E8）。对比锋芒：热度榜的每个引擎都在自建客户端、绑定自家工作台，OpenPaw 反向而行——**内核只管变强，壳交给开放的生态**：对 OpenWork 私有 API 永不触碰，关掉 OpenWork 命令行一切照旧，端点可见可断（`sidecar status` / doctor 网络审计）。**协议级拥抱、产品级不绑定、引擎位即客户端。**（锚：§4.5 域 E6/E8 / §7.10.3 防线五 / §6.4.2）

#### 三角卡位：OpenPaw 站在哪

一张图记住 OpenPaw 相对热度榜的位置——三个轴，每个轴上对手只占一端，OpenPaw 独占另一端：

1. **血统轴**：从零攒起的社区框架（OpenClaw / LangChain 系）⇄ 厂商闭源运行时（Claude Code / Codex）——OpenPaw 以**真实拆卸**同时拿到两端的优点：生产的可信 + 开放的体量（"生产血统 + 玩具体量"，主张 1/11）；
2. **命题轴**：全行业都在卷"Agent 能干什么"（工具、上下文、编码），OpenPaw 把火力指向更上游的"Agent 如何自己变强"——自进化的公开 trait 实验场（主张 2/7）。对 Hermes 正面差异化（它的进化引擎闭门），对框架型项目错位竞争（它们没有这个命题）；
3. **主权轴**：模型中立（主张 4）+ 零遥测（主张 3）+ 知识文件无锁定（主张 12）+ 毕业激励（主张 8）——对开发者，这是一份"你的 Agent 只属于你"的完整契约，热度榜没有任何一家能签。

**三角卡位的传播句**：*"Others compete on what agents can do. We open-sourced how they learn."*——对标热度榜的集体叙事：卷能力，我们开放学习本身。

**漏斗的工程护栏**：13 条主张全部挂接可验证章节；竞品对比句式只陈述公开事实与结构性差异，禁止贬损性措辞与"颠覆性""革命性"等不可验证形容词（对齐 §4.4.4 禁语纪律），竞品数字一律标注快照日期；每季度由 DX Owner 对照健康看板数据复核——**主张不能跑在数据前面**。

## 10. 结语

FreeAgent 证明了自进化 Agent 可以工程化；OpenPaw 要证明的是——**这个问题值得全世界一起回答**。

这段回答背后有思想的托付：OpenPaw 承接的是 FreeAgent 的三大产品灵魂与"信任竞赛"世界观（§2.4 思想承接）——**灵魂三传，各有代码物证；世界观一传，拆解三大焦虑**。代码会迭代，接口会演进，但三大灵魂的守护条款写入边界宪法（§4.4），接受三个证伪条件的季度检验（§2.4.3）——**思想在开源侧的存活，不靠情怀，靠制度。**

我们交出的是一个小而美的内核、一颗开箱即转的幼脑、一本记得住托付的目标存折、一组开放的战略接口、六道明示的考题，一条让任何开发者当天就能上路的坡道，一套从第一天就开源、可被社区审计的防线，一份写明"谁在养、养多久、死了怎么办"的承诺，一句"我们没在看什么"的数据自白，以及两个随时进驻任何团队工作台、却永远不反客为主的分身——一个以 MCP 协议应召（Sidecar），一个以引擎位坐进 OpenWork（engine-host）；我们收回的是社区最活跃的创造力、最前沿的实验路线，以及 GPT-Station 上那个属于我们自己的 OSS Agent 座席。

开源筑基，自研增值。FreeAgent 负责抵达终点，OpenPaw 负责探索所有岔路——而所有被证明值得走的岔路，终将成为终点的一部分。

而对开发者，我们用十三条主张说清这件事（§9.5）：**这里有一个五分钟就能编译的生产血统内核、一个谁都能下场的进化开放命题、一个记得住托付事项的目标存折、一份"我们没在看什么"的自白、一条从 PR 通向两千万台设备的路，以及两个现成的团队入口——一条通向任何 MCP 客户端的 `--sidecar`，和一把让 OpenWork 变成自己客户端的 `--engine-host` 钥匙。** 剩下的，交给刷到这个仓库的你。

热度榜会继续刷新，星数会继续跳动；但坐标系里那四个空位——生产血统、进化的民主化、模型中立、数据主权——在有人真正填上它们之前，会一直空着。OpenPaw 不打算在别人的赛道上追星数，它打算把赛道换成自己的：**Others compete on what agents can do. We open-sourced how they learn.**
