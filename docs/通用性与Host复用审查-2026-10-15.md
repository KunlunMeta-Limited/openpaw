# 通用性与 Host 复用审查（2026-10-15）

本轮已完成用户授权的预览、命名、输出格式与产物归属修复，Linux 三端保持运行。新发现的领域特化和跨模块重构在下文列为**待审核，尚未实施**，不将它们混入已修复结果。

## 审查范围与结论

覆盖 AI Office 预览/分类/Markdown/文件读取/产物恢复/目标任务入口，以及 OpenPaw Host 的 runtime、delegation、office、http、审批、事件投影与相关测试；对照 Engine、Core、Tools、Store、LLM、CLI、Goal Ledger 和 MCP 的职责与调用关系。结合静态调用链、契约测试、隔离浏览器与真实 Provider 验收；这不是所有工具、所有浏览器及所有网络环境的全覆盖证明。

**Host 确实存在配置、持久化事实解释和元数据维护的重复，并已出现行为分歧；但“Host 全部重写了 Agent/工具/模型手脚”不符合代码事实。** 它实际复用了 AgentLoop、ToolRegistry、Core 的 ToolHost/Provider/Approval trait、SessionReader/Writer、现有 OpenAI/Anthropic Provider、Axum、Tokio、reqwest。应收敛重复构造和事实源，同时保留必要的 HTTP/SSE 协议适配、审批生命周期及回合可靠性。

本轮生产代码检索未发现针对会话 `111`、其 session ID、某个城市的专用判断或分支。仍发现地图的旅游语义包装，以及目标任务入口的关键词名册映射和固定输出模板，见待审核事项 G01/G02。测试样本中的城市、旅游任务和显式 mock Provider 夹具不等于真实 Provider 的场景特判。

### 对话111地图的实际原因

原HTML引用的 Leaflet 脚本可加载，网页已创建点位和路线，7天卡片都存在；点击“只看D2”后只保留5个D2点位和当天连线。底图请求 `https://{a,b,c}.tile.openstreetmap.org/...png` 超时，页面通用诊断已显示具体资源地址与“超过8秒尚未加载”。因此，本次实际空白底图的直接原因是瓦片网络不可达，不能认定是HTML没有运行，也不能声称改解析器后外部底图已经恢复。

没有修改111产物、替换其中的地图服务或硬编码城市。**待环境处理的步骤**：在实际使用浏览器所在网络确认该瓦片域名可达；若环境要求更换服务，由产物作者选择合适且可用的资源地址；页面点“重新加载原页”后复查。应用不增加地图厂商专用代理或自动替换规则。

历史对话没有结构化交付事实时，最终正文里提到某文件仍存在“交付/过程”的语义歧义；本轮不再用中文排除词弥补，新的 register_artifact 消除了新回合的这个依赖。111中的 `_weather.py` 在最终答复里被明确交付为“可复现查询脚本”，不是代码按天气主题自动上架。

## 待审核：Host重点复用与可靠性问题

### R01 / P1：相同文本子任务直接复用历史结果，缺少失效条件

证据：[openpaw/crates/openpaw-engine-host/src/delegation.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-engine-host/src/delegation.rs:206) 通过 normalized_task_fingerprint 找到 completed 就直接返回；[openpaw/crates/openpaw-engine-host/src/delegation.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-engine-host/src/delegation.rs:542) 指纹只是合并空白并转小写。记录还会持久化并在重启后恢复，不包含文件版本、外部状态、父turn、模型或时间条件，也没有显式refresh。

影响：文件已变化、外部状态已变化或要求重新核验时，同样文字仍可能拿到旧结论，甚至没有真正执行子Agent。

建议：把工作空间身份复用与结果缓存分开；默认重新执行，确需缓存时由显式策略和输入版本决定，支持刷新。优先修复此项，不能靠给每种任务追加时间关键词处理。

### R02 / P1：相似度决定工作空间身份，可能错误合并不同职责

证据：[openpaw/crates/openpaw-engine-host/src/delegation.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-engine-host/src/delegation.rs:645) reusable_delegation_score 使用名称和任务的包含关系、字符二元组、公共前缀阈值。只要任务相似度足够高，即使显式名称不同也可复用旧空间。本轮调试中，`alpha-helper / collect alpha facts` 与 `beta-helper / collect beta facts` 被合并为前者；命名保留测试随后换成真正不相似的职责，以隔离“展示名是否保留”的验证，没有把这个独立问题当成已修复。

影响：不同职责的轨迹、产物归属及名称混在同一空间。建议：稳定agent/workspace标识决定复用，保留显式新建/继续语义；模糊匹配仅用于建议，不自动改变身份。与R01一起设计，避免“复用空间=复用旧结果”。

### R03 / P1：委派状态保存先删旧文件，存在数据丢失窗口

证据：[openpaw/crates/openpaw-engine-host/src/delegation.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-engine-host/src/delegation.rs:789) save_delegations 为“写临时→remove_file旧文件→rename”；[openpaw/crates/openpaw-engine-host/src/delegation.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-engine-host/src/delegation.rs:407) 构造snapshot后在锁外保存，多任务完成可使较旧snapshot后写覆盖较新状态。

影响：删旧后崩溃/rename失败丢记录；并发完成可能回退持久状态。可复用：[openpaw/crates/openpaw-store/src/frontmatter.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-store/src/frontmatter.rs:83) 已有同目录临时文件后替换思路，但它序列化Frontmatter，不能原样用于JSON；应抽取底层原子写原语，补齐跨平台替换、失败清理和有序提交。不是再新建Host专属持久化框架。

### R04 / P1：Gateway与Host对同一会话有两套事实解释

证据：[openpaw/crates/openpaw-engine-host/src/runtime.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-engine-host/src/runtime.rs:1544) restored_session_projection 处理 turn_accept/finish_prepare/finish_commit，只有commit才采纳批次消息；[ai-office/scripts/action-gateway.mjs](/media/cheng/新加卷/workSpace/Kunlun/ai-office/scripts/action-gateway.mjs:317) listSessions 与 [ai-office/scripts/action-gateway.mjs](/media/cheng/新加卷/workSpace/Kunlun/ai-office/scripts/action-gateway.mjs:590) 产物扫描直接读JSONL，后者虽识别turn_accept定位回合，却没有处理finish事务。[openpaw/crates/openpaw-cli/src/session_cmd.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-cli/src/session_cmd.rs:176) 也使用通用SessionReader，未经过Host事务投影。

影响：Host拒绝的未commit崩溃残留，Gateway产物/标题或CLI读取可能当成普通消息事实；多个消费方会持续漂移。本轮register_artifact复用了既有工具事实及OfficeAction，但没有把历史扫描升级为另一套事务实现。

建议：由Host提供统一的已提交会话/产物事实API，或将无HTTP依赖的事务投影移入共享Store服务供所有入口使用；Gateway仅保留浏览器Origin/文件预览边界。不要删除Host事务来追求表面复用，也不要让Gateway再写第三套可靠性协议。

### R07 / P2：CLI会话索引与Host提交未打通

### R08 / P2：目标任务控制面与Goal Ledger没有统一

证据：Gateway维护activeTasks、目标文件、超时、重启恢复、执行模式；Host另有回合入场队列与终态。[openpaw/crates/openpaw-goal-ledger/src/models.rs](/media/cheng/新加卷/workSpace/Kunlun/openpaw/crates/openpaw-goal-ledger/src/models.rs:82) GoalStatus为created/active/paused/completed/failed/cancelled/archived；Gateway运行用queued/in_progress等状态，同样接触goals目录，但不是统一模型。

建议：先明确“目标生命周期”与“单回合调度”边界，复用Goal Ledger模型/存储/恢复契约，在一个执行服务里维护目标状态，Gateway仅提交/查询。**Goal Ledger目前是被动ledger/profile，没有可直接替换Gateway的完整自主runner**，不能只把调用换名字就声称复用完成。
